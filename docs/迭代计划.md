# macOS 迭代计划（2026-10-11）

> 当前状态以 `HANDOFF.md` 为准。本计划合并审计009、006–008、ROADMAP 与任务卡，作为新的执行顺序；不代表其中建议已实现或设计已批准。一次只实施一个可独立验证的任务。

## 1. 排序结论与证据边界

当前核心功能主体已实现，产品MVP尚未完成。按ADR-084，目标是核心功能齐全、日常稳定、交互完善、视觉良好的首个macOS正式分发就绪版本；验收以 [MVP产品标准](MVP产品验收标准.md) 为准。源码基线 `c294b67`；设备 B 为 macOS 27 / arm64，已安装 `4d9339c` thin arm64 / ad-hoc 包，不能用旧包验收代表最新源码。历史 A/B 验收、MEM-1 闭环与本轮审计均保留，不相互覆盖。

优先级采用影响和依赖排序：

- **P0：测试启用前必须解决**。验收工具可能清除真实文档、聊天输入、剪贴板或覆盖文件；这是工具风险，不是已发生的数据损失。
- **P1：发布前必须收敛**。已复现的状态/配置错误、失败反馈与资源错误，以及最终包身份、附件校验、第三方核验。可访问性和兼容性先取得真实证据，有核心输入障碍则修复后发布。
- **P1体验：MVP必须完善**。设置布局、候选信息层次、最小词库纠错、基础拼音质量、字根提示与反馈闭环纳入首版；性能先测量，影响指标和日常体验的瓶颈须收敛。超出这些边界的增强进入MVP后。
- **P3：有触发条件再推进**。额外平台、引擎替换、全量重构、图标等；不挤占首版可靠性工作。

审计中的“缺少验证”不直接等于产品 bug。caretRect 的索引疑点、真实 VoiceOver、多屏和完整宿主功耗需要复验；FFI 压力通过不能代替 IMK 宿主验证。暂不执行现有真实用户环境验收脚本，直至 I0 通过。

以下工作量按一名熟悉项目的开发者顺序执行估计，包含针对性验证与文档；不含签名凭据、第三方参与及额外设备等待，不承诺日历日期。S≈0.5–1 工作日，M≈1–2，L≈2–4；设计审核或失败调查后重估。

## 4. 发布门禁与回归策略

1. **安全门禁**：IT-01/02 未通过前禁止在真实用户环境运行旧实机验收脚本；自动化在隔离环境验证已有数据保护。
2. **行为门禁**：IT-04…09 的已复现错误关闭。每个任务先回归失败用例，再验证相关路径；不为文档变化增加镜像测试。
3. **体验门禁**：IT-10/11 的实际辅助操作和阅读不能阻断核心输入。IT-16…22需满足产品交互/视觉标准；IT-12/23中的指标违规、明显卡顿或持续异常负载须修复，普通微优化可后置。
4. **候选门禁**：最终签名包的来源、摘要、版本、公证、目标覆盖可追溯。任何代码变更后重新生成候选并重跑受影响验收；不沿用旧安装包的通过项冒充最终结果。
5. **独立门禁**：P1-M5 第三方复现与零外联未完成时仍标待验收，不能仅凭同机离线重建或符号扫描关闭。

每张卡提交前 `make verify`；涉及 macOS 时 strict 宿主构建及隔离预览，涉及 live 行为才跑安全后的实机用例。fuzz/属性测试用于被改动的解析与状态边界，避免无差别扩测试。每迭代结束更新任务状态、ROADMAP 和 HANDOFF，保留原始证据及已知限制。
