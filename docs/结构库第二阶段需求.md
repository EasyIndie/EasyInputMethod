## 3. 每项需求的准入规格

### N1 字根字形身份库

- 字段（每行）：`PUA 码位或字形标识` / `可读字根` / `键位` / `证据来源`；
- 规模：覆盖五笔86 全部键面字根与常用变形（**约 200–300 个**），能解释 B0 的 72 个阻塞字形；
- 许可：文档级明确许可、GPL-3 兼容、可追溯 URL + SHA-256；**不接受"来源不详"**；
- 交付形态：`data/learning/*.tsv`（CC-BY-SA-4.0，项目自产编排）+ `data/sources.toml` 登记。

### N2 笔画/笔顺

- 字段：`字` / `笔画序列`（按笔顺）/ `来源`；
- 规模：先覆盖**字根集**（约 300 个）→ 满足成字字根解释；常用 3,000 字为扩展目标；
- 许可：同上；若引入第三方笔顺数据必须逐条登记，**不得**用字体渲染结果冒充笔顺事实；
- 与 `strokes` 的关系：`strokes`（取码笔顺）保留，新增字段区分"笔顺（书写）"与"取码笔顺"。

### N3 结构标注（五笔口径）

- 字段：`字` / `结构`（左右/上下/杂合）/ `证据`；
- 来源优先级：**五笔权威材料 > 识别码反推 > IDS**；三者不一致时归档为"口径差异"，不硬改；
- 规模：与 N1 同批的常用字即可，不做全量。

### N4 完整拆字（可选）

- 只解决 8 条 D2 漏拆；优先级最低，除非同一来源顺带提供 N1/N2。

## 4. 验收门槛（不达成不开工下一阶段）

沿用 ADR-309，并给出可测量口径：

| 门槛 | 口径 | 现状 |
|---|---|---|
| 覆盖 | 高频 **3,000 字**中 **≥98%** 给出"字根序列 + 键位 + 识别码依据" | 1,000 字中 73.5% `full` |
| 许可 | 每份新数据在 `docs/数据来源与许可.md` 登记，GPL-3 兼容，含 SHA-256 | D19 已登记；N1/N2 未定 |
| 体积 | 运行资源净增量 ≤ **512 KiB / 3,000 字**（按 558 B/字 外推约 1.6 MiB，**超预算**，需要压缩或裁剪字段） | 未测 |
| 延迟 | 不参与输入热路径；离线查询 p95 ≤ **5 ms**（CLI 参考实现） | 未测 |
| 可复现 | `modules/hanzi-structure` 内独立构建 + `tests/validate_b0.py` 独立重算 | ✅ 已具备 |

> 体积按现状外推会**超标 3 倍**：这也是第二阶段必须做的一件事——确定"运行包真正需要的字段子集"
> （`ids`、`positionMismatch`、`notes` 都不该进包），而不是把 558 B/字 直接乘 3,000。

| 里程碑 | 内容 | 完成标志 |
|---|---|---|

| **M2-4** | 扩到 3,000 字 + 体积/延迟实测 + 字段子集裁剪 | 满足 §4 全部门槛 |

每个里程碑单独出报告，`make verify` + `make macos-offline-tests` 必须全绿。

## 6. 边界（不可逾越）

- 不改变输入行为、不进输入热路径、不影响候选排序（ADR-189/309）；
- 不引入云、不做字形渲染/字体分发（字体另议）；
- 不把"未知"说成"已知"：`partial` 必须带可读的原因，`？（键 x）` 是合法表达；
- 任一新增数据来源若"来源不详/无许可"，**一律不采用**，哪怕技术上更好（ADR-310 的教训）。
