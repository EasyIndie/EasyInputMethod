# 更新源与镜像（大陆网络容错）

> 默认源是 GitHub Releases；**大陆网络可能不可达**。可在设置 → 更新里换成自建/区域镜像，或配置多个镜像自动回退。
> 换源不需要任何账号或凭据；**信任锚仍是签名包内固定的 Ed25519 公钥**。

## 1. 配置项

| 键 | 类型 | 说明 |
|---|---|---|
| `update.feed_url` | https URL 或空 | 主更新源；空 = 官方 GitHub 默认源 |
| `update.feed_mirrors` | 逗号/换行分隔的 https 列表（≤8） | 主源不可达时按顺序回退；去重保序 |

设置界面「更新」分区会自动出现这两个输入框（Schema 驱动）。示例：

```toml
update.feed_url = ""
update.feed_mirrors = "https://cn.example.com/lampyris/appcast.xml,https://sg.example.com/lampyris/appcast.xml"
```

## 2. 回退语义（更新程序 `--check`）

1. 依次尝试：主源 → 镜像 1 → 镜像 2 …（每个 15s 请求/30s 资源超时）；
2. 任一源**成功返回**（有更新或已是最新）即停止，不再继续；
3. 全部失败 → 非零退出并提示“所有更新来源均不可用”，输入法仍可离线使用；
4. 只有 `--check` 会联网；输入法宿主与核心始终零网络。

> 因为“成功返回已最新”就停止，镜像应尽快与 GitHub 同步；落后太多的镜像可能让用户暂时看不到新版本。

## 3. 镜像要求（重要）

- **内容必须与 GitHub 完全相同的 ZIP 字节**（或提供指向同字节的 URL）；任何重新打包都会导致验签失败。
- appcast 里 `sparkle:edSignature` 必须是项目私钥对**该 ZIP** 的签名；镜像不得改签名、版本号或长度。
- 只允许 https；URL 不得含账号密码或 fragment。
- appcast 的 ZIP 地址可以是镜像自己的 https 直链（同主机），也可以是 GitHub Releases 地址（会 302 到
  `release-assets.githubusercontent.com`，已在允许列表）；其他跨主机跳转会被拒绝。
- 镜像服务端应支持 Range/缓存友好；不要改写 XML 内容。

## 4. 搭建一个区域镜像（示例）

任意静态站点即可（对象存储 + CDN、VPS、GitHub Pages 的镜像站）：

```
https://cn.example.com/lampyris/appcast.xml
https://cn.example.com/lampyris/Lampyris-0.1.0-universal.zip
```

- `appcast.xml` 复制 Releases 里的同名文件（或把 `enclosure url` 换成你的 ZIP 直链，其余字段保持不变）；
- ZIP 原样复制（可用 `shasum -a 256` 与 Release 的 `.sha256` 对照）；
- 每次发版后同步更新这两份文件。

## 5. 验证

```sh
# 用仓库公钥验签（详见 README「更新与可复验」）
openssl pkeyutl -verify -rawin -pubin -inkey pub.pem -in Lampyris-0.1.0-universal.zip -sigfile sig.bin

# 或直接用源码构建的更新程序
LampyrisUpdateCheck --verify-payload Lampyris-0.1.0-universal.zip "<signature>"
```

命令行演练（安装器侧同样支持多源回退）：

```sh
python3 packaging/macos/upgrade.py \
  --feed-urls "https://cn.example.com/lampyris/appcast.xml,https://github.com/.../appcast.xml" \
  --verifier <LampyrisUpdateCheck 可执行文件>
```

## 6. 边界

- 不支持带认证的私有源（拒绝 URL 凭据、不发送认证头）；
- 不做自动测速/择优，只按配置顺序回退；
- 多公钥/密钥 ID 轮换、渠道与架构筛选见 ADR-267，尚未实现。
