# LWS-86 CHANGELOG

## 1.0（正式，2026-11-20，ADR-381 / ADR-388；随萤火虫 1.4.0 发布）

转正与三处**勘误性修正**（草案期发现，均不放宽 R1–R10）：

1. **R9e 成字字根特例从 1 条扩到 4 条**。独立实现（S-3）用「报户口 + 首笔 + 次笔 + 末笔」重算时，
   `方`（官方 `yygn`，按笔顺 丶一乙丿 应得 `yygt`）、`车`（`lgnh` vs `lgng`）、`止`（`hhhg` vs `hhgg`）
   推不出来。数据因此改标 `radical-char-exception`（原先误标 `radical-char`），规范 R9e 列明这 4 例。
   **没有改任何码，也没有为通过判定去改笔顺。**
2. **新增 R2-note：多键位字根以逐字 `keys` 列为准**。`⺋ 凵 丆 𠂇 丷 儿 𠂉` 这 7 个字形各挂两个键，
   静态字根表不足以判定某字用哪个键（1.0 数据里 755 字受影响）；实现拿不到逐字键位时必须标 `partial`。
   这是独立实现暴露的真实规范缺口，不是数据错误。
3. **数据包可复现**：`generatedAt` 取提交时间（`SOURCE_DATE_EPOCH` 可覆盖），打包时间戳固定、条目按名排序，
   同一提交两次生成得到同一个 SHA-256。

**独立实现验证**（`tools/lws86-reference-impl.py`，只读规范、不引用判定器）：3,746 / 3,755 字逐字一致、0 失败；
剩 9 条 = 4 个已列明特例 + 5 个缺笔顺数据的成字字根（`夕 戈 巳 臼 皿`，D18 未覆盖，标 `partial`，不猜）。

**当前状态**：范围 GB2312 一级 3,755 字，`full` **3,755（100.0%）**、`partial` 0；一级之外 27 字仍 `partial`
（`docs/tasks/T-ROOT86.md` §2，缺可靠 86 字形参考，不排期）。自检 L4：3,755 字 0 失败。

## 1.0（草案，2026-11-19，ADR-381）

- 首版规范：数据模型（`roots` / `chars` / `shortcodes`）、规则 **R1–R10**、识别码网格、一致性等级 **L1–L4**。
- 范围：五笔86；GB2312-1980 一级 3,755 字（另含学习字表并集 5,021 字），`full` 3,727（99.3%，报告 307–313 判定后），`partial` 0。
- 数据来源：D2（MIT）+ 项目自编（D18）与标准 v1 校验；不新增来源、不含私有区字形。
- 工具：`tools/wubi86-std-bundle.py`（生成数据包 + SHA256SUMS）、`tools/wubi86-std-check.py`（L1–L4 判定）。
- 已知限制：`partial` 0 条待 86 canonical 根序（`docs/tasks/T-ROOT86.md`；试点 30 抽 20，报告 306）；`radical-char-exception` 仅 `母 XGUI` 一条；
  4 码字"3 字根+识别码"与"4 字根"的字形歧义按规则与码位判定，无法区分时保持 `partial`。
- 待办：`wangma-diff.md`（与王码官方口径的逐字差异清单，抽样 50–100 字）、扩到 GB2312 二级（未立项）。

## 变更规则

- `1.x` 只允许向后兼容增补（加字、加例字、勘误）；改规则或改已有字的根序必须升 `2.0`。
- 每次发布更新本文件、重新生成数据包、附 `SHA256SUMS`；勘误不改历史数据文件。
