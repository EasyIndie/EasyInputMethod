# 开发与迭代工作流（Development Workflow）

> 目标：**单人也快、质量不降、成熟后平滑支持多人共建**。
> 本文是工作流与 CI 分层的权威说明；配套 `AGENTS.md`（铁律/验证）、`CONTRIBUTING.md`（提交规范）、`.github/workflows/`、`Makefile`。相关决策见 ADR-072。

---

## 1. 原则

1. **一个门禁**：`make verify` 是"可提交"的唯一标准，本地与 CI 等价。
2. **分层**：PR 跑"快"，`main`/夜间跑"全"；重活不挡内环。
3. **单人降级、团队升级**：同一套 workflow，靠分支保护 / 标签 / `CODEOWNERS` 开关切换，不重搭。
4. **铁律自动化**：能机检的绝不靠自觉（网络 / 配置 / unsafe / 许可 / DCO）。
5. **小步、可验证**：一次一个改动；删代码优于加代码（`AGENTS.md` §11）。

---

## 2. 分层 CI

| 层 | 触发 | 内容 | 目标时长 | 现状 |
|---|---|---|---|---|
| **check（fast）** | 所有 PR / push | fmt + clippy + test + deny + `verify-no-network` | ≤2 min | ✅ 已实现 |
| **heavy（条件）** | PR 命中 `crates/` `platforms/` `fuzz/` `tools/` `data/` `packaging/` 等 | macos 全量构建 + 预览冒烟；fuzz 短跑 | ~4 min | ✅ 已实现 |
| **post-merge** | `main` push | 重型检查 + 验收出包（`macos-acceptance.yml`） | ~5 min | ✅ 已实现 |
| **nightly** | 定时 | 长 fuzz、`cargo deny advisories`、基准趋势 | — | ⏳ 待办（MVP 后） |
| **on-demand** | `workflow_dispatch` | 出包、Pages、release dry-run | — | ✅ 已实现 |

**关键细节**：分支保护的必需检查是 `check` / `macos` / `fuzz`。若"路径不相关"就**跳过整个 job**，会让必需检查停在 `Expected` 而卡住合并。因此重型 job **始终运行并上报成功**，只把**具体 step** 条件化：

- `scripts/ci-detect-code-changes.sh` 判断本次 PR 是否"代码相关"（docs-only → `false`）；
- `macos` / `fuzz` 的每个重型 step 带 `if: steps.changes.outputs.code == 'true'`；
- `push` 到 `main` 一律视为代码相关（重型全跑）。

---

## 3. 单人提速

| 手段 | 说明 |
|---|---|
| `make fast` | 内环：`fmt-check + clippy + test`（不含 deny / 隐私断言），小改动秒级反馈 |
| `make verify` | 外环：提交前完整门禁 |
| `make hooks` | 安装 `pre-push` → 自动跑 `make verify`，失败前移（`git push --no-verify` 可临时跳过） |
| `make macos-preview` | macOS 独立窗口，秒级 UI 反馈（不注册系统输入法） |
| auto-merge | PR 由作者决定 `gh pr merge --auto`：CI 绿自动合，免"盯 CI" |
| trunk-based | 短命分支（<1 天）；docs / 低风险可管理员直推 `main`（本地 `make verify` 先过），风险面走 PR |

---

## 4. 质量保障

**已实现**

- 分支保护必需检查 `check` / `macos` / `fuzz`；`main` 禁强推 / 禁删除。
- 解析器 fuzz（3 目标）与每周 `cargo deny advisories`（`security.yml`）。
- 可复现构建 / SBOM / SHA（`macos-acceptance.yml` + `packaging/macos/`）。
- `verify-no-network.sh`（铁律 1）；PR 模板含铁律自检清单。
- DCO 校验（`dco.yml`）：**可见但不阻断**，团队化后设为必需。

**待办（MVP 完成后）**

- 覆盖率上报（`cargo llvm-cov`，软阈值，不作硬卡）。
- 基准回归：把稳定的 `run-perf.sh` 作基线，夜间对比阈值并告警。
- fuzz 语料入库 + 长跑；崩溃自动建 issue。
- `nightly.yml`：长 fuzz + advisories + 基准趋势。
- 依赖机器人（Dependabot/Renovate 分组；Actions 仍**必须钉 SHA**，见 `CONTRIBUTING.md` §9）。

## 5. 铁律自动化（对应 `AGENTS.md` §2）

| 铁律 | 自动化 |
|---|---|
| 1 不联网 | `make verify-no-network`（源码依赖 + 产物符号）；CI 必跑 |
| 2 内存安全 | 核心 crate `#![forbid(unsafe_code)]`（编译期保证） |
| 3 配置唯一 | 约定禁止 `UserDefaults`/注册表/第二文件；可加脚本扫描（待办） |
| 4 数据登记 | 新增数据须登记 `数据来源与许可.md` + `data/sources.toml`（人工 + 评审） |
| 5/7 先写 ADR | PR 模板勾选 + 人工评审；可加软检查（待办） |

## 6. 面向多人共建（开关表）

同一套流程，随团队规模"开开关"，**不重写 CI**：

| 能力 | 单人（现在） | 团队（成熟后） |
|---|---|---|
| 合并 | PR + 必需检查；低风险直推 | 必需 review + `CODEOWNERS` + dismiss stale |
| 队列 | 无 | **merge queue**（多 PR 竞争时） |
| CI | `check` 必跑 / 重型条件 | 重型全跑 + 分平台矩阵（P3+） |
| fuzz/bench | 夜间 | 夜间 + 门禁阈值 |
| 依赖 | 手动 / Dependabot 分组 | Renovate + 自动合低风险 |
| DCO | 可见不阻断 | 设为必需检查 |
| 发布 | `git tag` 手动 | release train + 自动 changelog |
| 治理 | — | 标签 / 里程碑 / `good first issue` |

**团队化首批动作**（有外部贡献者时）：加 `.github/CODEOWNERS` → 分支保护加"必需 review" → 开 merge queue → 把 `dco` 设为必需检查。

---

## 7. AI 协作者

- Agent 任务走 `docs/tasks/*.md` 任务卡，用 `scripts/dispatch-task.sh` 派发。
- Agent 产出**一律走同一 PR 门禁**，禁止"顺手重构"。
- **隐私 / 安全相关 diff 必须人工复核**：网络、配置写入、FFI `unsafe`、数据许可。
