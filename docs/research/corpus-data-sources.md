# 自建 corpus 的数据来源调研（ADR-309 前置，只调研不改仓库数据）

> 2026-11-06。**本文不引入任何数据**：候选文件只下载到临时目录做可行性验证，`data/` 未改动。
> 结论：**不需要 Make Me a Hanzi 的 Arphic 图形数据**；用「MIT IDS + Unicode Unihan + 自编字根笔画」即可满足 ADR-309 的验收线。

## 0. 先把需求拆到最小

B0 的缺口（报告 240/241）只有三件事，对应三类数据：

| 需求 | 只服务什么 | 规模 | 是否必须 |
|---|---|---|---|
| **结构**（左右/上下/杂合） | 识别码判定（末笔×结构） | 高频 3,000 字 | **必须** |
| **字根序列 + 键位** | 拆解讲解 | 同 3,000 字 | **必须** |
| **字根笔画序列**（首/次/末笔） | 成字字根的取码解释 | **约 130 个字根** | **必须** |
| 字形图形（SVG/位图） | 字形图示、笔画动画 | 全量 | 非必须（可运行时渲染） |
| 笔顺动画数据 | 练习演示 | 全量 | 非必须（L4 再说） |

关键判断：**我们没有"全量笔顺"需求**——成字字根解释只需要约 130 个字根自身的笔画序列，
这个量级可以像 D14/D16 那样**自编 + 核验**，不需要引入 Arphic 衍生的图形数据。

## 2. 可行性实测（临时下载，未入库）

用 `yi-bai/ids` 的 `ids_lv1.txt`（MIT）对 B0 的 1,000 条做了两次对照：

| 检验 | 结果 |
|---|---|
| IDS 能给出结构序列的字 | **992 / 1000** |
| B0 的 `partial`（238 条）里 IDS 能给结构的 | **236 / 238** |
| 「有识别码 且 有 IDS 结构」的条目 | 512 |
| 其中 IDS 结构与该识别码要求的结构**一致** | **446（87.1%）** |

解读：

1. **IDS 能覆盖我们最缺的那 238 条**——这就是 corpus 的可行路径；
2. 87.1% 一致说明两件事：① 识别码推导大体正确；② **约 13% 不一致**必须先定规则再落地
   （可能来自"五笔的结构判定"与"IDS 根算子"在包围/嵌套字上的口径差异，而不是任一方"错"）。
   规则由五笔为准、IDS 作 oracle，并对不一致样本逐条记录（跟 D1 的 oracle 对照同一套做法）。

## 3. 推荐方案（最小、可验证、可迁移）

```text
结构/分量  ← yi-bai/ids (MIT)  +  Unihan kIDS/kRSUnicode（Unicode License）交叉校验
字根身份   ← 已有 D14 可读字根表（自编）
字根键位   ← 已有 D14/D17（自编）
字根笔画   ← 新增自编：约 130 条（首/次/末笔），用 Unihan kTotalStrokes 校验笔数
字形图形   ← 暂不需要；若 L3/L4 要图示，运行时用 OFL 字体渲染，不烘焙图片
```

**明确不采用**：makemeahanzi 的 `graphics.txt` / `hanzi-writer-data`（Arphic PL 衍生作品）、
KanjiVG（CC-BY-SA 3.0 + 简体覆盖差）、任何字典网站抓取。

## 3.1 13% 不一致的结论（报告 242）

66 条不一致**不是数据错误**，而是两套分类口径差异：五笔把独体字（下/正/天/自/开）与部分镶嵌判为"杂合"，
IDS 按字形上下/左右切；另有五笔拆法与 IDS 分解根不同的情况（我/跟/像/死）与包围判定差异。
66 条**全部**满足"组件数 + 1 = 码长"，说明识别码推导自洽。

处置：**五笔识别码字母为结构权威，IDS 只作交叉校验**（87.1% 一致即合格），不一致样本按类别归档，
不强行统一、也不用来改数据。partial 的真病因另有三类（PUA 占位 54 / 缺笔画 52 / D2 漏拆 133），
见报告 242 §3。

## 4. 工作量与验收对应（ADR-309）

| 工作 | 量级 | 对应验收项 |
|---|---|---|
| 解析 IDS + 结构映射规则（`⿰/⿲→左右`、`⿱/⿳→上下`、包围/嵌套→杂合） | 1 天 | 结构覆盖 ≥98% |
| 与 Unihan/现有识别码三方对照，记录 13% 不一致样本并定裁 | 1 天 | 抽样核验 100% |
| 自编 130 字根笔画序列 + `kTotalStrokes` 校验 | 1–2 天 | 成字字根可解释 |
| 接入 `build_b0.py`（`--ids` 输入）并扩到 3,000 字 | 1 天 | 高频 3,000 字 ≥98% |
| 体积/延迟实测（运行包净增量） | 半天 | ADR-189 口径 |

合计约 **1 周**（不含审阅），与 ADR-309 的"周级"估计一致。
