# 待办与积压（下一版迭代的范围来源）

> 2026-11-06 整理。1.1.0 已发布上线；`dev` 里已经躺着**二级简码 598 条**（报告 238，Cargo 1.2.0 / build 39），

## 0. 先定版本语义（决定哪些能装进 1.2.0）

| 改动类型 | 版本 | 原因 |
|---|---|---|
| 改候选顺序 / 键位手感 / 简码 | 小版本（1.2.0、1.3.0…） | 用户要能用版本号区分手感变化 |
| 只加只读 UI（提示、练习窗） | 小版本 | 可关闭、不影响排序 |
| 纯缺陷/安全/安装 | 补丁（1.2.x） | 可回滚到"只修 bug"的状态 |
| 新平台 | 独立项目/里程碑 | 不跟 macOS 质量同批，否则回归无法归因 |

## 2. 建议的 1.2.0 范围（三选一）

### 套餐 A「工程收口 + 教学地基」（推荐）
- **内容**：B3（B0 → 运行资源 + 字段子集）+ B1（L3 只读提示）+ D1/D2/D5/D6 + C1（调研）+ E1
- **理由**：① 二级简码已改手感，1.2.0 本来就要换包验收；② 教学是"只读 UI"，不改排序，风险可控；
  ③ 体积是唯一硬门槛，先做出来才知道能不能扩到 3,000 字；④ D1/D2/D5/D6 都是今天踩出来的坑，成本小、收益确定。
- **风险**：首次把教学数据装进包 → 必须走 ADR（运行资源装载/FFI 边界）+ 体积/延迟双实测。
- **工作量**：约 2–3 周（含验收）。

### 套餐 B「质量与门禁」最小版
- **内容**：D1/D2/D5/D6 + A4 测量 + D3/D4 部分，不碰教学数据。
- **优点**：风险最低，1 周内可出候选。
- **缺点**：用户可感知的变化只有二级简码，其余是工程改善。

### 套餐 C「平台扩张」
- **内容**：F1 Windows TSF spike。
- **优点**：长期价值最大。
- **缺点**：1–2 周 timebox 大概率停在"结论"，且会分散 macOS 维护；**不建议与 1.2.0 同批**。

> 推荐 **A**；如果希望更快出包，先出 **B** 当 1.2.0，把 A 的教学部分放到 1.3.0。

## 3. 每项的"算完成"口径

| 项 | 完成标志 |
|---|---|
| B3 | 运行资源 ≤512 KiB/3,000 字；装机后 `make verify` + 离线回归 + 体积/内存/查询延迟三张实测表 |
| B1 | 提示可关；稳态 p95 ≤16 ms 不变；`test-*` 覆盖"full/partial 降级表述"不回归 |
| D1 | 无签名或不符白名单的 tag **直接失败**（不是警告） |
| D2 | CI 里 B0 独立重算**不再 skip**（有数据即可跑） |
| D5 | 内存硬顶改用 footprint 口径，误判率 0 |
| D6 | 站点版本行由发布流水线生成，手工 dispatch 即可上线正确版本 |
| C1 | 候选清单 + 许可结论 + 否决理由（只出报告，不动仓库数据） |

## 4. 需要你现在决定的三件事

1. **1.2.0 走 A 还是 B**（A 含教学数据入包，需要多一次 ADR 与体积实测）；
2. **D1 签名 tag**：要不要现在就启用（需要你决定签名方式：`git tag -s` 的 GPG/SSH 密钥）；
3. **平台扩展**（F1 Windows spike）是否本季度启动——它和 macOS 的维护精力是互斥的。
