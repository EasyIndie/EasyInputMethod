## 2. 行为变更（用户可感知）

### 2.1 用完练习窗口，内存会还回来（ADR-387，报告 330）

1.3.3 上，练习窗口是"建一次就一直在"的单例：关窗只是把它藏起来，控件树、图层、窗口后备存储
都留在输入法进程里；而且**默认隐藏的「键位图」面板在开窗时就已经建好并排过版**。

| 指标（进程内实测） | 1.3.3 | 1.3.4 |
|---|---|---|
| 首次开窗（不点键位图） | +16.9 MiB（真机，报告 329） | +15.7 MiB（**键位图那 19.1 MiB 不再预支**，报告 330） |
| 关窗后释放 | 0（只有 orderOut） | **窗口 + 内容视图 + 键位图面板一并拆掉**（真机回收 ~8 MiB） |
| 反复开/关 | 不适用（一直复用同一窗口） | 真机 **开 61 / 关 59 三轮一致**；离线契约 +0.3～0.4 MiB/轮 |

「是否显示键位图」和口诀开关是显示偏好，关窗后仍然记得，下次开窗按需重建。

**没有变的东西**：练习进度、题库、出题与判分、题型解锁、进度文件格式一行没动；
44 MiB footprint 硬顶与 `heap live ≤ 24 MiB` 都没调（ADR-338/379）。

### 2.2 说明：开过练习之后，footprint 不会回到冷启动水平

这不是泄漏，也不用调阈值：AppKit 的字形/文本布局缓存与 AttributeGraph 是**进程级常驻**，
关窗后那些页只是交给分配器标记可复用（MADV_FREE），`phys_footprint` 不会立刻下降。
实测首次开窗约 +17 MiB 里，键位图 7.0、窗口与首帧约 3、其余是上述缓存（报告 330 的区域表）。
所以 44 MiB 门禁仍然只适用冷启动窗口（ADR-385），"关窗后回落"这条旧验收口径已作废（ADR-387）。

## 4. 发布流程

1. `dev` → PR → CI 全绿 → merge commit。
2. main 上 `macOS Acceptance Package` 产出候选 → 校验 ZIP SHA / 包内执行 SHA / `spctl`。
3. 用户移除再加回「萤火虫」→ `make macos-fast-reinstall APP=… ARGS="--stop-host --keep-data"`。
4. 真机验收（练习窗口开/关/重开、整套 acceptance）。
5. 打签名 tag → Release → 站点上线 → 回读 `v1.3.4 · 构建 47`。
