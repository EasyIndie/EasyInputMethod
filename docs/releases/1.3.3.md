## 2. 行为变更（用户可感知）

### 2.1 修掉「候选窗留在桌面上不走」（报告 327）

症状：打完字后偶尔会有候选窗以最高层浮在桌面上，点它、切输入源、切应用都不消失，只能重启输入法。

原因：候选面板必须 `hidesOnDeactivate = false` + `.popUpMenu` + `.canJoinAllSpaces`（输入法进程长期不是前台应用），
于是**任何一条"该收窗但没人叫它收"的路径都会留下一个用户关不掉的窗口**。真机复现路径是「组合态里切走输入源」——
没有键盘事件、`deactivateServer` 也没被调用。

现在候选窗每 0.2 s 自问一句：「还在组合吗？输入源还是我吗？」答案是否就收窗、清内容，并顺手清掉悬空的预编辑。
真机实测：切走输入源后 **0.6 s 内**窗口消失（上一版同路径会一直挂着）。

### 2.2 长时间使用后内存更省（ADR-386，报告 328）

练习题库以前把每个字的全码、字根、识别码、三条简码各存一份，七个题型各建一遍，还把 5 万多行码表整表摊开排序。
现在题库只存「题型 + 字」，讲解用到才解析；词组题库逐行扫描只留最好的 800 行。

| 指标 | 1.3.2 | 1.3.3 |
|---|---|---|
| 建完全部练习题库的常驻增量 | 5.86 MiB | **1.95 MiB** |
| 建题库时解析的学习区条目 | 5,021（全部） | **0** |
| 宿主用 1.5 h 后的 footprint | 47.0 MiB（报告 326） | （装机后填） |

出题权重、判分、进度文件、题型解锁全部不变。

### 2.2.1 学习表补 `坶`

「母 在合体字里拆 毌+一+丷」这条规则覆盖到 `坶 fxgu`，学习区不再显示「拆解待核验」。
学习表 `full` 4,993 → **4,994 / 5,021**（一级仍是 3,755/3,755 = 100.0%）。
