## 2. 相对 0.1.14 的改动（面向用户）

这一版交付的是一整批**从未随版本发布过**的更新链路改动（此前只存在于候选包与隔离演练）：

- **装包即带更新程序**：DMG 与 ZIP 现在都内含 `LampyrisUpdateCheck.app`，安装器与 `scripts/install.sh` 会把它装到 `~/Applications`（ADR-294/295）。
- **更新程序版本同步**：升级负载自带更新程序时，会替换 `~/Applications` 里的本体（运行中不退出，下次生效；失败不影响输入法）。
- **更新窗口可卸载**：新增「卸载萤火虫…」，支持「保留配置与词库」与「彻底清理」两种模式（ADR-296）。
- **彻底清理真的清干净**：修复更新程序把 `updates/` 当数据根导致的「假清理」——配置、个人词库、更新备份现在一并删除（报告213 §5-P1/§7；该缺陷未进入任何发布版）。
- **菜单「检查更新…」不再被旧副本抢占**：优先打开安装目录内的更新程序，LaunchServices 只作兜底（报告213 §5-P2）。
- **安装脚本不再谎称已注册**：系统没有接受自动注册时如实提示需要在系统设置里手动添加。
- 网站版本行改为带构建号（`v0.1.15 · 构建 24`）。

## 4. 发布步骤

1. 合入本材料 + 站点更新（`site/index.html` → `v0.1.15 · 构建 24`）到 main，等 `macOS Acceptance Package` 成功。
2. `git tag -a v0.1.15 -m "Lampyris 0.1.15"` → push tag → `Release` 工作流。
3. 核对资产：ZIP/DMG/源码/更新程序 + `.sha256` + `appcast.xml`（`sparkle:version` 应为 24）。
4. DMG 签名/staple/`spctl` 复核；`releases/latest/download/appcast.xml` 指向本版。
5. dispatch `Pages`，回读首页显示 `v0.1.15 · 构建 24`。
6. 装 Release 资产到 air、在 pro 上跑 0.1.14 → 0.1.15 升级；补写 §1 与 §3 的实测结论。
