# 萤火虫 1.4.2 发布稿

> 状态：**待发布**。范围：DMG 布局收敛（ADR-391）。产品输入行为、码表、配置、隐私口径**零改动**；
> 安装语义（落点、备份、回滚、输入源注册）也不变。
> 上一次发布：[1.4.1](1.4.1.md)（2026-11-23，build 49）。

## 1. 为什么发这一版

1.4.1 修好了四处安装问题并已真机 PASS（[1.4.1 §4](1.4.1.md)），但 DMG 里还留着一个交互陷阱：
顶层直接摆着 `Lampyris.app`。它是 `LSBackgroundOnly` + `LSUIElement` 的背景程序，**双击本来就没有窗口**；
旁边紧挨着「安装萤火虫」，于是用户的第一反应是「Lampyris 打不开」。（1.4.0 的失败截图就是这么来的。）

## 2. 这一版做了什么

1. **DMG 顶层只留三样**：`安装萤火虫.app`、`卸载萤火虫.app`、`安装与卸载说明.txt`。
2. **输入法本体与更新程序改为安装器载荷**：`安装萤火虫.app/Contents/Resources/Payload/{Lampyris.app,LampyrisUpdateCheck.app}`，
   由 `packaging/macos/stage-installer-payload.sh` 装入；`make-dmg.sh` 在缺载荷或标识不符时**拒绝出包**。
3. **载荷在签名之前装入**：`codesign` 会封印 bundle 内的文件，签名后再塞载荷会让安装器自己的签名失效
   （干净机器上会被 Gatekeeper 拒绝启动）。发布流程因此调整为「装载荷 → 签安装器/卸载器/更新程序（同一次公证提交）→ 打 DMG → 签/公证 DMG」。
4. **顺带补上一个旧缺口**：安装器与卸载器现在也各自 staple（此前只有主应用与更新程序有公证票据）。
5. **仍然可审计**：Finder「显示包内容」能看到同一份已签名、已公证的 app；说明文件写清了位置与原因。
6. ZIP 渠道不变（`Lampyris-<v>-universal/` 内仍是 `Lampyris.app` + `LampyrisUpdateCheck.app` + `scripts/`），`install.sh` 不改。

## 3. 这一版要求你验证什么

在这台 MacBook Air（普通帐户、无 Xcode/CLT）走真实下载链路：

1. 打开 DMG：**只看到**「安装萤火虫」「卸载萤火虫」「安装与卸载说明」三样（没有可点的 `Lampyris.app`）；
2. 双击「安装萤火虫」→「安装」：全程完成，版本行显示 `1.4.2 · 构建 50`；
3. 装完双击 `~/Applications/LampyrisUpdateCheck.app`：出窗口；
4. 需要时用「显示包内容」能看到 `Contents/Resources/Payload/` 里的两个 app（可审计性）。

## 4. 本地验证（开发机，签名链路未验）

| 项 | 结果 |
|---|---|
| `stage-installer-payload.sh` + `make-dmg.sh` 预览 | DMG 顶层正好三个条目；载荷在 `Contents/Resources/Payload/` |
| 从该 DMG 直接开安装器 | 窗口 520×314，版本行读的是载荷里的 `Info.plist` |
| 契约测试 | `test-dmg-updater.py` 22 例（载荷进包 / 缺载荷拒绝 / 标识不符拒绝 / 顶层只有三样 / 先装载荷再签名）|
| 反例守住 | `bash -n` 语法检查；`make verify` + 离线回归全绿（见 §5）|

签名/公证链路（`ci-sign.sh --also` 三件套 + DMG）只能在 CI 上验证，本机没有证书。
