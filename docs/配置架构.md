# 配置架构设计（萤火虫输入法）

> 目标：**极简配置、真值唯一、单一写入路径、改动实时生效**。
> 本文是配置子系统的权威设计，配合 `docs/技术架构方案.md`（v0.2）的总体架构阅读。

---

## 0. 名词

| 术语 | 含义 |
|---|---|
| **Schema（选项元数据）** | 每个选项的**唯一定义**：键名、类型、默认值、取值范围、中文说明。定义在 Rust 里，**只有一份** |
| **配置文件** | `config.toml`，用户显式设置的值。**唯一的持久化真值** |
| **快照（Snapshot）** | 运行时由「Schema 默认值 + 文件覆盖值」合并出的不可变 `Config`，**所有组件唯一的读取源** |
| **变更事件** | 配置变化后广播的通知，订阅者据此**即时生效**，无需重启 |

---

## 1. 四条铁律

| # | 规则 | 为什么 |
|---|---|---|
| **R1** | **文件是唯一的持久真值**。禁止把配置另存到 `UserDefaults`、注册表、`NSUserDefaults`、环境变量或第二个文件 | 避免"两份配置互相打架"，是"真值唯一"的核心 |
| **R2** | **运行时只有一份快照**（`Arc<Config>`）。所有组件（引擎/宿主/UI）都读它，**不各自缓存副本** | 避免状态漂移 |
| **R3** | **只有 `ime_config_set()` 能改配置**。它负责：校验 → 更新内存 → **原子写文件** → 广播事件 | 单一写入路径，杜绝多写者竞争 |
| **R4** | **选项只在 Schema 定义一次**。默认值、范围、说明都来自它；设置界面按 Schema **动态生成**；文件里的注释也由 Schema 生成 | 杜绝"默认值写在三个地方" |

## 2. 数据流

```
         外部文本编辑               设置界面 / 快捷键 / CLI
              │                            │
              │  (文件监听)                 │  ime_config_set(key, value)
              ▼                            ▼
     ┌──────────────────────────────────────────────────┐
     │              ime-config 模块（唯一写入者）          │
     │  load → 校验 → 迁移 → 合并 Schema 默认值            │
     │        → ArcSwap<Config>  ← 广播 ConfigChanged     │
     └───────────────────────┬──────────────────────────┘
       原子写回 config.toml   │  读（零拷贝、无锁）
        (temp + rename + 锁)  ▼
     ┌──────────────────────────────────────────────────┐
     │   引擎 / 宿主 / 候选窗 / 设置界面 全都读同一份快照   │
     └──────────────────────────────────────────────────┘
```

- **写**：永远走 `ime_config_set()` → **写回文件** → 广播。
- **读**：`ArcSwap` 无锁读取同一份快照。
- **外部编辑**：文件监听（debounce）+ 重新加载，等价于一次写入。

---

## 3. 跨进程的"真值唯一"

macOS/iOS/Windows 上，**设置界面常常是独立进程**，而输入法宿主是另一个进程。这不能破坏唯一性：

- **配置文件是跨进程的单一真值**：每个进程都从同一个文件加载；
- **写入用「加锁的读-改-写 + 原子替换」**：临时文件 → `fsync` → `rename()`（POSIX 原子；Windows 用 `MoveFileEx` + `MOVEFILE_REPLACE_EXISTING`）；配合文件锁避免并发覆盖；
- **其他进程靠文件监听感知变化**，重新加载并广播本地事件 → 各自即时生效。

> 因此：设置界面**不允许自己解析/写 TOML**，只能通过 `ime-config` 的接口（经 IPC 委托给 IME 进程）请求修改。
> **唯一写者 = IME 进程**；其它进程只读 + 监听。

## 4. 实时生效（无需重启）

```rust
// ime-config
static CONFIG: ArcSwap<Config> = ...;

pub fn set(key: &str, value: &str) -> Result<(), ConfigError> {
    let mut next = (**CONFIG.load()).clone();   // 1. 基于当前快照
    schema::validate_and_apply(&mut next, key, value)?; // 2. 按 Schema 校验
    persist_atomic(&next)?;                      // 3. 原子写文件
    CONFIG.store(Arc::new(next));                // 4. 发布新快照
    notify_subscribers();                        // 5. 广播
    Ok(())
}
```

订阅方各自处理：

| 组件 | 响应动作 |
|---|---|
| 五笔引擎 | 立即应用 `auto_commit` / `z_key` / 简码开关 |
| 拼音引擎 | 立即应用 `fuzzy` / `max_in_mixed` |
| 候选窗 | 立即应用 `count` / `theme` / 字号（**当前正在输入的候选立即重排重绘**） |
| 快捷键层 | 重新注册 `toggle_mode` |

- 技术选型：`arc-swap`（无锁快照）+ 自建观察者列表（**不引入 `tokio` / 异步运行时**，为一个 watcher 拉运行时不值）；**不引入 TOML 热重载黑魔法**，写入路径由我们自己控制。
- 配置**很少变**（人工操作），所以"每次写文件"完全可接受，无需节流；只有快捷键连按循环切换时做 **300–500ms 防抖**。

## 5. 配置 vs 会话状态（避免把临时状态写进配置）

| 类别 | 例子 | 是否持久化 | 存放 |
|---|---|---|---|
| **配置（偏好）** | 输入模式、auto_commit、theme、快捷键 | ✅ | 快照 + `config.toml` |
| **会话状态（临时）** | 当前组合缓冲、候选页码、预编辑串 | ❌ | 引擎内存，不进配置 |

> **输入模式 `mode` 属配置**（记住用户上次选择，重启后保持）；"默认混合"体现为 Schema 里的默认值。

## 6. v1 精简配置（共 7 项）

原则：**能自动的绝不暴露，能默认的绝不写进文件**。Schema 里可以定义更多选项，但**文件里只出现这 7 个**，其余用默认值。

```toml
# ═══ 萤火虫输入法 · 配置 ═══
# 改完保存即时生效，不用重启
# 以 # 开头的都是说明

mode = "mixed"
# mixed = 五笔优先 + 拼音兜底（推荐） | wubi = 仅五笔 | pinyin = 仅拼音

[wubi]
auto_commit = true      # 打满四码且唯一时直接上屏
z_key       = "wildcard"  # z 键：wildcard = 万能键 | none = 关闭

[pinyin]
fuzzy = false           # 模糊音（zh=z、ch=c、sh=s、n=l…）

[candidate]
count = 7               # 每页候选数（3–9）

[appearance]
theme = "auto"          # auto = 跟随系统 | light | dark

[hotkey]
toggle_mode    = "ctrl+shift+m"   # 循环切换 混合 → 五笔 → 拼音
toggle_english = "shift"          # 中英：shift = 单独按 Shift（对齐搜狗/微信）| 组合键 | none
toggle_width   = "shift+space"    # 全/半角（对齐搜狗/微信）| 组合键 | none
```

后续按需从 Schema **开放**新选项（如 `show_radical`、`font_size`、`page_up/down`、`简繁切换`、`标点全半角`、`候选横排/竖排`），**加选项不改架构**：Schema 加一项 → UI 自动出现 → 文件按需写。

## 7. 健壮性

| 场景 | 处理 |
|---|---|
| 文件不存在 | 用 Schema 默认值生成一份（或直接内存默认，首次改动时再落盘） |
| 文件语法错误 | **保留上一份可用快照**，不崩溃；日志/UI 提示"第 N 行有误" |
| 未知键 | 忽略并警告（向前兼容），**不删除**用户写的未知键 |
| 版本升级 | 文件带 `version`；`migrate()` 单向迁移旧键，迁移前备份 |
| 并发写（多进程） | **唯一写者 = IME 进程**；其它进程只读 + 监听。文件锁 + 原子替换仍是底层防护，但不应依赖 last-writer-wins 仲裁 |
| 磁盘只读 | 降级为"会话内生效、不持久化"，并提示 |

## 8. 选项元数据（Schema）——驱动一切

每个选项**只定义一次**：

```rust
struct OptionSpec {
    key: &'static str,           // "wubi.auto_commit"
    value_type: ValueType,       // Bool / Enum(&[...]) / Int(Range)
    default: Value,
    doc_zh: &'static str,        // "打满四码且唯一时直接上屏"
    scope: Scope,                // 需要实时生效的组件（引擎/候选窗/快捷键）
}
```

由它派生：

- **C ABI**：`ime_config_schema()` 供设置界面动态渲染表单，界面**零硬编码**；
- **文件注释**：**只在首次生成文件时**按 Schema 写入中文说明；后续 `set` 只改对应键，**不重写用户文件**（避免破坏用户手写格式）；
- **校验**：类型/范围/枚举值；
- **默认值**：唯一出处。

## 9. C ABI 草案（`ime-ffi`）

```c
// ── 初始化（宿主最先调用，设定配置文件路径）──────
int32_t               ime_config_init(const char* path);

// ── 读取（所有组件）─────────────────────────────
// 返回当前快照的借用指针，下次 set/reload 前有效；线程安全只读
const ImeConfig*      ime_config_snapshot(void);
const char*           ime_config_get(const char* key);   // 取单个值（字符串形式，线程本地缓冲）
const char*           ime_config_last_error(void);       // 最近一次加载/重载失败原因；空串=无错误（ADR-059）

// ── 元数据（设置界面用）─────────────────────────
const ImeConfigSchema* ime_config_schema(void);          // 选项清单，含类型/默认/说明

// ── 写入（唯一写入路径）─────────────────────────
int32_t ime_config_set(const char* key, const char* value_toml); // 0=成功
int32_t ime_config_reload(void);                          // 强制从文件重载

// ── 变更通知（实时生效）─────────────────────────
typedef void (*ImeConfigChangedFn)(const char* key, void* user);
int32_t ime_config_subscribe(ImeConfigChangedFn cb, void* user);
void    ime_config_unsubscribe(int32_t token);
```

**契约**：
- `snapshot` 返回的是**借用**，调用方不得释放；任何 `set` 之后应重新获取；
- `get` / `last_error` 返回**线程本地**缓冲（同一线程下次调用前有效）；
- `set` 是 `catch_unwind` 包裹的，绝不 panic 穿越 FFI；所有字符串 UTF-8；
- 配置接口**线程安全只读**（内部 `ArcSwap`）；但 `subscribe` 回调在**触发 `set`/`reload` 的那个线程上同步派发**（外部编辑时即 `ime-config` 的文件监视线程），宿主若需更新 UI 必须自行转主线程——本仓库统一由 `ConfigWatcher` 做 `DispatchQueue.main.async`（ADR-058）；
- ⚠️ **与会话接口的线程模型不同**：`ImeSession` 是**单线程绑定**（见 `技术方案.md` §5.3），勿把两者的跨线程契约混用。

## 10. 实现落点

```
crates/
├── ime-config/
│   ├── src/schema.rs     # OptionSpec 全表（唯一真值定义）
│   ├── src/config.rs     # Config 结构体 + 合并默认值
│   ├── src/persist.rs    # 原子写 / 文件锁 / 迁移 / 监听
│   ├── src/watch.rs      # 外部编辑监听 + 广播
│   └── src/lib.rs        # ArcSwap 快照 + set/get/subscribe
└── ime-ffi/              # §9 的 C ABI（唯一 unsafe 集中地）
```

## 11. 验收（Phase 1 内）

1. 改 `config.toml` 保存后，**正在输入的候选窗立即按新设置变化**，无需重启。
2. 用菜单/快捷键改 `mode`，**立刻生效并写回文件**。
3. 全仓库**只有一个文件**保存配置（代码审查断言：不出现 `UserDefaults`/注册表写配置）。
4. 删掉某一行 → 该项回落到 Schema 默认值。
5. 写坏语法 → 输入法**照常工作**（用上一份快照）并提示错误行。
6. 设置界面（后续）**不含任何选项硬编码**，完全由 `ime_config_schema()` 渲染。
