# 候选框 v4：简洁选词与五笔学习

2026-10-14，用户指派设计更新，替代v3候选提案；未实施产品代码。

## 结构

上行保留预编辑码和条件页码，主体为序号＋候选。当前项仅使用**加粗、较强文字层级**，不添加选中背景、色块或边框；非当前项使用可读的次级文字。当前候选标识不等于键盘焦点，也不靠颜色单独判断。

下方只显示当前项的学习信息，细分隔线隔开，不在每个候选下面重复。五笔及混合模式显示；纯拼音模式整块隐藏，窗口随之缩短。混合模式的拼音候选也依据目标字词查五笔，与候选来源无关。

- 单字：目标字＋完整五笔86编码；字根与码位对应；有识别码时另行解释末笔与字型。不能把完整码末位一律当字根或一律当识别码。简码与完整码区分，默认教学展示完整码。
- 词组：目标词＋词组编码；各字参与取码的片段＋词组规则。两字各前两码，三字前两字各首码加第三字前两码，四字及以上前三字和末字各首码。各字拆分及完整码也应可读地列出，长词按必要内容展开高度，不重复所有候选的说明；多字词不取中间所有字的编码。当前词组稿展示取码摘要和逐字字根示例，完整逐字编码与识别码解释仍按实际可靠数据展开。
- 多编码：优先与实际方案/候选码一致的可验证完整码；不能把用户词的自定义码冒称规范码。方案或规范码不明确时标清自定义编码，教学拆分缺失时不给虚构规则。
- 无码：显示“五笔编码暂缺”；有码无可靠拆分：保留编码并显示“拆字说明暂缺”。缺失只发生在学习区，不阻碍选词和上屏。
- 无候选：不显示学习区；长文本按实测换行，字号保持可读，不用省略号截断拆分关系。定位仍不夺取客户端焦点。

## 交互契约与待实现事项

当前项变化时同步更新学习区，禁止显示上一个字的解释。首项默认为空格提交目标；数字或鼠标选择仍依既有契约，不增加箭头选词或改变Enter/Esc/退格/翻页行为。设计高亮不是新增候选导航实现。一次直接提交可能不会留下学习浏览时间；本轮不新增提交后悬浮、延时上屏或强制教学步骤。

当前工程只有D13键名字提示，不等于实际拆字；现有reverseLookup仅查拼音。候选关联完整五笔反查、结构解释模型、窄FFI传递、合法可显示的字根字形与数据覆盖均为后续实现项。D2/D3表示不同，D3有PUA且明确作为非发布oracle，不能直接将其字符串塞进UI；引入派生数据须按来源许可/SHA与数据skill审核。末笔字型/成字字根/键名字等规则需逐类校验。现有工具提示不能作为拆字真实性证据。

稿件单字样例“你 WQIY”、词组“你好 WQVB”编码已查现有码表；拆分展示为设计样例，尚未建立可发布、自动验证的逐字教学数据。原生字体是否覆盖所有字根须单独验证，不能用错误形近字替代。

## 样例与验证边界

8张AppKit离屏稿覆盖亮暗/高对比单字、混输拼音找到词组、纯拼音隐藏学习区。参考宽360pt；单字学习态154pt，词组示例178pt，纯拼音74pt。实际尺寸按候选数、拆分内容、字号和屏幕动态测量。这些不是固定生产尺寸。

系统语义色沿v2，选中项不使用背景。原型仅静态内容，编译warnings-as-errors；不证明真实AX、教学数据正确率、长词展开或实机焦点通过。IT-24和MVP验收保持未关闭。
