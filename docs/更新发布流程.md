# 更新发布流程（GitHub Actions + Ed25519）

> 目标：发版时由 CI 构建/签名/公证 ZIP，生成 appcast 并用**离线私钥**签名；客户端默认从 GitHub Releases 取 feed，
> 用户可在设置「更新 → 更新来源」改成自建 https 地址；验签公钥固定在签名包，用户不能替换。

> **⚠️ 更新私钥不可丢。** `LAMPYRIS_UPDATE_PRIVATE_KEY` 是唯一丢失后无法在现有更新链内恢复的凭据。
> 已安装客户端固定内置公钥；私钥丢失后无法再签出它们信任的更新，只能让用户手动重装带新公钥的版本。
> GitHub Secret 只写不可读，不能当作备份。请在生成私钥后立刻在密码管理器 + 离线加密介质各保存一份 PEM，
> 并定期核对公钥指纹。轮换时必须先用旧私钥签过渡版本，再替换公钥/Secret。

## 1. 生成密钥（只做一次）

在受信任的本机（建议离线机器）执行，OpenSSL 3 自带 Ed25519：

```sh
# 私钥（PKCS#8 PEM，权限 600，绝不入库、绝不贴进聊天/issue）
openssl genpkey -algorithm ED25519 -out lampyris-update-private.pem
chmod 600 lampyris-update-private.pem

# 公钥：Ed25519 公钥 DER 的最后 32 字节就是原始公钥，再 Base64
openssl pkey -in lampyris-update-private.pem -pubout -outform DER | tail -c 32 | base64
```

把输出（Base64，44 字符左右）写入并提交 **`packaging/macos/update-public-key.txt`** —— 公钥是公开值，入库后任何人都能独立复验：

- 构建/工作流默认读该文件写入 `SUPublicEDKey`，**不需要**再配仓库 Variable/Secret（已有旧 Secret 可删除）；
- 仓库 **Secret** 只放私钥：`LAMPYRIS_UPDATE_PRIVATE_KEY`（上面 PEM 的完整内容）；
- 私钥建议同时离线保存；它一旦泄露就能签出被客户端信任的包，按第 4 节轮换。

## 2. 本地校验一次签名链路（可选但推荐）

```sh
# 私钥签名（对 ZIP 原始字节）
openssl pkeyutl -sign -rawin -inkey lampyris-update-private.pem -in Lampyris.zip -out Lampyris.zip.sig
base64 -i Lampyris.zip.sig | tr -d '\n' > Lampyris.zip.sig.b64

# 用已构建的更新程序验签（必须返回 0；它只验签，不安装）
platforms/macos/build/website-updater/LampyrisUpdateCheck.app/Contents/MacOS/LampyrisUpdateCheck \
  --verify-payload Lampyris.zip "$(cat Lampyris.zip.sig.b64)"
```

> 构建更新程序：`python3 platforms/macos/Updater/build.py`（默认使用入库公钥与 GitHub feed）；
> `--public-key` 仅用于轮换或本地测试覆盖。

### 第三方独立复验（只用仓库公开材料）

```sh
# 32 字节原始公钥 → Ed25519 SPKI DER → PEM
{ printf '\x30\x2a\x30\x05\x06\x03\x2b\x65\x70\x03\x21\x00'; \
  base64 -d packaging/macos/update-public-key.txt; } > pub.der
openssl pkey -pubin -inform DER -in pub.der -out pub.pem

# 从 Release 下载 appcast.xml 与 ZIP，取出 edSignature 解码成 sig.bin 后：
openssl pkeyutl -verify -rawin -pubin -inkey pub.pem \
  -in Lampyris-0.1.0-universal.zip -sigfile sig.bin
# 或用源码自建更新程序：LampyrisUpdateCheck --verify-payload <zip> <signature-base64>
```

## 2.5 签名 tag（待启用）

计划要求发版 tag 签名，Release 工作流会用 `git tag -v` 校验。**当前因设备不稳定暂不启用**：仓库没有 `packaging/git-allowed-signers` 时工作流只输出警告并继续；提交该文件后自动转为强制（未签名/签名者不在白名单即失败）。

一次性准备（把**你的** SSH 公钥写进仓库）：

```sh
# 以 SSH 签名（推荐；GPG 同理，改成 gpg.format=openpgp）
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub

# 仓库文件 packaging/git-allowed-signers（每行一个签名者）：
#   you@example.com ssh-ed25519 AAAAC3Nza...
```

之后每次发版：

```sh
git tag -s v0.2.0 -m "Lampyris 0.2.0"   # -s = 签名
git push origin v0.2.0
```

本地校验：

```sh
git config gpg.ssh.allowedSignersFile packaging/git-allowed-signers
git tag -v v0.2.0
```

> `v0.1.0` 是在这条规则之前发布的（未签名）；从下一个 tag 起强制。GitHub 页面上的 “Verified” 徽标需要把同一把
> GPG/SSH 公钥也加到 GitHub 账号，属于额外展示，不替代仓库内的 `git tag -v` 校验。

## 3. GitHub Actions 发版（`.github/workflows/release.yml`）

推送 tag `vX.Y.Z` 触发。沿用既有「main 出包、tag 只发布」流程：`macos-acceptance.yml` 已在同一提交产出签名/公证候选包，
release 工作流按提交找到该产物、校验后只补一次 Ed25519 签名与 appcast，不重新构建。步骤：

1. 触发：推送 tag `vX.Y.Z`（或手动 workflow_dispatch，输入构建号）。
2. 产物：由 main 的 `macOS Acceptance Package` 工作流完成构建、Developer ID 签名与公证；release 工作流用
   `gh run download` 取同一提交的验收产物，再由 `validate-release.py --assets-only` 校验。
3. ZIP 与 `length`：从验收产物中取 `Lampyris-X.Y.Z-universal.zip`；`length` 与 SHA-256 由脚本自动计算。
4. 签名 ZIP：用 `LAMPYRIS_UPDATE_PRIVATE_KEY` 还原 PEM（`chmod 600`），`openssl pkeyutl -sign -rawin`，Base64 得到 `edSignature`。
5. 生成 `appcast.xml`（Sparkle 兼容，客户端与 Python 解析规则一致）：

```xml
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <item>
      <enclosure
        url="https://github.com/EasyIndie/EasyInputMethod/releases/download/vX.Y.Z/Lampyris-X.Y.Z-universal.zip"
        sparkle:version="BUILD"
        sparkle:edSignature="BASE64_SIG"
        length="ZIP_BYTES"
        type="application/octet-stream"/>
    </item>
  </channel>
</rss>
```

6. 上传 release 资产：ZIP、`appcast.xml`、源码附件；`releases/latest/download/appcast.xml` 即为默认 feed 地址。
7. 客户端：独立更新程序显式检查 feed → 选 build 更高项 → 下载 → 验签 → 用户确认 → Swift `UpdateInstaller` 停宿主/备份/替换/回滚；命令行演练可单独用 `packaging/macos/upgrade.py`。PR #142（main `56c2457`）的修复使 Swift 下载的私有临时 ZIP 在确认取消、验签/安装失败或完成后释放清理；成功升级仅保留旧包备份与 receipt，失败回滚后清理 staging。尚未出包含此修复的新签名包，不应把旧已装版本计为通过。两条实现路径都不能以下载成功代替验签。

脚本与命令（也是 CI 实际执行的）：

```sh
# 生成签名 appcast（离线；--openssl 可指定 brew openssl@3）
python3 packaging/macos/release-appcast.py   --zip packaging/out/release/Lampyris-0.1.0-universal.zip   --build "$(python3 tools/release_version.py build)"   --short-version "$(python3 tools/release_version.py version)"   --url "https://github.com/EasyIndie/EasyInputMethod/releases/download/v0.1.0/Lampyris-0.1.0-universal.zip"   --private-key "$RUNNER_TEMP/lampyris-update-key.pem"   --out packaging/out/release/appcast.xml
# 输出 JSON 含 length/sha256/signature；随后用已构建的更新程序自检：
LampyrisUpdateCheck --verify-payload <zip> "<signature>"
```

发布步骤用 `gh release create <tag> <zip> <appcast.xml> --verify-tag` 上传两个资产，
`releases/latest/download/appcast.xml` 即默认 feed。

> 注意：GitHub Releases 会 302 到 `release-assets.githubusercontent.com`；客户端只允许
> `github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`、`raw.githubusercontent.com` 四个 https 主机。

### 不发版的签名更新程序诊断（ADR-286）

仅需核验当前 main 的独立更新程序时，可手动触发 `Update Signing Check`（`--ref main`）。该任务仅在 main 使用签名凭据，先签名/公证、用临时负载验证入库公钥与私钥并拒绝篡改，再上传保留 7 天的 `Lampyris-updater-diagnostic-<SHA>`，内含 ZIP、ZIP SHA 和 `SOURCE-COMMIT.txt`。下载后必须回读附件 SHA、包的标识/版本/双架构/签名公证、执行 SHA；不能把该产物当作 Release、升级 feed 或已完成真实 UI 原生验收。任务不创建 tag/Release、不安装程序、不下载真实 feed；版本/构建号若仍与已发布版相同，不可覆盖生产身份。

### 隔离验收目标（ADR-287，分阶段）

安装器现在把包名/可执行路径/标识视为同一 `InstallTarget`，生产更新窗口显式选择原有生产目标，默认不变。测试构建只能在签名包内同时带 `LampyrisTestOnly=true`、UUID 隔离身份与已拥有私有根时，才把安装域/备份/receipt 指向该根；任一字段缺失或不符即停用更新，不回退生产目录；`build.py` 拒绝把这三个键写进发行产物（报告181）。离线测试覆盖私有临时域的备份/失败回滚与生产包哨兵；**这不能当作签名包 UI 真机安装 PASS**。仍缺：签名隔离更新程序、经公证的隔离载荷、受控 HTTPS 签名 feed 与新测试构建号；在这些门禁完成前，不得运行现有诊断 build20 附件执行安装，也不得将测试配置写到真实 `config.toml`。不创建正式 appcast、tag 或 Release。

### 隔离更新 drill 的公开测试 feed（ADR-288）

用户已选择方案 a：drill 使用项目自有 Pages 子路径 `https://input.jokerhub.cn/drill/`（HTTPS，Let's Encrypt；`easyindie.github.io` 会跳 http，禁用）。流程：

1. main-only 手动工作流 `Isolated Update Drill`（输入接收设备的私有根、架构、测试构建号、`drill` 子路径）用临时 Ed25519 密钥生成隔离更新程序（`build.py --isolated-root/--isolated-identity/--test-build`）、签名并公证的隔离输入法载荷与 `appcast.xml`，作为保留 7 天的 artifact 上传；更新程序自身只做 Developer ID 签名（不参与验签链，载荷已单独公证）；
2. 专用发布任务把当前 `site/` 与该 artifact 合并后部署 Pages（测试二进制不入 git 历史）；
3. 本机在 `LampyrisIMKTest.<UUID>` 私有根内执行原生 drill，任何时刻都不得触碰生产包/配置/词库/输入源；
4. drill 结束重跑普通 Pages 部署下线 `/drill/`，删除私有根与测试更新程序。

drill 目录不是正式升级来源，不得创建 tag/Release、不得改生产公钥或默认 feed、不得修改系统信任库与 /etc/hosts。

## 4. 轮换与回滚

- 换密钥：新版本包用**旧私钥**签一次做过渡（客户端公钥仍匹配），随后发行公钥更新的版本；不要只换公钥就发，旧客户端会拒绝。
- 撤包：从 release 删除资产并更新 appcast（build 置空/回退）即可；已下载包仍会验签，未验签不得安装。
- 私钥泄露：立即停止发版、发布新公钥版本，并公告旧包不再可信。
