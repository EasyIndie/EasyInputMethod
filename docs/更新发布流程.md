# 更新发布流程（GitHub Actions + Ed25519）

> 目标：发版时由 CI 构建/签名/公证 ZIP，生成 appcast 并用**离线私钥**签名；客户端默认从 GitHub Releases 取 feed，
> 用户可在设置「更新 → 更新来源」改成自建 https 地址；验签公钥固定在签名包，用户不能替换。

## 1. 生成密钥（只做一次）

在受信任的本机（建议离线机器）执行，OpenSSL 3 自带 Ed25519：

```sh
# 私钥（PKCS#8 PEM，权限 600，绝不入库、绝不贴进聊天/issue）
openssl genpkey -algorithm ED25519 -out lampyris-update-private.pem
chmod 600 lampyris-update-private.pem

# 公钥：Ed25519 公钥 DER 的最后 32 字节就是原始公钥，再 Base64
openssl pkey -in lampyris-update-private.pem -pubout -outform DER | tail -c 32 | base64
```

把输出（Base64，44 字符左右）记为 `SUPublicEDKey`：

- 仓库 **Variables**：`LAMPYRIS_UPDATE_PUBLIC_KEY`（发版构建时写入 Info.plist 的 `SUPublicEDKey`）；
- 仓库 **Secrets**：`LAMPYRIS_UPDATE_PRIVATE_KEY`（上面 PEM 文件的完整内容）；
- 私钥建议同时保存在离线介质；CI secret 只是发布便利，泄露可导致"能签出被客户端信任的包"。

## 2. 本地校验一次签名链路（可选但推荐）

```sh
# 私钥签名（对 ZIP 原始字节）
openssl pkeyutl -sign -rawin -inkey lampyris-update-private.pem -in Lampyris.zip -out Lampyris.zip.sig
base64 -i Lampyris.zip.sig | tr -d '\n' > Lampyris.zip.sig.b64

# 用已构建的更新程序验签（必须返回 0；它只验签，不安装）
platforms/macos/build/website-updater/LampyrisUpdateCheck.app/Contents/MacOS/LampyrisUpdateCheck \
  --verify-payload Lampyris.zip "$(cat Lampyris.zip.sig.b64)"
```

> 构建带公钥的更新程序：`python3 platforms/macos/Updater/build.py --public-key "$(cat pub.b64)"`，
> 它会写入默认 GitHub feed 与公钥；不带公钥则是关闭状态（不联网）。

## 3. GitHub Actions 发版（`.github/workflows/release.yml`）

推送 tag `vX.Y.Z` 触发。沿用既有「main 出包、tag 只发布」流程：`macos-acceptance.yml` 已在同一提交产出签名/公证候选包，
release 工作流按提交找到该产物、校验后只补一次 Ed25519 签名与 appcast，不重新构建。步骤：

1. 触发：推送 tag `vX.Y.Z`（或手动 workflow_dispatch，输入构建号）。
2. 产物：由 main 的 `macOS Acceptance Package` 工作流完成构建、Developer ID 签名与公证；release 工作流用
   `gh run download` 取同一提交的验收产物，再由 `validate-release.py --assets-only` 校验。
3. ZIP 与 `length`：从验收产物中取 `Lampyris-X.Y.Z-universal.zip`；`length` 与 SHA-256 由脚本自动计算。
4. 签名 ZIP：用 `LAMPYRIS_UPDATE_PRIVATE_KEY` 还原 PEM（`chmod 600`），`openssl pkeyutl -sign -rawin`，Base64 得到 `edSignature`。
5. 生成 `appcast.xml`（Sparkle 兼容，客户端与 Python 解析规则一致）：

```xml
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <item>
      <enclosure
        url="https://github.com/EasyIndie/EasyInputMethod/releases/download/vX.Y.Z/Lampyris-X.Y.Z-universal.zip"
        sparkle:version="BUILD"
        sparkle:edSignature="BASE64_SIG"
        length="ZIP_BYTES"
        type="application/octet-stream"/>
    </item>
  </channel>
</rss>
```

6. 上传 release 资产：ZIP、`appcast.xml`、源码附件；`releases/latest/download/appcast.xml` 即为默认 feed 地址。
7. 客户端：更新程序 `--check` 取 feed → 选 build 更高项 → 下载 → 先验签 → 再走 `packaging/macos/upgrade.py`（停宿主/备份/替换/回滚）。

脚本与命令（也是 CI 实际执行的）：

```sh
# 生成签名 appcast（离线；--openssl 可指定 brew openssl@3）
python3 packaging/macos/release-appcast.py   --zip packaging/out/release/Lampyris-0.1.0-universal.zip   --build "$(python3 tools/release_version.py build)"   --short-version "$(python3 tools/release_version.py version)"   --url "https://github.com/EasyIndie/EasyInputMethod/releases/download/v0.1.0/Lampyris-0.1.0-universal.zip"   --private-key "$RUNNER_TEMP/lampyris-update-key.pem"   --out packaging/out/release/appcast.xml
# 输出 JSON 含 length/sha256/signature；随后用已构建的更新程序自检：
LampyrisUpdateCheck --verify-payload <zip> "<signature>"
```

发布步骤用 `gh release create <tag> <zip> <appcast.xml> --verify-tag` 上传两个资产，
`releases/latest/download/appcast.xml` 即默认 feed。

> 注意：GitHub Releases 会 302 到 `release-assets.githubusercontent.com`；客户端只允许
> `github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`、`raw.githubusercontent.com` 四个 https 主机。

## 4. 轮换与回滚

- 换密钥：新版本包用**旧私钥**签一次做过渡（客户端公钥仍匹配），随后发行公钥更新的版本；不要只换公钥就发，旧客户端会拒绝。
- 撤包：从 release 删除资产并更新 appcast（build 置空/回退）即可；已下载包仍会验签，未验签不得安装。
- 私钥泄露：立即停止发版、发布新公钥版本，并公告旧包不再可信。
