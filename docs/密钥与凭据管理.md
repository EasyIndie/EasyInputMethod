# 密钥与凭据管理（多项目统一）

> 目标：私钥不丢、不泄露、可轮换；公钥/指纹可公开复验；CI 用最小权限拿到**一份**密钥副本。

## 0. 最重要：更新私钥丢失后不可恢复

**`LAMPYRIS_UPDATE_PRIVATE_KEY`（Ed25519 更新签名私钥）是本项目唯一一旦丢失就无法在现有更新链内恢复的凭据。**

- 已安装客户端内置的是对应**公钥**；私钥丢失后，无法再签出这些客户端愿意安装的更新。
  只能发布一个内置新公钥的新版本，让现有用户**手动重新安装**，更新链重置。
- GitHub Secret 是**只写不可读**的；Secret 里有一份**不等于有备份**，无法从 GitHub 导出。
- 必须至少保存两份可读副本：密码管理器 + 离线加密介质（或等价的离线保险库）。
- 备份的是 PEM 原文；记录公钥指纹，定期核对（见 README 的 `0fdcb0db…`）。
- 不要把 PEM 放进仓库、issue、聊天、CI artifact、Downloads 或明文笔记。
- 轮换顺序：**旧私钥签过渡版本 → 新公钥入库 → 再删除旧 Secret**；不要先删旧钥，否则过渡版本也签不出来。


## 1. 本项目涉及哪几把密钥（不要混用）

| 用途 | 类型 | 存放 | 是否公开 |
|---|---|---|---|
| 更新包签名（appcast/ZIP） | Ed25519 私钥/公钥 | 私钥仅 GitHub Secret `LAMPYRIS_UPDATE_PRIVATE_KEY`（建议另存密码管理器）；公钥提交在 `packaging/macos/update-public-key.txt` | 公钥公开 |
| 发版 tag 签名 | SSH（推荐）或 GPG 签名密钥 | 私钥在本机 `~/.ssh/`（可放密码管理器）；公钥提交在 `packaging/git-allowed-signers` | 公钥公开 |
| macOS 代码签名/公证 | Apple Developer ID 证书 + ASC API Key | GitHub Secrets（`APPLE_CERTIFICATE_P12_BASE64` 等） | 否 |
| GitHub 访问 | PAT / Actions token | 尽量用 `GITHUB_TOKEN`；长寿命 PAT 放密码管理器 | 否 |

原则：**一把密钥只做一件事**。更新签名密钥不要拿去签 Git tag，反之亦然。

## 2. 推荐的统一保管方式（按项目数量）

### 方案 A：密码管理器 + 组织级 Actions Secret（推荐给你）

- **真源**：1Password / Bitwarden 的专用保险库（如 “Dev / Release Keys”），每个项目一条 item：
  更新私钥 PEM、tag 签名私钥（或引用硬件密钥）、公钥与指纹、创建/轮换日期、负责人。
- **CI**：使用 **组织级 secrets**（Organization → Settings → Secrets → Actions）供多个仓库共享，
  再配合 **Environment（如 `release`）+ Required reviewers**，只有受保护的发版 job 能读；
  仓库级 secret 只放项目独有的东西（如本项目更新私钥）。
- **本机**：`op`/`bw` CLI 注入，避免明文落盘；SSH 私钥放 `~/.ssh` 并设 `600`，也可由密码管理器 SSH agent 提供。
- **好处**：一个入口统一管理多项目；离职/换机可审计；避免“哪台机器上还有一份”的隐性副本。

### 方案 B：集中密钥服务（项目多、团队协作时）

- HashiCorp Vault / AWS Secrets Manager / Doppler / Infisical：
  CI 用 **OIDC** 换取短期凭据（GitHub → 云），不落长期私钥；
  适合多个仓库、多人、需要审计日志与自动轮换的场景。
- 成本：多一个服务依赖；个人多项目可先用方案 A。

### 方案 C：加密密钥库仓库（离线备份）

- 用 `age` 或 GPG 把私钥加密后放**私有**仓库（或加密 U 盘），解密私钥只放 CI secret；
- 适合“需要版本化备份但不想依赖第三方保险库”的场景；务必把解密口令单独保存（密码管理器）。

### 硬件密钥（更强保证，可选）

- YubiKey（OpenPGP 或 PIV）承载 tag 签名密钥：私钥不可导出，签名需触碰；
- 更新签名若要自动化，仍需软件私钥放 CI，因此**更新签名与 tag 签名分开**：前者自动化，后者人工硬件签。

## 3. 落地清单（本项目）

1. 更新私钥：GitHub Secret `LAMPYRIS_UPDATE_PRIVATE_KEY` + 密码管理器离线副本（同一份，定期核对指纹）。
2. tag 签名：把**你的 SSH 公钥**写进 `packaging/git-allowed-signers`，发版用 `git tag -s`。
3. 发版 job 绑定 `release` environment（要求人工批准），只在该 environment 暴露更新私钥。
4. 90–180 天检查一次：secret 是否仍需要、指纹是否与 README 一致、离职/换机后是否已轮换。
5. 轮换按 `docs/更新发布流程.md`：旧钥签过渡版本 → 新公钥入库 → 删除旧 secret。

## 4. 反例（不要做）

- 把私钥贴进 issue/聊天/提交历史（即使后来删除，历史仍在）；
- 多个仓库各存一份不同私钥、公钥却只更新一处；
- 用同一个密钥既签更新包又签 Git tag，泄露后两边一起失守；
- 把 `LAMPYRIS_UPDATE_PRIVATE_KEY` 暴露给 `pull_request` 触发的 workflow（fork PR 不应能读 secret）。
