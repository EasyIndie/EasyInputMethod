> 本文件是本项目**数据准入的唯一权威记录**。任何进入 `data/` 或被内置/分发的内容，必须在此登记。
> 配套：`技术方案.md` §7、`决策记录.md`。

## 0. 为什么需要这份文件

Rime 生态长期存在"词典许可不明"的灰区：很多五笔/拼音码表被第三方以宽松许可重新发布，但底层可能来自**闭源商业输入法**（如极点五笔、微软五笔）。`SamsonLab/pure-ime` 专门为此建立了 data intake policy，本项目照做。

**原则：**

1. **可追溯**：每份数据记录来源 URL、上游作者、声明许可、加入日期、SHA-256。
2. **可再分发**：只收许可明确允许再分发（且与本项目 GPL-3.0 兼容）的数据。
3. **可生成**：优先使用"我们能自己生成"的数据（如由公开规范 + 编码器生成码表）。
4. **可替换**：数据与代码解耦，码表只是数据包；法律问题不牵连代码。
5. **标注风险**：第三方"重新授权"的数据打 ⚠️，不得作为不可替代的唯一来源。

## 2. 自建流水线（首选路径）

```
字根表（公开规范）
   +  编码器（自研 Rust：键名字/成字字根/合体字/末笔字型识别码）
   +  字→字根拆分（D2，多份 MIT 数据交叉校验）
   ↓
单字码表（D1，自建）
   +  词组表（D4，MIT）+ 词组编码规则
   ↓
词组码表（自建）
   +  词频（D10）
   ↓
data/generated/*.tsv（文本真值；不产出 `.imedict`，ADR-060）
```

- 生成脚本与源数据哈希**全部开源**，任何人可复现；
- 交叉校验：**自建码表 vs D3 码**（oracle）全量对照，不一致处逐条归因（ADR-016）；
- 回归测试可用公开码表（含 LGPL 表）**仅作对照，不进产物、不分发**。

## 3. 准入流程（新增任何数据前）

1. 在 §1 表格新增一行，填写来源/上游/许可/风险；
2. 下载并与上游 `LICENSE` **逐字核对**（不接受"仓库根目录没写许可"的默认推断）；
3. 计算 SHA-256 并记录；源文件放 `data/sources/`（如体积大则记录下载脚本）；
4. 若为"第三方重新授权"或上游不明 → 标 ⚠️，并寻找替代；
5. 更新 `data/sources.toml`（机器可读版本）；
6. CI 校验：`data/` 下每个文件都能在 `sources.toml` 里找到登记。

- **自产数据/词库/字体**：建议 **CC-BY-SA-4.0**（词库、码表等有编排的作品）或 **CC0**（字根表、编码规则等事实性数据）；**不用 GPL 覆盖数据**（GPL 是软件许可，不适合数据）。
- **第三方数据**：按各自许可（MIT / Apache-2.0 / CC 系列等）。
- 兼容：MIT、BSD、Apache-2.0、LGPL-3、GPL-3、公有领域、CC-BY、CC-BY-SA。
- 不兼容：与 GPL-3 冲突的许可、无许可（All Rights Reserved）。
- 分发时保留各数据源的版权声明，汇总到 `NOTICE`。
