# MVP后里程碑路线与目标

> 前置：产品MVP按ADR-084完成并正式分发。以下为建议路线，不是已承诺的日期或批准所有新增功能；到阶段再根据用户反馈、数据许可和实测拆卡。P3/P4/P5/P6保留原平台阶段编号，版本号在发布时确定。

| 顺序 | 里程碑 | 目标与范围 | 完成标志 / 启动条件 |
|---|---|---|---|
| R1 | macOS首版稳定维护 | 收敛实际用户兼容/安装/恢复问题，扩展macOS版本和应用覆盖；保持核心体验与隐私承诺 | 发布阻塞反馈关闭，更新兼容矩阵；无新增默认功能，更新可安装且不丢配置/词库 |
| R2（P2深化） | 输入质量与效率 | 基于固定质量集改善长词/简拼/多音字排序和学习；有需求时评估整句；通过实测改善空闲功耗、冷加载和持久化 | 与MVP质量/性能基线比较有明确收益，无混输、延迟、内存或包体回退；FSA替换仅在现有后端不足的证据下立ADR |
| R3（P3） | Windows首个完整版本 | Rust TSF spike限1–2周，失败采用C++薄壳；复用Rust引擎/配置，完成候选、设置、安装及签名 | Win10/11目标应用日常使用验收、平台资源安全及离线可核验；达到与macOS相同核心任务标准，而非只证明能上屏 |
| R4（P4） | Linux首个完整版本 | Fcitx5薄宿主、候选/配置接入、目标发行版打包；IBus仅有实际需求时评估 | 明确发行版/桌面环境支持矩阵，安装、输入、焦点、配置和离线核验通过 |
| R5（P5，分别立项） | Android与iOS核心输入 | 先评估移动端五笔/混输触屏体验与约束；Android Kotlin/JNI，iOS Swift/staticlib且不申请Full Access | 每个平台单独交付输入/布局/无障碍/功耗/生命周期/隐私验收，不把桌面UI直接缩小移植 |
| R6（可选） | 更多输入方案与数据 | 五笔98/新世纪/郑码或必要国际化，需求明确后推进 | 合规来源、编码准确性及回归矩阵充分；不为方案数量增加默认体积/维护负担 |
| R7（P6，可选） | 本地语音可行性 | P6前不做；纯本地独立模块，先评估模型体积、许可、功耗与平台限制 | 纯本地处理、录音不落盘，模型获取工具与核心网络禁令隔离；达不到指标则不交付 |

R1启动后可做R2研究，但一次只实施一项；跨平台阶段启动前确认macOS维护能力，避免现有产品无人维护。Windows/Linux或移动端优先顺序如需求变化，先更新路线决策，不自动同时开工。

持续门禁：零网络/零遥测、配置唯一、依赖许可、数据登记、make verify零诊断、目标平台真实应用验收、版本及对应源码可追溯。自动升级、安装助手、锁自动恢复、引擎替换等需单独ADR，不因出现在路线中视为已冻结设计。

不排期：云同步、账号、广告、AI写作/翻译/搜索、打字统计/画像和剪贴板历史。emoji/皮肤等不属于核心目标，保持暂缓。
