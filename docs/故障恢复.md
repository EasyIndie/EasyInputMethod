# 故障恢复（用户数据 · 配置 · 词库）

> 面向**本机排障**：当输入法的配置或用户词库出现异常时，按本文定位并手工恢复。
> 原则：**输入法绝不自动改写或删除用户文件**；恢复一律是"人工确认后"的操作。

相关：`docs/配置架构.md`（配置铁律）、ADR-029（用户词库有界 TSV v1）、ADR-059（配置错误反馈）。

---

## 0. 数据位置

| 数据 | 路径 |
|---|---|
| 配置（唯一真值） | `~/Library/Application Support/Lampyris/config.toml` |
| 用户词库 | `~/Library/Application Support/Lampyris/user-dictionary.tsv` |
| 用户词库锁（临时） | `~/Library/Application Support/Lampyris/user-dictionary.tsv.lock` |
| 卸载备份 | `~/Library/Application Support/Lampyris/uninstalled/` |

> 系统码表（`wubi86-core.tsv` / `pinyin-*.tsv`）随 `.app` 分发，**只读**，不在用户目录。

## 1. 配置写坏了（TOML 语法错误）

**症状**：菜单里出现「配置错误：配置语法错误（第 N 行…）」，且弹一次提示。

**行为（设计如此）**：输入法**照常工作**——沿用**上一份有效快照**，不会崩溃、不会写入你的文件。

**恢复**：

1. 按提示的**行号**修正 `config.toml` 语法；保存后下次读取自动清除错误（无需重启）。
2. 若已记不清正确格式：删除或重命名 `config.toml`，下次启动即按 **Schema 默认值**重建注释模板（只是回到默认设置，不会损坏其它数据）。

> ⛔ 不要用 `UserDefaults`、注册表或第二个配置文件保存设置——那样会破坏"配置唯一真值"。

### 1.1 配置锁残留（较少见）

配置文件写入时会短暂持有一个 `config.toml.lock`。与用户词库不同，配置锁**超过 30 秒视为异常残留并自动回收**（配置是可重建的偏好）；如果仍遇到"无法保存输入模式/设置"，可手工处理：

```sh
pgrep -x Lampyris || echo "无进程"
rm -f ~/Library/Application\ Support/Lampyris/config.toml.lock
```

## 2. 用户词库：残留锁（异常退出后常见）

**症状**：菜单提示「用户词库读写失败，请检查权限或文件格式」；新学的词不生效。

**原因**：写用户词库时会短暂持有一个 `user-dictionary.tsv.lock`（`create_new`）。若进程**异常退出**（强杀 / 崩溃 / 断电），锁文件可能残留。

**诊断**：

```sh
ls -l ~/Library/Application\ Support/Lampyris/
ls -l ~/Library/Application\ Support/Lampyris/user-dictionary.tsv.lock 2>/dev/null && echo "存在残留锁"
```

**恢复（必须在确认没有活动写者之后）**：

```sh
# 1) 确认没有萤火虫进程在运行
pgrep -x Lampyris && echo "仍有进程，请先切换为 ABC 并退出输入法" || echo "无进程"

# 2) 无进程后，删除残留锁（不要删除 user-dictionary.tsv！）
rm -f ~/Library/Application\ Support/Lampyris/user-dictionary.tsv.lock
```

> ⚠️ **禁止在未确认无写者时删锁**：如果有另一个进程正持锁写入，删锁会破坏"仅一个写者"的保证。
> 因此输入法**不做自动删锁**；这一步必须人工判断。

> ℹ️ **耐久性**：用户词库写入不做逐次 fsync（ADR-066），会话结束时（失焦/退出）统一落盘；进程被强制杀死时可能丢失**最近一次学习**，但文件不会损坏。

## 3. 用户词库：容量 / 权限上限

**症状**：菜单提示读写失败，且**原数据完好**（输入法从不半途改文件）。

**已知上限**（ADR-029）：文件 **≤ 2 MiB**、条目 **≤ 10000** 条；编码 ≤ 64 字节、文本 ≤ 256 字节。

**恢复**：

- 容量满 → 先导出备份（菜单「导出用户词库…」），再精简 `user-dictionary.tsv` 或新建；
- 权限问题 → 确认 `~/Library/Application Support/Lampyris/` 归当前用户所有且可写：
  ```sh
  ls -ld ~/Library/Application\ Support/Lampyris/
  # 需要时：chmod u+rwx ~/Library/Application\ Support/Lampyris/
  ```

## 4. 正式数据文件缺失（正式宿主异常）

**症状**：菜单出现「数据文件错误：…」，输入法回退到**内置样本引擎**（只能打极少量演示字）。

**原因**：`.app/Contents/Resources/` 里缺少 `wubi86-core.tsv`（或拼音表），或文件损坏。**正常安装的包不会缺**——这是异常。

**恢复**：重新安装完整包（`platforms/macos/install.sh` 会校验可执行权限，但资源完整性以**重装**为准）；不要用样本兜底当正式可用状态。

---

## 5. 通用原则（勿违反）

1. 输入法**只读**你的文件；出错时**保留上一份有效数据**。
2. 恢复操作前**先备份**（尤其 `user-dictionary.tsv`）。
3. **不要**跨设备同步、不要写第二配置文件、不要引入在线恢复。
