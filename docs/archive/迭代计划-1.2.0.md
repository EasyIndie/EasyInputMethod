# 1.2.0 迭代计划（顺序与批次）

> 2026-11-06。目标：**除平台扩张（F）外，把 `docs/待办与积压.md` 里的积压项在 1.2.0 周期内"做完或明确关闭"**，
> 不留悬空项。做法是按依赖与风险排成 6 个批次，逐批推进、逐批验证，**只换一次包**。
> 范围来源见 [待办与积压](待办与积压.md)；版本语义见 [MVP后执行计划](MVP后执行计划.md) §0。

## 0. 三条排序原则

1. **先低风险、后高可见**：工程门禁（不改手感）先做，教学与质量改动后做——这样出问题时能立刻排除"是不是门禁改动弄的"。
2. **一条依赖链不打断**：`C1 调研 → C2 字根库 → B4 拆字扩充`、`B3 运行资源 → B1 提示 → B2 练习`，链内不插队。
3. **需要证据的项不预做**：A1/A2/A3/A4/A5 里只有 A4（冷首键）能靠测量推进，其余没有证据就**明确关闭**并写下触发条件，不算"遗留"。

## 2. 每批的完成标志

### B1 工程收口（先做，零手感风险）
- **D2**：CI 里 B0 独立重算**不再 skip**（加 `fetch-wubi-chaizi.sh` 等步骤），失败即红。
- **D5**：内存门禁改用 `vmmap` footprint，误判率 0；`RSS_HARD_MB` 退居参考。
- **D6**：站点版本行由发布流水线生成（`site/index.html` 里 3 处硬编码改为构建期替换），手工 dispatch 即正确。
- **D4**：延迟统计覆盖长编码/翻页/候选窗刷新（至少再两段脚本）。
- **E2**：soak 增加到 30 分钟档（`MINUTES=30`），记录键数/内存/词库一致性。
- 验收：`make verify` + 离线回归零诊断；四项各自有前后对比数字。

### B2 数据地基（ADR 先行）
- 先写 ADR：教学运行时资源的**装载方式**（嵌入 vs 外部文件）、字段子集、FFI 边界（ADR-189 要求"改为外部资源读取需另写 ADR"）。
- 产物：`B0-runtime`（**只保留运行必需字段**：`char/code/class/components/keys/strokes/recognition/quality/notes` 去掉 `ids/positionMismatch/frequency`），扩到 3,000 字。
- 验收：**运行资源 ≤512 KiB**、查询 p95 ≤5 ms、装机包净增量实测、宿主内存不涨过预算。
- 若体积超预算：先减字段/降字数，**不许**为了指标砍真实性（quality 不改口径）。

### B3 教学只读（L3）
- 候选窗/工具栏显示：拆解、识别码依据、简码；`full` 完整讲、`partial` 必带「拆解待核验」、`unknown` 只说缺资料。
- 可关闭（沿用既有学习区开关，**不新增配置项**）。
- 验收：稳态 p95 ≤16 ms 不变；`b0_query.py` 的表述规则在 UI 上不回归；关掉后与 1.1.0 行为一致。

### B4 教学练习（L4）
- 先 ADR（新功能面：题库、判分、进度、导出）。判分**只用 `full` 条目**；零遥测、进度本地。
- 验收：练习窗独立、可关；错题/进度可本地导出；不写第二配置文件。

### B5 质量项（有证据才动）
- **A4**：先用 `phase` 钩子测宿主侧占比；收益 <2 ms 就**不做**并记录。
- **A1**：用 B2–B4 之后的样本集看"非首选率"是否仍明显；不明显就关闭 ADR-304 P2。
- **A2/A3/A5**：**明确关闭**，各写一条触发条件（例如 A3：拿到官方三级简码表 + 用户反馈识别码难记）。
- 验收：每一项都有"做/不做 + 数据"的记录，不留"以后再说"。

### B6 数据扩张（受 C1 结论约束）
- **C1**（可与 B1 并行）：来源与许可调研，只出报告。
- **C2/C3/B4**：只有 C1 找到**许可明确、可追溯、可生成**的来源才做；否则如实在需求文档里写"无合格来源，暂缺"，并把 249 条占位保留为 `？（键 x）`。
- 验收：每份新数据在 `docs/数据来源与许可.md` + `data/sources.toml` 登记（URL + SHA-256 + 许可）。

## 3. 顺序理由（为什么不能换）

1. **B1 必须最先**：D2/D5/D6 是这次发布踩出来的坑，成本小；而且 D2 让 CI 能跑 B0 重算，**后面 B2/B6 的数据改动才有自动防线**。
2. **B2 在 B3 前**：没有运行资源，提示只能靠手写文案，等于把结构库白做。
3. **B3 在 B4 前**：练习题要从提示里取"拆解/识别码"解释，先有只读层再谈判分。
4. **B5 放最后**：它要读 B2–B4 之后的评测数据才能决定做不做，提前做等于拍脑袋。
5. **B6 独立**：数据链只看 C1 结论，不阻塞产品批次；反之如果把 C2 插进 B2–B4，会让"数据没到位"拖住产品。

## 4. 时间与风险

- 乐观（C1 有合格来源、B4 顺利）：**4–5 周**；保守（C1 无来源、B4 需求反复）：**6 周**。
- 最大风险：**B2 体积**（现 558 B/字 × 3,000 = 1.6 MiB，超 512 KiB 三倍）——所以 B2 第一步就是字段子集与实测，不达标就缩字数。
- 次要风险：**B4 是新功能面**，容易膨胀；ADR 里先写死"只做题库+判分+进度，不做社交/排行/云"。
- 全程只在**末期换一次包**；中间用 `dev-preview` 与离线回归验证，不打扰已装版本。
