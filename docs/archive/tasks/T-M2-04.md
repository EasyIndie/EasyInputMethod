## 结论（2026-10-08 完成，调研止步）

- **结论：Phase 1 不接入 `inputx-pinyin`，保留内置轻量兜底；列为 P2「观察」候选。不写后续接入卡、不改产品代码。** 终局仍按 ADR-008 走自研 FSA。
- **依据（实测）**：
  1. **许可达标**：代码 `MIT OR Apache-2.0`；数据（Unihan Unicode v3 / jieba MIT / pypinyin MIT / Leipzig+SUBTLEX CC-BY 4.0）均与 GPL-3 兼容，仅分发派生 FST + 整数词频。**非否决项**。
  2. **体积否决**：核心数据 `pinyin.dict` **4.2 MiB**，默认（含 bigram/trigram）≈ **22.8 MiB**；实测 release 二进制默认 **24.2 MB**、仅 core **4.77 MB**——远超 0.6 MB 预算。
  3. **质量持平**：20 常用词 hit@1 各 **19/20**、hit@5 内置 19/20 vs inputx 20/20；inputx 仅超长整句（中华人民共和国）占优。
  4. **API 可适配但非零成本**：facade 的 `lookup` 不含权重与**简拼**，简拼适配所在 `inputx-core` **未发布 crates.io**，需自写权重/简拼/词级反查适配层。
  5. **维护风险**：单作者（bus factor 1）、crates.io 1.4.0 滞后于 `develop`、API 有变动——不宜作混输兜底关键依赖。
- **附带发现（非本卡范围）**：内置兜底「贪心最长优先」切分把 `mingong` 切成 `ming+o+ng`，导致超长整句词条漏检；留待 P2 自研引擎处理。
- 产出：`docs/reviews/002-inputx-pinyin-spike.md` + ADR-008 spike 复核 + 本结论。验证：`make verify` 全绿（纯文档变更）。
