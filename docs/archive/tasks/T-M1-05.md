# T-M1-05：单字码表生成 + oracle 对照回归（pro）

- **状态**：完成（2026-10-08）
- **模型建议**：**pro**（裁定分歧、判断一致率、设计回归口径）
- **前置**：T-M1-03（编码器）、T-M1-04（D3）、T-M1-04b（oracle #2）、T-M1-05b（结论）
- **目标**：用**本仓编码器**生成单字码表，并与 oracle 做全量对照回归。

> 按 **ADR-016**：发布码表**必须**由本仓编码器生成；第三方码表只作对照。

## 步骤

1. 用 `crates/wubi-encoder` 对拆字数据（D2）逐字编码（键名字/成字字根走 T-M1-02，合体字走 T-M1-03）。
2. 反转索引得到 `code → [字]`；重码先按临时权重（一级字>二级字>其它 + 笔画数）排序。
3. 输出 `data/generated/wubi86-single.tsv`（`code\t字\tweight`；提交生成脚本与统计，大文件按需）。
4. **多 oracle 对照（ADR-019）**：与 **≥2 个独立 oracle** 全量比较（均**仅测试、不打包**）：
   - Oracle #1 = `WindInput`（D3）；Oracle #2 = `rime-wubi`（T-M1-04b）；
   - 报告一致率（全体 + GB2312 一级字），对两个 oracle 分别统计；
   - **三方都不一致**的条目：逐条按五笔86 规范**人工裁定**并记录理由（不得向某个 oracle 拟合）；
   - 一级字一致率目标 ≥ 99%（对两个 oracle 均需达标）。
5. 回归脚本 + 结果摘要写入 `docs/`。

## 验收

- `wubi86-single.tsv` 可由脚本复现生成，**且完全来自自建编码器**；
- 对照回归脚本存在；对**两个 oracle** 的一级字一致率均 ≥ 99%（未达标须记录原因与计划）；
- 差异分析写入文档；
- `make verify` 全绿。

## 铁律提醒

- 对照用第三方码表**不打包、不分发**（ADR-016 + AGENTS.md 铁律 4）；
- 自产码表用 **CC-BY-SA-4.0**（ADR-014）。

## 禁止

- 不把第三方码表提交进仓库或作为发布数据；
- 不硬编码码表进代码。

## 参考

- ADR-016、ADR-007、ADR-014、ADR-013；`docs/技术方案.md` §6.3/§7.1

## 结论与偏差（2026-10-08 完成）

- ✅ **交付**：`crates/wubi-encoder/examples/generate.rs`（生成 + 多 oracle 回归，一条 `cargo run` 可复现）→ `data/generated/wubi86-single.tsv`（27,823 字，471 KB）与 `data/generated/wubi86-regression.txt`。
- ✅ **发布路径（primary）**：用**本仓编码器**对 D3 第 2 列（每码位一字形的干净拆字）逐字生成全码（键名字 `encode_key_name` + 合体字 `encode_hechengzi`）；字根表为公开五笔86 规范在 D3 字形记法下的表达（342 字形，多数表决推导）。
- ✅ **多 oracle 对照（ADR-019）**：
  - primary vs D3：全体 **99.9784%**（27817/27823）、**GB1 100%**（3755/3755）；仅 6 处歧义字形差异（均为生僻扩展区字）。
  - primary vs rime（oracle #2，LGPL-3）：全体 **98.77%**、**GB1 100%**（3755/3755）。
  - **三方两两不一致：0 条**（primary 与 D3 仅 6 处差异，且这些字在 rime 中缺失或与 D3 一致），无需逐条人工裁定。
- ✅ **交叉检查路径（D2）**：按任务卡对 D2 逐字编码（键名字/成字字根/合体字），GB1 一致率仅 **91.66%**，量化并确认 D2 字形记法歧义（ADR-017：同一 PUA/通配字形 U+F001E/U+F0013 在不同字中代表不同字根；马/幺等字根被拆成多字形且不统一；少量条目残缺）。
- ⚠️ **对任务卡第 1 步的偏差（如实记录）**：任务卡原意“对 D2 逐字编码”，但 D2 拆字字形记法歧义过大（GB1 仅 ~92%，天花板约 94%，见 ADR-020），**不满足 ≥99% 验收**。故发布路径改用 **D3 第 2 列（MIT，干净拆字）作为字根来源**，D2 降级为交叉检查；识别码/结构/末笔仍为 D3 派生（PROVISIONAL，ADR-017/019）。**发布码表仍是本仓编码器逐字生成，不是直接拷贝 D3 码列**（ADR-016 不违背）。
- ⚠️ **字根表推导的循环性（如实记录）**：发布路径的字根表由 D3 编码多数表决推导，故“primary vs D3”的一致率本质是**规则自洽检验**（非独立）；**真正的独立校验是 rime（极点系，独立谱系）——GB1 100%、全体 98.77%**，满足 ADR-019“多 oracle 交叉验证”口径。
- 🔧 **顺带修正**：`encode_chengzi` 补全标准（1 笔=键+首笔+LL、2 笔=键+首笔+次笔、≥3 笔=键+首笔+次笔+末笔），修正 T-M1-02 的简化实现（原实现把 2 笔成字字根错误地编成 4 键）；见 ADR-020。
- ✅ `make verify` 全绿（fmt + clippy -D warnings + 21 测试 + deny + 隐私断言）。
