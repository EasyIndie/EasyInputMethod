## 1. 背景知识：五笔家族与常见形码

### 1.1 五笔字型是什么

**五笔字型**（王永民，1983 年）是**形码**输入法：把汉字拆成若干"**字根**"，字根分布在除 `Z` 外的 **25 个字母键**上；按字根的键位输入。它的取码规则（键名字、成字字根、合体字的"取大优先/兼顾直观/能连不交/能散不连"、末笔字型识别码）构成了一套确定性算法——这正是我们能**自己实现编码器**的原因。

### 1.2 三代五笔

| 版本 | 发布 | 特点 | 用户量 | 备注 |
|---|---|---|---|---|
| **五笔86**（王码86） | 1983 | 最经典，教程/词库/资料最多，**事实标准** | **绝大多数** | 个别字根分配不够合理；重码略多 |
| **五笔98**（王码98） | 1998 | 重新设计字根分配，更规范、重码更少 | 少 | 学习资料少 |
| **新世纪版**（王码新世纪） | 2008 | 取码规则更统一，支持大字符集（GB18030） | 很少 | 主要在部分教学场景 |

三者是**同一套思想**（拆字根 + 25 键），区别只在**字根表**和少量取码细节 → **同一个引擎就能支持，换数据即可**。

### 1.3 郑码（不是五笔的版本）

**郑码**由郑易里、郑珑设计，是**另一种独立的形码**：按"基本字根 + 笔画"组织，规则更系统，对**生僻字、繁体、古籍**支持好，专业排版/古籍数字化领域有人用。取码规则与五笔完全不同。

### 1.4 其它常见形码（了解即可）

| 方案 | 说明 |
|---|---|
| 仓颉 | 朱邦复设计，**繁体中文**主流（台/港） |
| 行列30 / 大易 / 呒虾米 | 台湾常见形码 |
| 小鹤音形 / 自然码 | **双拼 + 形码**混合方案 |
| 二笔 / 表形码 / 笔画 | 更简单的形码 |

### 1.5 对本项目的影响

- **`ime-table` 引擎只做通用的"码 → 候选"查询与排序，与具体方案无关。**
- **五笔家族（86/98/新世纪）共用同一套拆字/取码/词组规则**，字根表不同 → **自建流水线只需一套，多生成几份数据即可**。
- 郑码/仓颉规则不同 → 作为**可选数据包 + 可选规则模块**，Phase 1 不做。
- **Phase 1 只做五笔86**（用户基数最大）。98/新世纪是"再加一份数据"的工作量，不是重写代码。

> 顺带：我们自建的编码器会产出"字 → 字根拆分"，正好用于**字根提示**和**反查拆字**功能。

## 3. 许可证决策

### 3.1 你的诉求

- **好推广**（不是商业项目、纯个人爱好，不需要企业友好）；
- **防"劣币驱逐良币"**——不能被别人拿走代码、闭源包装、加广告后反过来把你挤掉。

这两个诉求指向的是**copyleft（著佐权）**，而不是宽松许可。

### 3.2 对比

| 许可 | 推广难度 | 防"闭源抄袭" | 企业采用意愿 | 说明 |
|---|---|---|---|---|
| MIT / BSD | 最低 | ❌ 完全允许闭源 fork | 最高 | 别人可拿走闭源、加广告，**正是"劣币"场景** |
| Apache-2.0 | 低 | ❌ | 高 | 含专利授权，但同样允许闭源 |
| MPL-2.0 | 中 | 🔶 文件级 | 中 | 改你的文件要开源，但可搭配闭源文件 |
| **GPL-3.0** | 低（开源社区内） | ✅ **强** | 低 | 任何分发都必须开源 |
| AGPL-3.0 | 中高 | ✅ 最强 | 极低 | 管到网络服务，桌面输入法用不上 |
| LGPL-3.0 | 中 | 🔶 | 中高 | 面向库，不适合应用 |

### 3.3 推荐：**GPL-3.0-or-later**

理由：

1. **精准实现"防劣币"**：任何人分发基于你代码的版本，**必须同样以 GPL 开源**——没法闭源包装后反过来打你；
2. **在开源社区里"最好推广"**：**开源桌面输入法的主流许可**——RIME 的各前端(`weasel`/`squirrel`)、`Trime`、`msime`、`ibus-table-wubi` 全是 GPL-3，社区接受度最高、没有门槛；
3. **不追求收入** ⇒ 不需要 Apache/MIT 的"企业可闭源"空间；
4. **额外好处（重要）**：切换到 GPL-3 后，**原本因许可被排除的资源重新可用**——`libpinyin`(GPL-3)、`rime/rime-wubi`(LGPL-3) 等都能合法使用（我们仍优先自建以求质量与可复现，但不再是法律雷区）。

### 3.4 配套（许可证不覆盖的部分）

- **名称 / Logo 保护**：许可证**不保护名字**。在 README 声明「项目名称与 Logo 保留权利，fork 版本请改名」，防止别人拿你的名声做劣币。将来可考虑注册商标。
- **贡献协议**：用 **DCO**（Developer Certificate of Origin，`Signed-off-by`）即可，简单、不设门槛；单人不追求商业双授权时无需 CLA。
- **保留版权与来源**：GPL 要求在分发时保留版权声明与许可副本；我们额外做 `NOTICE` / `docs/数据来源与许可.md`。
- **可复现构建 + 签名**：让"正版"和"被改过的版本"可区分，也是防劣币的一环。

> 如果日后改主意想让公司也能采用，最实际的折中是 **MPL-2.0**（文件级 copyleft）。但在"纯爱好 + 防抄"的前提下，GPL-3.0 是更干净的答案。

## 4. 配置示例（草稿，待你确认）

设计规则：**全中文注释、扁平、默认值合理、选项少、每个选项一句说明**。配置文件用 TOML（`config.toml`），码表用 TSV。

```toml
# ═══════════════════════════════════════════════
#  刺猬输入法 · 配置
#  改完保存 → 输入法菜单里点「重新加载」即可生效
#  以 # 开头的都是说明，看懂了随便改
# ═══════════════════════════════════════════════

# ── 输入模式 ──────────────────────────────
mode = "mixed"
# mixed  = 五笔优先，想不起码时自动用拼音兜底（推荐）
# wubi   = 只用五笔
# pinyin = 只用拼音

# ── 五笔 ─────────────────────────────────
[wubi]
auto_commit  = true        # 打满四码且只有一个候选时，直接上屏
z_key        = "wildcard"  # z 键的作用：wildcard=万能键 | none=关闭
show_radical = true        # 候选旁边显示字根拆解，方便学五笔
short_code   = true        # 启用一/二/三级简码

# ── 拼音兜底 ──────────────────────────────
[pinyin]
fuzzy          = false     # 模糊音（zh=z、ch=c、sh=s、n=l…），开了更宽松
show_in_mixed  = true      # 混输时把拼音候选排在五笔候选后面
max_in_mixed   = 3         # 混输时最多显示几个拼音候选
engine         = "inputx"  # 拼音引擎：inputx（默认）| native（自研，实验）

# ── 候选窗 ───────────────────────────────
[candidate]
count      = 7             # 每页显示几个候选（3–9）
page_up    = ","           # 上一页按键
page_down  = "."           # 下一页按键
font_size  = 16

# ── 外观 ─────────────────────────────────
[appearance]
theme = "auto"             # auto=跟随系统 | light=亮色 | dark=暗色

# ── 快捷键 ───────────────────────────────
[hotkey]
toggle_mode = "ctrl+shift+m"   # 循环切换 混合 → 五笔 → 拼音
```

**共 15 个选项**，一屏看完。你觉得：

- 选项数量要**再精简**还是**增加**（比如加"简繁切换""标点全半角""候选横排/竖排"）？
- 注释密度合适吗？
- 要不要**纯文本快捷配置**（如 `settings.txt` 只放 `mode=...` 这类键值对）给不想看注释的人？

## 附：本项目相关名词速查

| 名词 | 一句话解释 |
|---|---|
| 形码 | 按汉字形状拆解编码的输入法（五笔、郑码、仓颉…） |
| 音码 | 按读音编码（拼音、双拼） |
| 字根 | 构成汉字的基本部件，五笔把它们分配到 25 个键 |
| 键名字 | 每个键上的代表字，连按四次该键即可打出 |
| 成字字根 | 本身是字且在字根表中的字根，按"键名+首笔+次笔+末笔" |
| 末笔字型识别码 | 不足四码时补的两位：末笔笔画 + 字型结构（左右/上下/杂合） |
| 重码 | 同一个编码对应多个候选字 |
| 简码 | 只打一/二/三码就能出的高频字 |
| 词组码 | 多字词按规则取码（2字=各前2码；3字=1首2首3首3次；4字+=1首2首3首末首） |
| 混输 | 同一串输入同时用两种引擎解，合并候选 |
