# 交接提示词模板

> 按ADR-246/248/250固定dev迭代，main为受保护代码基线；模板不授权自动切源、清空真实数据或直接推main。四种场景各一份。状态值来自 `./scripts/handoff-status.sh`（只读采集，`--prompt` 会给骨架）；
> 流程与反例见 `.agents/skills/update-handoff/SKILL.md`。
> 注意：采集脚本当前`--prompt`骨架仍含旧main直推及最近ZIP推断，不应照抄；状态以HANDOFF和本模板为准，跨代理可直接用[本次专用提示词](交接提示词-2026-10-22-agent.md)。

## 填写要点

| 字段 | 从哪来 | 注意 |
|---|---|---|
| 包 SHA | 表格「已装包」+ 包目录 `.sha256` | 两份都要：zip 用于核对下载，执行 SHA 用于核对安装结果 |
| config | 表格「config」 | 明确写"有几个显式 `hotkey.*`"；保留用户值，默认值验收用隔离配置，不据此自动清真实数据 |
| 输入源 | 表格「输入源」 | 交接时如果不是 ABC，要说明是谁切的、要不要还原 |
| 遗留项 | HANDOFF §3 | 只挑与本次任务相关的，不要整段复制 |
| 步骤 | HANDOFF §4 | 可执行命令 + 可判定结果，禁止"验收一下输入"这种写法 |
| 边界 | HANDOFF §5 + 本次特殊性 | 重启前后分工、真实会话授权、只测一个包 |

## 反例

- ❌ "接着上次继续"：对方无法核对包、配置、输入源。
- ❌ 只给包名不给 SHA：装完才发现是旧包，白跑一轮验收。
- ❌ 不写还原点：测完留下 `mode=wubi`、输入源被切走。
- ❌ 把设计说明塞进提示词：提示词只回答"在哪、做什么、怎么判定"。
