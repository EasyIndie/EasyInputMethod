## 人工验证记录（2026-10-08）

### 已确认的结论

1. **必须是 `.app`，不能是 `.inputmethod`**：macOS 13 的 LaunchServices 无法扫描 `.inputmethod`（`lsregister -f` 报 `-10811`）；系统内所有输入法均为 `.app`。已改产 `Yinghuo.app`。
2. **macOS 只在登录/启动时扫描输入法**；`killall TextInputMenuAgent`、`launchctl kickstart`、删 `IntlDataCache`、`lsregister -f`、`TISRegisterInputSource` 均无法触发重扫。
3. **引擎侧无问题**：`tests/run-ffi-smoke.sh` 用真实数据实测 `wq→你`、`nihao→你好`。

### 未通过的：系统不枚举本输入法（无论签名方式）

同一台机器、同一目录、同一次登录对比（`tools/diagnose.sh` 输出）：

| 包 | 位置 | 签名 | 被系统枚举？ |
|---|---|---|---|
| `Yinghuo.app`（我们，ad-hoc） | `/Library/Input Methods/` 与 `~/Library/Input Methods/` | ad-hoc | ❌ |
| `Yinghuo.app`（我们，自签证书、已加入系统信任 codeSign） | `/Library/Input Methods/` | `Yinghuo Local Dev` | ❌ |
| `AinuTest.app`（**苹果原版 Ainu**，仅改 id） | `~/Library/Input Methods/` 与 `/Library/Input Methods/` | ad-hoc | ❌ |
| `SogouWBInput.app`（第三方，可用） | `/Library/Input Methods/` | **Developer ID**（Apple Root CA） | ✅ |

- `TISCreateInputSourceList` 共 282 源（含搜狗），**唯独没有我们**。
- `imklaunchagent` 每次启动都记：`TISFileInterrogator updateSystemInputSources false … cacheFormatVersion 0, magicCookie 0, inputSourceTableCountSys 0`。
- AMFI 对本机 ad-hoc / 自签二进制判定：`not valid: adhoc signed or signed by an unknown certificate chain`；自签证书加信任后仍如此（`local signing public key not initialized`）。
- 本机 `security find-identity -v -p codesigning` 为 **0 个有效身份**（无 Developer ID）。

### 结论与影响

- 现象的最可能解释：**macOS 要求第三方输入法用 Apple 签发的证书签名**（Developer ID / Apple Development），ad-hoc 与自签均不被 AMFI 接受。
  - 佐证：Sogou 是**后装的**且能出现 → 本机发现机制正常；差的只是“签名身份”。
  - AMFI 对 ad-hoc/自签二进制始终判定 `not valid: adhoc signed or signed by an unknown certificate chain`；自签加系统信任也无误。
- 与 `docs/技术方案.md` / ADR-010「Phase 1 不做签名」冲突 → **需决策**（SIG-1）。
- **代码交付物本身已完成并自测通过**；本卡的「人工装载+打字」验收**未完成**，如实记录。

   - **结论**：macOS 26/27 强制「Developer ID + hardened runtime + 公证」；Phase 1「不签名」前提不成立。

   - 补 `DT*` 键（`DTPlatformName`/`DTSDKName`/`DTXcode`…）；`LSMinimumSystemVersion` 10.13 → 13.0。
