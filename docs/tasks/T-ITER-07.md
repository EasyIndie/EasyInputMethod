# T-ITER-07：保存失败反馈与动作结果一致

- 状态：已完成（ADR-096；保存错误可见及失败快捷键消费）
- 模型建议：pro（涉及资源所有权、状态契约或跨层行为判断）
- 前置：IT-04 的动作解释约定
- 目标：用户能区分切换成功与持久化失败（P1，对应迭代计划 IT-07）
- 步骤：先 ADR 明确未匹配/成功/失败的动作结果和事件消费策略；用隔离只读/锁占用环境复现标点与简繁失败；统一快捷键、菜单与面板错误反馈，保留原状态。
- 验收：失败不假装切换成功；真实原因可见；无意外客户端输入、状态漂移或错误无限弹出；恢复可写后成功路径正常。 提交前 `make verify` 零诊断；涉及 Swift 跑 strict 宿主构建与隔离预览；脚本先在隔离用户环境覆盖成功/失败/中断，不先用真实数据试错。
- 铁律提醒：配置只走 ime-config；行为/协议变更先 ADR；核心零网络；一次一个改动，文档同步。
- 禁止：在真实配置上改权限制造失败；丢弃错误；混入跨控制器去重（另属IT-09）。
- 参考：[迭代计划](../迭代计划.md)、[审计009](../reviews/009-macos-product-engineering-audit.md)、根目录 AGENTS.md；配置行为另读配置架构.md与相关ADR。
