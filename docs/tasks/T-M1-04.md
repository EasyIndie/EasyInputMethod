# T-M1-04：拆字数据加载与交叉校验

- **状态**：待认领
- **模型建议**：flash（机械：下载/加载两份 MIT 拆字表、比对、输出差异报告）
- **前置**：无
- **目标**：加载两份 MIT"字→字根拆分"数据并做**逐字交叉校验**，产出差异清单。

## 数据源

1. `aardio/wubi-lex` 仓库 `sepllingData/86.txt`（MIT），格式：`字\t字根1字根2...`（每行一字）。
2. `huanfeng/WindInput` 仓库 `data/schemas/wubi86/wubi86_chaizi.txt`（MIT），格式待你下载后确认（可能同格式或带编码）。

> 用 `data/sources/fetch-wubi-chaizi.sh` 下载并记录 SHA-256（不要提交大文件，只提交脚本 + 校验和）。

## 步骤

1. 写 `data/sources/fetch-wubi-chaizi.sh`：下载上述两文件到 `data/sources/`（若文件较大，仅下载、不提交，提交脚本）。
2. 写一个**独立工具**（放 `tools/` 或 `crates/wubi-encoder` 的 example/bin，建议 `examples/crosscheck.rs`）：
   - 解析两份文件为 `HashMap<char, Vec<String>>`（字 → 字根序列，去重）；
   - 输出：
     - 交集大小、各自独有字数；
     - **分歧清单**：同一字、两份数据的字根序列不一致（最多打印 200 条 + 总数）；
     - 写到 `data/generated/chaizi-diff.txt`（可提交，作为人工裁定依据）。
3. 在 `docs/数据来源与许可.md` §1 登记这两份数据（D2/D3 已有条目，补 SHA-256 与下载脚本路径）。

## 验收

- `./data/sources/fetch-wubi-chaizi.sh` 可运行、校验和写入脚本；
- `cargo run -p wubi-encoder --example crosscheck`（路径以实际为准）产出差异文件；
- 差异清单已存在且大小合理（>0 行属正常）；
- `make verify` 全绿。

## 铁律提醒

- 数据必须登记许可 + SHA-256（AGENTS.md 铁律 4）；
- 只下载、不把大文件直接提交进仓库（除非确认要内置）。

- 不擅自"裁定"分歧（裁定属于 T-M1-05，pro 做）。
