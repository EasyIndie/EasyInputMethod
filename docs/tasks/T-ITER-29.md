# IT-29：混输自动提交的跨引擎歧义保护

- 状态：ADR-160工程修复完成；核心回归及默认码表Swift/C ABI通过，最终包原生待验。
- 优先级：P1核心输入，先于IT-26可达性优化，IT-24仍发布P0。
- 复现：现有默认词表、空临时学习词库、默认auto_commit开启；混输逐键wang第4键自动提交佢。纯拼音同码有王等候选，无自动提交；纯五笔wang的唯一提交是该模式现有约定。
- 原因：会话拿到五笔should_commit后未核对另一活动引擎的不同候选，单引擎唯一与混输可选目标冲突。
- 目标：用户还应能选择合法拼音，不让五笔域唯一抢提交；不引入模型/新配置/模式。
- 第一步：先ADR明确混输唯一作用域与不同来源/同文本去重/模糊或简拼候选的保护条件；不能偷偷改纯五笔唯一契约或把所有自动提交永久关掉。
- 验收：默认wang能选择王/佢，明确五笔输入仍可显式确认；纯五笔唯一、auto关闭、同文本去重、无拼音冲突、后续长拼音、取消/退格/数字/学习路径有回归。当前组合不得提前/重复上屏，真实默认最终包补验。
- 参考：[报告011](../reviews/011-core-completeness-and-scope.md)、结构化默认词表结果。先本地提交、功能完善后集中推送；UI暂缓。

- 本地结果：默认混输wang四键均不提交，佢第1、王第2；纯五笔wang仍唯一自动提交佢。无新配置/依赖，已装包不变。
