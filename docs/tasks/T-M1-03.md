## 先调研（本卡最关键的产出）

识别码 = **末笔笔画区 + 字型结构位**，需要每个字的两个信息：`末笔笔画`、`字型结构（左右/上下/杂合）`。

- 现有 MIT 拆字数据（`aardio/wubi-lex`、`huanfeng/WindInput` 的 `wubi86_chaizi.txt`）给出的是"字 → 字根序列"，**是否包含结构/末笔信息？**
- 请核对这两份数据的实际字段；若都没有，评估以下方案并选一个写进本卡结论：
  1. 从开放字形数据（如 Unicode IDS / CHISE）推导结构——但 IDS 结构 ≠ 五笔字型结构，可能不准；
  2. 交叉校验法：从多份公开码表反推"字→码"，与"字根序列编码"互相印证，不一致处人工裁定（**推荐，作为过渡**）；
  3. 手工维护一份常用字的结构表。

**结论要落到 `docs/数据来源与许可.md`（新增来源或标注风险），并更新本卡的"实现"部分。**

## 实现（基于上面结论）

合体字规则（标准，勿改）：

- ≥4 字根：取 第1、2、3、末 字根的键；
- 3 字根：第1、2、3 字根键 + 识别码；
- 2 字根：第1、2 字根键 + 识别码；
- 识别码键位表（横竖撇捺折 5 区 × 左右/上下/杂合 3 位）：
  - 横区(GFDSA)：左右=G 上下=F 杂合=D
  - 竖区(HJKLM)：左右=H 上下=J 杂合=K
  - 撇区(TREWQ)：左右=T 上下=R 杂合=E
  - 捺区(YUIOP)：左右=Y 上下=U 杂合=I
  - 折区(NBVCX)：左右=N 上下=B 杂合=V

公开 API（建议，可据结论微调并在 PR 说明）：

```rust
pub fn encode_hechengzi(radicals: &[String], structure: Structure, last_stroke: Stroke, table: &RadicalTable)
    -> Result<String, EncodeError>;
```
