# T-M1-03：合体字取码 + 末笔字型识别码（pro）

- **状态**：待认领
- **模型建议**：**pro**（五笔识别码规则 + 结构/末笔数据来源调研 + 与 oracle 全量对齐，易错）
- **前置**：T-M1-02（编码器基础）、T-M1-04（数据/oracle 就绪）
- **目标**：实现合体字取码与末笔字型识别码，并用第三方码表作 **oracle 全量验证**。

## 背景（T-M1-04 + ADR-016 已澄清）

- `huanfeng/WindInput` 的 `wubi86_chaizi.txt`（MIT，D3）**第 3 列给出 27,823 字的已验证五笔86 码**。
- 按 **ADR-016**：D3 **只作验证 oracle，不进入发布产物**；发布码表必须由本仓编码器生成。
- D3 **不直接给出**「末笔笔画」「字型结构」字段 → 仍需确定这两个输入的来源。

## 先调研（本卡最关键的判断）

识别码 = **末笔笔画区 + 字型结构位**，需要每字：`末笔笔画`、`字型结构（左右/上下/杂合）`。

评估并**选定**一种来源，写进本卡结论并登记 `docs/数据来源与许可.md`：

1. **独立来源**：从字形数据（Unicode IDS / CHISE 等）推导结构 —— 最符合"长期正确"（独立于 D3），但 IDS 结构 ≠ 五笔字型结构，需验证。
2. **派生数据**（可接受）：从 D3 反推「码末位 → (末笔, 结构)」，生成一份**自有**结构/末笔数据集（MIT 允许派生），再用**第二个独立来源抽样校对**，避免自证。
3. **人工维护**：只覆盖常用字，工作量大。

## 实现

合体字规则（标准，勿改）：

- ≥4 字根：第 1、2、3、末 字根键；
- 3 字根：第 1、2、3 字根键 + 识别码；
- 2 字根：第 1、2 字根键 + 识别码；
- 识别码键位（横竖撇捺折 5 区 × 左右/上下/杂合 3 位）：
  - 横区(GFDSA)：左右=G 上下=F 杂合=D
  - 竖区(HJKLM)：左右=H 上下=J 杂合=K
  - 撇区(TREWQ)：左右=T 上下=R 杂合=E
  - 捺区(YUIOP)：左右=Y 上下=U 杂合=I
  - 折区(NBVCX)：左右=N 上下=B 杂合=V

建议 API（可微调并说明）：

```rust
pub fn encode_hechengzi(radicals: &[String], structure: Structure, last_stroke: Stroke, table: &RadicalTable)
    -> Result<String, EncodeError>;
```

## 验收

- 与 **D3 oracle 全量对照**：产出一致率报告（写入 `data/generated/` 或 `docs/`）；
  - 目标：常用字（GB2312 一级 3755 字）一致率 **≥ 99%**；全体 ≥ 95%（不达标须说明）。
- 所有不一致项**逐条归因**（编码器 bug / 数据错 / 规则边界），结论归档。
- 数据来源已登记；**未把 D3 码表拷进发布产物**（ADR-016）。
- `cargo test -p wubi-encoder`、`make verify` 全绿。
