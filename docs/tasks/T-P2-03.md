# T-P2-03：用户反馈入口（GitHub Issues）

- **状态**：✅ 完成（2026-10-11；ADR-071）
- **模型建议**：pro（涉及隐私承诺边界与对外行为，需判断）
- **前置**：ADR-071（先写 ADR）、`docs/隐私与安全.md` §1/§6、`SECURITY.md`
- **目标**：给用户一个反馈问题/提建议的入口，且**不引入网络/遥测/账号**。

## 步骤

1. **入口**：输入法菜单新增「反馈问题与建议…」（紧邻「偏好设置…」）。
2. **渠道**：打开公开的 GitHub Issues 新建页（静态链接）；敏感漏洞提示走 `SECURITY.md` 的私密安全公告。
3. **App 不发送数据**：仅 `NSWorkspace.open(URL)` 交给系统浏览器；**不在 URL 预填**环境信息。
4. **诊断信息本地生成**：版本/构建/源码提交/macOS 版本/架构，展示并支持「复制诊断信息」；不含输入内容/词库/配置。
5. **测试**：预览冒烟断言链接为项目公开地址、诊断信息含版本/系统/架构。

## 验收

- 菜单入口可打开反馈面板；
- **App 自身零网络调用**（打开浏览器是用户主动动作）；
- 诊断信息**不含隐私**；`make verify` 全绿，`verify-no-network.sh` 通过。

## 铁律提醒

- 不联网/零遥测/不出设备/无账号（`隐私与安全.md` §1）；
- 不新增网络依赖；核心仍 `forbid(unsafe_code)`（本改动只在 Swift 宿主）。

## 禁止

- 自动上报/统计/崩溃上报；账号；URL 预填用户数据；后台静默外联。

## 参考

- `docs/决策记录.md` ADR-071、`docs/隐私与安全.md` §1/§6、`SECURITY.md`、`platforms/macos/Sources/Feedback.swift`。

## 修订（2026-10-11，ADR-073）

- **问题**：同步 `NSWorkspace.open(url)` 在主线程会卡死菜单（实测：关闭代理、GitHub 不可达时，点击后无反应，随后菜单全部失效）。
- **修复**：打开外部链接统一改为异步 `FeedbackUI.openExternally`，不阻塞主线程。
- **门控**：菜单入口仅在 `FeedbackUI.isAvailable`（纯本地 LaunchServices 判据）为真时显示。
