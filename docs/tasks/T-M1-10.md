# T-M1-10：`CodeTableEngine::convert` 去全表线性扫描（pro）

- **状态**：待认领
- **模型建议**：**pro**（排序/去重/截断语义 + `z` 通配边界，需判断）
- **前置**：ADR-060（数据结构决策）、T-M1-09（正式码表接入，已完成）
- **目标**：把 `convert` 热路径从 **O(全部条目) 全表扫描**改为 **二分精确 + 同前缀区间扫描**，`z` 通配走独立且**有上界**的分支；对外候选（顺序/去重/截断/`is_prefix`/自动上屏）与现有行为**逐条一致**。

## 背景

`CodeTableEngine::convert`（`crates/ime-table/src/lib.rs`）目前为统一支持 `z` 通配，遍历 `table.entries` **全部条目**判断 `code.starts_with(input)`。数据小（`wubi86-core.tsv` 30,384 码 / 37,828 条目，491,854 B）时够快，但按键延迟随条目数**线性上升**——违反 ADR-060 的"规模余量"要求。

## 步骤

1. 先跑基线：`cargo test -p ime-table`，记录现有测试（尤其 `bounded_top_k_preserves_best_candidates_for_prefix_and_wildcard`、`configured_wildcard_and_auto_commit_change_behavior`）全绿。
2. **非通配路径**（`input` 不含 `z`，或未开启 `z` 通配）：
   - 精确候选：`Table::exact(input)`（二分）；
   - 前缀候选：`Table::prefix(input, …)`（`partition_point` 定位同前缀区间）；
   - 用与现状**相同**的 rank `(code == input, entry.weight, Reverse(text), Reverse(code))` 做**有界 top-k**，保证排序与截断一致。
3. **`z` 通配路径**：保持扫描语义，但必须**有明确上界**（例如仅在匹配前缀的区间内、或对通配位做受控枚举），不得退化为无界全表；结果与现状一致。
4. 不改动：`max` 截断语义、`is_prefix = code.len() > input.len()`、自动上屏（仍走 `Table::exact` 且仅满码唯一）。
5. 新增回归测试：精确 + 前缀 + 重码 + `z` 通配 + top-k 截断，逐条断言；对同一输入比较"改前/改后"候选序列（可用固定小表快照）。

## 验收

- `cargo test -p ime-table` 全绿（含全部既有测试）；
- `make verify` 全绿；
- `ime-cli` / 独立预览样本不变：`wq→你`、`kwwl→中华人民共和国`、`nihao→你好`、`a` 有多页；
- `platforms/macos/tests/run-perf.sh` 引擎基准不劣化。

## 铁律提醒

- `ime-table` 必须 `#![forbid(unsafe_code)]`；不联网；不改 FFI 协议与对外行为（纯性能改动）。

## 禁止

- 不引入新依赖（尤其 `cedarwood`，见 ADR-060）；
- 不改 `Engine` trait 或候选排序**语义**；
- 不顺手重构 `ime-table` 其它无关部分。
