# T-M1-09：正式码表接入 ime-table / ime-cli（pro）

- **状态**：✅ 完成（2026-10-09 追认；交付格式为文本 TSV，不产出 `.imedict`，见 ADR-060）
- **模型建议**：**pro**（跨 crate 集成 + 体积预算取舍）
- **前置**：T-M1-05（单字表）、T-M1-06b（词组表 + 词频）、ADR-021（多候选）
- **目标**：用**真实自建码表**替换 M0 示例表，让 `ime-cli` 能用正式数据打字，并满足**体积预算**。

> **结果（追认）**：`ime-table::Table::from_tsv` 载入 `code\ttext\tweight`；`data/generated/wubi86-core.tsv` = **491,854 B ≤ 0.6 MB**；`ime-cli` 从数据文件加载并保留内置回退。**不产出 `.imedict`**（ADR-060：文本 TSV 为可审计真值，cedarwood/二进制/mmap 仅为带触发条件的可选优化）。

## 背景

- 码表由脚本生成：`data/sources/fetch-*.sh` 下载源数据 → `cargo run -p wubi-encoder --example generate`（单字）、`--example generate_phrases`（词组）。
- ⚠️ `data/generated/wubi86-phrases.tsv`（5.6 MB）**不入库**（可再生）；单字表 `wubi86-single.tsv`（约 313 KB）入库。
- 格式为**多候选**（ADR-021）：`code\ttext\tweight`，同码多行，按 `weight` 降序。

## 步骤

1. 在 `ime-table` 增加从 TSV（`code\ttext\tweight`）构建 `Table` 的加载器：
   - 解析错误处理（正常行 / 缺列 / 空行 / 非法权重）；解析器**单测**；
   - 同码多候选：保留全部，按 `weight` 降序。
2. `ime-cli` 改为从数据文件加载（路径由参数/环境变量传入，**不写死绝对路径**）；保留最小内置回退表（供无数据文件的 CI）。
3. **体积预算**：内置码表**总体 ≤ 0.6 MB**（`技术方案.md` §7.2）。全量词组表远超预算 → 需**裁剪**：
   - 单字：全保留（约 313 KB）；
   - 词组：按 `weight` 保留高频（选择规则要**写进文档**，例如按词频阈值/上限条数），使总产物体积 ≤ 0.6 MB；
   - 记录实际体积与裁剪规则到 `data/generated/` 报告或 `docs/`。
4. 更新单测：真实样本 `wq→你`、`kwwl→中华人民共和国`、`gggg` 等重码按词频降序。

## 验收

- `ime-cli` 用正式码表能打出验收样本（含词组）；
- 解析器单测覆盖：正常行、缺列、空行、非法权重；
- **打包体积 ≤ 0.6 MB**（记录实测值与裁剪规则）；
- `make verify` 全绿；
- 完成后 `ROADMAP.md` 的 P1-M1 全部勾选。

## 铁律提醒

- 解析器是"唯一不可信输入"入口 → 至少手工构造边界用例（`cargo fuzz` 目标可随后补）；
- `forbid(unsafe_code)`；不联网；数据许可登记（CC-BY-SA-4.0，ADR-014）。

## 禁止

- 不引入 `cedarwood`（仅带触发条件的可选优化，ADR-060；体积/规模触发后再立项）；
- 不在 `ime-core` 里写码表相关特判；
- 不把大型生成表（`wubi86-phrases.tsv`）提交进仓库。
