# 294 — 预览与正式包同源：数据清单、真实配置、学习区字根

日期：2026-11-16　设备：air（arm64 / macOS 27.2）
结论：预览与正式包**用同一份源数据**，但此前维护着两份复制清单（已合并为一份）；
预览改为复制真实 `config.toml` 到私有根，行为与已装包一致；候选框学习区字根已确认显示。

## 1. 起因（用户提问与现象）

1. 预览窗口和正式包是否用同一份数据？担心迭代中形成两套、维护成本升高。
2. 预览里发现「候选框学习区字根不显示」。

## 2. 数据同源性

- 两者都读同一份仓库数据：`data/generated/*`、`data/symbols.tsv`、`data/sources/wubi86-level3-codes.tsv`、
  `modules/keymap/data/key-roots-wubi86.tsv`。
- **但复制清单此前是两份**：`build.sh` 逐文件 `copy_data`，`dev-preview.sh` 另有一份 → 已经漂移
  （报告 293：预览漏了 key-roots，键位图没有字根/口诀）。
- 修复：新增 `platforms/macos/runtime-resources.txt` 作为**唯一清单**，`build.sh` 与 `dev-preview.sh`
  都按它复制；`test-runtime-resources.py` 断言清单文件存在、两条构建链都读清单、且不再出现逐文件复制列表。
- 实测：`B0-runtime.tsv` 在已装包 / 预览包 / 仓库三处 SHA-256 完全一致（`148f4168…`）；
  预览 Resources 现与清单一致（B0、码表、拼音、简码、符号、emoji、键位字根）。

## 3. 行为同源性：预览复制真实配置

隔离预览此前只用 Schema 默认值（私有根没有 `config.toml` 就按默认），而真实配置里
`candidate.show_wubi_learning = true`（用户显式开启）。于是同样的数据在预览里“学习区不出现”，
看起来像数据缺失。修复：`run-panel-interactive.py` 启动前把真实 `config.toml` **复制**到私有根
（0600、预览只读写私有副本，真实文件有 protected 断言），预览与已装包的偏好从此一致。

## 5. 差异与遗留

- 预览与正式包仍是**两个进程、两个数据目录**（预览私有根、正式 `Application Support`），
  但源数据与复制清单已同源；预览的练习/词库/配置都是私有副本，不污染真实数据。
- 预览主窗口改用 `WindowPlacement`（ADR-365），与正式自建窗口一致。
- 仍建议：改动数据文件或新增运行时资源时只改 `runtime-resources.txt`，由测试拦截第二份清单。
