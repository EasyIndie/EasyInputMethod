# 065 — 菜单“消失”是未激活假象；子菜单子项命令仍未生效

2026-10-18 凌晨，承接 064。重登后做干净会话验证：先由用户真实鼠标点击子菜单，再逐步隔离“菜单不呈现”的真实原因。结论有两条，且**推翻 063 与 064 的主判断**。

## 一、“产品菜单消失”是采集时未激活的假象

输入法菜单里的产品项由 `IMKInputController.menu()` 提供，而菜单只有在控制器被当前客户端**激活**后才会包含这些项。激活只需要在焦点客户端里产生一次按键。

实测（同一会话，正式包 `ed2a2ea…`）：

| 状态 | 菜单项数 | 产品项 |
|---|---|---|
| 重登后首读 | 23 | 齐全 |
| 切到搜狗拼音再切回 | 13 → 10 | 无，且“萤火虫”源项也不在 |
| 在 TextEdit 里按一次字母键 | **23** | 齐全 |

用同一手法复测候选 `df661d3`（换入后**先按键再读**）：菜单 **23 项**，`输入模式：五笔`（含子菜单）、四状态、设置、关于齐全。

因此：

- 063 的“候选产品菜单未呈现 → FAIL/INCONCLUSIVE”**正式作废**：那是采集脚本在替换后从未按键、读到系统通用输入菜单造成的。
- 064 的“热替换本身污染菜单”需要收窄：主因同样是未激活；“换回后仍 10 项”在另一些轮次里可以靠按键恢复。仍存在**另一种**真实退化——部分热替换后源项彻底消失、TIS 与实际菜单不一致，只能重登恢复（本会话末尾再次出现）。

## 二、真实鼠标点击子菜单子项，仍然不切换

干净会话、正式包（即“原方案”：父项自有 action + 自定义 view + 子菜单 + 三个独立 selector），由用户真实鼠标操作：

1. `mode=mixed`，点「输入模式：混输 → 五笔」：**仍 mixed**。
2. 为区分“没投递”和“投递了别的项”，用 ime-cli（`--config` 指向真实配置，走 `ime-config`）把 mode 临时设为 `wubi`，菜单刷新为「输入模式：五笔」；用户点「拼音」：**仍 wubi**。（配置已按字节还原：`65643c64…`。）
3. 对照：AXPress 顶层「关于」→ 关于窗口正常打开；AXPress 子项返回 0 但无效果。

结论：**顶层菜单命令的投递链路正常，子菜单子项的点击不产生模式变化**。两种解释目前无法区分——(a) 子项命令根本没有被投递；(b) 系统投递的是“当前勾选的那个子项”，所以看起来永远不变化。两者对 mode 的观测完全相同，需要带日志的候选才能分辨。

这也解释了历史上 v2/v3 的 `tag=6`：当时 mode 正是 mixed，勾选项也是 mixed，符合解释 (b)。

## 三、方法修正

1. 任何菜单采集前，必须先在焦点客户端里按键一次激活控制器；否则读到的是系统通用菜单。
2. 热替换恢复后，若源项消失且 TIS 与实际菜单不一致，只能重登；不要在该状态下继续判定。
3. 子菜单类结论必须有“顶层阳性对照”（如关于）和“勾选项≠目标项”的状态设计，否则 (a)(b) 不可分辨。
