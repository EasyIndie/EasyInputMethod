# 报告 301：同形字根辨识短语 + 未达标提示（ADR-374）

日期：2026-11-18 / pi（air）· 分支：`dev`

## 1. 真机反馈

1. 字根题里「口」（K）与「囗」（L，方框）几乎一模一样，看不出区别（截图 16.36 / 16.38）。
2. 阶段题都练满（进度 100%）但没有反馈。

## 2. 根因

1. 两道题的题干是 `questionLabel.text = question.char`，字形本身在常见字体里同形；题目因此**无解**。
2. 进度行的提示只在"下一阶段尚未解锁"时才写门槛；用户下一阶段早已解锁（`attempts > 0`），
   正确率 86% 又没达标 → 横幅不显示、门槛也不显示 → 界面上没有任何下一步信息。

## 3. 改动

| 位置 | 改动 |
|---|---|
| `RootNotes.swift`（新增） | 混淆字根的辨识短语 + 例字：口（嘴巴，吃/吗）、囗（包围外框，国/园）、曰、日、目、且、罒、田、甲、由、冂、凵、匚、己、巳 |
| `PracticeWindow.applyQuestionChrome()` | 字根题题干上方写「字根 · 囗（包围外框，如「国」「园」）」；无短语时仍是「字根」 |
| `PracticeWindow.updateStats()` | 未达标时始终写差什么：字数不够 → 「还需练 N 字（X/30）且正确率 ≥90%（当前 Z%）」；字数够但正确率不够 → 「正确率需 ≥90%（当前 Z%），再答对几题就能达标」 |
| `renderForTesting` | 改用 `updateStats()`，离屏实拍与真实窗口的进度行一致 |
| 测试 | 新增 `RootNotes` 与"正确率不够"两组断言；离屏测试的 Swift 源清单补 `RootNotes.swift` |

## 5. 待真机复验

- 遇到「口」：上行应写「字根 · 口（嘴巴，如「吃」「吗」）」；遇到「囗」：写「字根 · 囗（包围外框，如「国」「园」）」。
- 正确率不足时，进度行明确写出"正确率需 ≥90%（当前 Z%）"。
