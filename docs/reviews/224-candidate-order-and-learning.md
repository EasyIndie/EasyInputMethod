# 224 候选顺序与"个人化不跟手"的现状诊断

> 用户反馈（2026-11-03，日常主力五笔、混合输入模式）：**单字候选排序不跟手，常用字总排在其它位置，
> 有时直接打错、有时要数编号；两字词同样有问题。** 希望评估现状与业界做法，减少反复修改带来的效率损失。
>
> 本报告只做诊断与方案取舍，**不改代码**（IT-23 试用期换包即作废，见 ADR-298）。

## 1. 现状：四层机制里，只有"静态词频"在真正起作用

| 机制 | 实现 | 实测效果 |
|---|---|---|
| 简码层（一级 25 / 二级 625 / 三级） | **未实现**。`data/generated/wubi86-single.tsv` 里码长 ≤ 2 的行数 = **0**，全码表只含 3–4 码 | 单字母/双字母输入退化为"前缀匹配 + 整字词频排序" |
| 静态词频 | `weight` = jieba 词频（单字最大 883 634；词组中位 3） | 决定几乎全部顺序 |
| 单字个人化 | `crates/ime-core/src/lib.rs:343-347`：**单字 `bonus = 0`**（有测试 `wubi_single_order_ignores_learning_but_phrases_have_bounded_bonus` 钉住） | **学不动**：反复选同一个字也不会前移 |
| 词个人化 | 同上：`learned.min(32)` | 每次选择计数 +1，收益上限 32 |
| 用户自造词 | `crates/ime-ffi/src/session.rs:145-155`：`Candidate::new(text, code, **0**, …)` | 权重 0，只能靠 ≤32 的学习分竞争静态权重（可达 88 万） |

### 1.1 最严重的一条：一级简码基本"不存在"

五笔 25 个一级简码是肌肉记忆的核心（`g一 f地 d在 … q我 w人`）。实测用真实码表，按"该键前缀组按 jieba 词频降序"取首选：

```
25 个一级简码中，能靠前缀+词频排到第一的：8 / 25
q → 多 外 名      （「我」全码 trnt，根本不在 q 前缀组）
w → 他 人 你
a → 或 其 区
v → 她 那 好
i → 小 没 当
```

用户按习惯打 `q` + 空格，得到的是「多」。这既是"常用字总排在其它位置"，也是"有时候会打错"的直接来源——**不是词频调不动，而是简码这一层根本没有**。

### 1.2 单字：学习被硬编码为 0

`bonus = if 多字 { learned.min(32) } else { 0 }`。所以 `aaaa`（工 3771 / 㠭 1）这种组，用户选一百次「㠭」也不会前移一位。

### 1.3 就算打开单字学习，32 也太小

统计 4 351 个单字同码组：**第 1 与第 2 的权重差中位数 24，其中 47.3% 的组差值 > 32**。
即使用 32 的上限去竞争，也有一半的组翻不过去。词组层稍好（83% 的词组权重 ≤ 32），但每选一次只 +1，要连选十来次才见效——这就是"不跟手"。

### 1.4 缺的东西

无时间衰减（一次早年的误选会永久粘住）、无 MRU（最近用过的不前移）、无位置记忆（上次在第 3 位，下次还在第 3 位而不是记住你偏好第 3 位）、无上下文。

## 2. 业界怎么做（两类哲学）

### 2.1 拼音/整句系（搜狗、微信、macOS 拼音、Gboard）

- **上下文语言模型**打分，个人化作用在 LM 层而不是"单候选权重加常数"；
- 个性化 = n-gram 计数 + **时间衰减**（常见半衰期 7–30 天）+ 最近使用短窗增强；
- 用户自造词单独池，命中码则优先，可管理删除；
- 纠错/模糊音与排序解耦。

本项目明确不做 LM 与大词库（非目标），这部分只借鉴"衰减 + MRU + 用户词优先"三个低成本机制。

### 2.2 五笔系（极点、RIME/小狼毫、搜狗五笔、QQ 五笔）

共同点是**位置稳定优先于自适应**：

1. **结构性分层**：键名/成字根 → 一级简码 → 二级简码 → 三级 → 全码，逐层在前；简码由**规则表**决定，不参与词频竞争。这是"常用字位置稳定"的根本。
2. **词频调序是可选且保守的**：多数提供"智能调序/固定顺序"开关；RIME 系默认不调频；保守实现只做"选过的候选前移一位"，不动首位。
3. **首选位保护**：不轻易把用户熟悉的首选挤走，除非有明确的重复证据（常见做法：连续 2–3 次、甚至 5 次选择同一非首选才升位）。
4. **误选不学习**：单次误选（选完立刻删除/撤销、或紧接着又选别的）不计入，避免"一次手抖永久改序"。
5. **位置记忆**：记住 `(码 → 上次选的序号)`，下次同码把该项放回原位，而不是整体位移。

## 3. 建议方案（按收益/风险排序，均待 v1.0.0 发布后实施）

| 阶段 | 内容 | 收益 | 风险/成本 |
|---|---|---|---|
| **P0** | **补简码层**：一级 25 / 二级 625 作为独立层排在同类全码候选之前；三级按规则 | 直接消灭"打 `q` 出「多」"这类打错；把"位置稳定"从词频手里拿回来 | 需一张简码表（公开标准事实，须按 `data/sources.toml` 登记来源与 SHA）；新增 1 层排序，不改 ABI |
| **P1** | **个人化刻度修正**：单字也参与；上限改为"组内权重差的分位"而非固定 32；换算成可解释的排序位次 | 让"选过就前移"真的生效 | 改 `personalize` 语义与既有测试；需回归候选稳定性 |
| **P2** | **保守调序**：首选位保护（连续 ≥2 次才动）、误选不学习、时间衰减（半衰期）、MRU 短窗 | 减少"越用越乱" | 需在 `ime-dict` 存时间戳或有界窗口，注意 2 MB/1 万条上限 |
| **P3** | **位置记忆 / 固定顺序开关** | 五笔老手的"跟手"感 | 新增配置项，按项目铁律要论证必要性（倾向不加，先用 P0–P2） |

### 3.1 评估方法（不做就没有"更丝滑"的证据）

建 150–200 条个人高频样本（单字 50 / 两字词 50 / 混排长句 50），度量：平均按键数、翻页次数、非首选选择率、错字率。改动前后在同一包上跑同一批样本，写入 schema 2 报告。没有这个基线，"变好了"无法验证。
