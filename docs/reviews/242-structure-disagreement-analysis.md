# 242 — 13% 结构不一致：能不能解决？能，而且它不是 partial 的真病因

- 日期：2026-11-06　｜　数据来自临时下载（`ids_lv1.txt`，`sha256 aa9ba7e394d8fd5cf797…`），**未入库**
- 关联：报告 240/241、`docs/research/corpus-data-sources.md`（数据来源调研）

## 1. 结论先说

| 问题 | 答案 |
|---|---|
| 66/512 的"结构不一致"是数据错误吗？ | **不是**。是两套分类口径差异（五笔把独体字/部分拆法判成"杂合"，IDS 按字形上下/左右切开） |
| 需要"修"吗？ | **不需要修数据，需要定口径**：五笔识别码字母是结构权威（它就是编码时的判据），IDS 只作交叉校验；不一致样本按类别归档 |
| 它挡住了 corpus 吗？ | **没有**。partial 的真病因是**组件数与码长对不上**，与结构无关 |

## 2. 66 条不一致长什么样（可归类）

| 类别 | 数量 | 例子 | 原因 |
|---|---|---|---|
| IDS `⿱`（上下）但五笔判**杂合** | 17 | 下 `ghi`、正 `ghd`、天 `gdi`、自 `thd`、开 `gak` | 五笔把这些当**独体字**（独体 = 杂合），IDS 按字形上下切 |
| IDS `⿱` 但五笔判**左右** | 10 | 我 `trnt`（丿扌丶）、跟 `khve` | 五笔拆法与 IDS 的分解根不同，根算子随之不同 |
| IDS `⿰` 但五笔判**上下** | 10 | 像 `wqje`、死 `gqxb` | 同上（五笔按字根顺序，不按视觉包围） |
| IDS `⿰` 但五笔判**杂合** | 10 | 非 `djdd`、成 `dnnt` | 五笔把镶嵌/包围判为杂合 |
| 包围类（`⿸⿵⿺⿻`） | 8 | 事 `gkvh`、书 `nnhy`、越 `fhat` | 五笔对包围的判定与 IDS 的"外层包内层"不同 |

**验证**：这 66 条**全部**满足"组件数 + 1 = 码长"（0 条例外），说明它们的识别码推导自洽，
不一致纯粹来自结构命名，不是我们算错。

## 3. partial 的真病因（239 条，已分类）

| 类别 | 数量 | 例子 | 需要的修复 |
|---|---|---|---|
| **A** 保留 PUA 占位即可自洽 | **54** | 在 `dhfd`、用 `etnh`、一 `ggll` | 把 BMP 私有区字形当作**占位组件**（不丢弃），并用"第 i 个组件 ↔ 第 i 个码字母"推断它的键位。**不需要新数据** |
| **B** 单组件（缺笔画） | **52** | 于 `gfk`、才 `fte`、走 `fhu`、见 `mqb` | 需要**字根笔画序列**（自编约 130 条 / D18），或这些独体字的笔画数据 |
| **D** 组件数少于码长（D2 漏拆） | **133** | 是 `jghu`、年 `rhfk`、以 `nywy`、被 `puhc` | 需要更完整的拆字源，或**约束求解**：用"字根→键"反推合法拆法（见 §4） |

## 4. 一个可行的"不引入新数据"的解法（针对 D 类）

思路：**码本身就是约束**。若一个字的字根序列对应的键序列 = 码（去掉末尾识别码），那这个拆法就是自洽的。
用现有 D14「字根→键」表 + D2/D3 字根池，可以做"码驱动"的拆法搜索。

实测（对 partial 里键可映射的 176 条）：

- 已知组件的键序列是**码的子序列**：**173 / 176**。

也就是说，绝大多数 partial 的已知组件与码顺序一致，只是**缺了若干个组件**（D2 漏拆或 PUA 未解）。
这为"按码补齐"提供了强证据，值得下一步做一个原型（`--solve` 模式）：
枚举缺失组件数、在对应键的字根集合里找候选、用 D2/D3 的分布排序、只接受唯一解。

## 5. 建议的处置

1. **口径先定死**（写进 spec / ADR-309 追加条款）：
   - 五笔结构以**识别码字母**为准；IDS 仅作交叉校验（87.1% 一致即为合格）；
   - 不一致的 66 条按 §2 归档，不强行统一，也不用来改数据。
2. **A 类 54 条**：schema v3 允许"键位已知、字形未知"的占位组件（`components` 里标 `{"key": "d"}`），
   解释写成"字根（d 键，字形待识别）"。这能把 full 从 753 提到约 **807**。
3. **B 类 52 条**：并入 ADR-309 的"自编字根笔画"（D18），顺带解决成字字根首/次/末笔。
4. **D 类 133 条**：先做"码驱动拆法搜索"原型；即使只解一半，full 也能到 ~870。
5. IDS 仍然值得引入——但用途是**校验结构**与**给搜索提供候选分量**，不是当作拆字真值。
