## 1. 为什么先做这件事

「打单字不跟手」是主观描述。ADR-304（简码入表 + 位次上移）要发布，就必须能回答两个问题：
**改之前是多少、改之后是多少**，且这个数字在别人机器上能一秒复现。所以先造尺子，再动刀。

## 2. 尺子怎么做

| 组成 | 位置 | 说明 |
|---|---|---|
| 样本集 | `tools/eval/samples.tsv`（200 条） | 由 `gen-samples.py` 从仓库内已登记数据派生，可复现 |
| 评测器 | `crates/ime-cli/src/bin/ime-eval.rs` | 直接驱动真实 `Session` + 真实码表，不模拟、不桩 |
| 一键入口 | `make eval-candidates` | 纯本地；输出表格 + JSON |
| 基线 | `tools/eval/baselines/1.0.2-build37.json` | 绑定提交号、样本 SHA、码表 SHA |

**关键设计：意图来源与排序权重不同源。** 单字意图取 `pinyin-chars.tsv` 的 jieba 词频（D10），
码表排序用的是 WindInput 权重（D3）。若两者同源，"首选率 100%"只是自证——第一版正是这样写错的，
看到 50 条单字全中首选才发现，已改为跨源取。

## 4. 结论与对 1.1.0 的约束

1. **同码内排序已经不是瓶颈**：`single` / `word2` 命中且首选；`word34` 87% 首选。
   这与报告 224「单字 bonus=0 是问题」的判断**部分冲突**——bonus 只在"用户已经学过该词"时才起作用，
   基础排序本身是健康的。
2. **缺口集中在一级简码**：`jianma1` 只有 32% 首选、44% 连候选列表里都找不到（用户得改打全码）。
   这正是 ADR-304 的 P0。
3. `sentence` 的 70.6% 是**数据覆盖**问题（码表没有这些词），不是排序问题；1.1.0 只要求不劣化。
4. 于是 1.1.0 的判定线写死为：`jianma1.first%` 与 `jianma1.keys/sample` 必须明显改善，
   其余类别 `hit% / first% / keys` 不得劣化；`sentence` 单独看，不达标不阻塞。

## 5. 未做 / 已知限制

- 未模拟**学习曲线**（`personalize` 需要真实选择序列，基线与对照都用冷启动引擎）。
  ADR-304 P1 的位次上移收益要靠单测 + 装机手感确认，本尺子只保证"静态排序不劣化"。
- 未建模分词歧义（长句按码表贪心切词；用户的实际切法与它不同）。
- 样本集一旦入库即为考卷，改动须在报告里说明理由。
