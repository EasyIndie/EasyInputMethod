## 1. 这次改了什么（两处，同属"候选顺序"一个行为面）

### 1.1 P0：一级简码入表（数据 + 生成器）

| 项 | 内容 |
|---|---|
| 数据 | `data/sources/wubi86-level1-codes.tsv`（**D17**，项目自建清单，CC-BY-SA-4.0，25 条） |
| 生成 | `generate_core.rs` 追加 25 行：`code = 键位`、`text = 字`、`weight = 该字在全码表里的权重` |
| 校验 | `tools/check-level1-codes.py`：25 条 / 键位唯一 / 字唯一 / 全码一致 / 生成结果含 25 条 / 核心表 ≤2 码行数 = 25 |
| 核心 | **零改动**——靠既有 `Rank = (code == input, weight, …)` 的"精确优先于补全" |
| 自动上屏 | **未改**：仍要求输入长度 = 4，简码必须空格或数字确认（五笔习惯） |

### 1.2 P1：`personalize` 改"有界位次上移"

- 删掉 `bonus = learned.min(32)`（多字）与 `bonus = 0`（单字）两条分支：学习不再叠加到静态权重上。
- 新规则：先按静态权重排序 → 学过的候选按固定步数上移（≥1 次 1 位、≥4 次 2 位）。
- **首选位保护**：最多升到第 2 位，永不挤掉当前首选。这比 ADR 原文更保守——首选位是老手肌肉记忆的锚点，
  报告 224 §2.2 的业界做法（五笔系"首选位保护"）也这么要求。
- **不跨分块**：精确 / 补全 / 模糊三类各自成块，上移不得跨块，否则"学过的补全候选"会压到精确命中前面，
  破坏 `is_prefix` 的硬约束（该约束由 `exact_wubi_precedes_high_frequency_completion_on_every_path` 守着）。

| 类别 | 命中率 | 首选率 | 平均位次 | 按键/条 |

| jianma2（二级规则 30） | 100% → 100% | 93.3% → 93.3% | 0.07 → 0.07 | 3.07 → 3.07 |

| word2 / word2v / word34 | 不变 | 不变 | 不变 | 不变 |
| sentence（17） | 70.6% → 70.6% | 70.6% → 70.6% | 0.00 → 0.00 | 11.00 → 11.00 |

结论：**只动该动的那一格，其余零劣化**。`jianma1` 的 14 条未命中（用户得改打全码）全部变成一键首选。
