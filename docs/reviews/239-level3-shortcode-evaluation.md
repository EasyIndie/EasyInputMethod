# 239 — 三级简码评估：按键收益有限，建议暂缓

- 日期：2026-11-06　｜　工具：`tools/eval/simulate-level3.py`、样本类 `jianma3`
- 关联：报告 238（二级简码落地）、`docs/research/wubi-schemes-and-learning-loop.md` §4.5（L1）

## 1. 问题

二级简码落地后（报告 238），按研究文档 §4.5 的顺序该评估三级简码（约 4,400 字）。
先要说清一个容易混淆的事实：**三级简码是"表"不是"规则"**——不是任何四码字都能 3 码上屏，
只有官方表指定的字可以。所以本轮做的是**上限估计**：假设高频前 4,400 个四码字都能 3 码 + 空格上屏。

## 2. 做法

1. 从码表取全部四码单字，按 jieba 字频降序取前 4,400 个，为每个字生成一条 3 码行（全码前 3 码）→ 模拟表；
2. 样本新增 `jianma3` 类（40 条）：高频四码字，**只打全码前 3 码**；
3. 用同一批 280 条样本跑基线（当前表）与模拟表，比较 `jianma3` / `single` / `jianma2` / `prefix2` / `ALL`；
4. 统计代价：与既有 3 码全码字（如 式=aad）撞码的数量、表体积增量、真正能省键的字占比。

## 3. 结果

| 项 | 值 |
|---|---|
| 模拟条目 | 4,400 |
| 与既有 3 码全码字**撞码** | **582**（13.2%） |
| 其中**真正能省 1 键**的（四码重码字） | **1,568（35.6%）** |
| 表体积增加 | **+52.8 KB** |

| 类别 | 基线（命中/首选/位次/按键） | 加三级简码后 |
|---|---|---|
| **jianma3**（40 条，只打 3 码） | 100.0 / **75.0** / 0.35 / **4.25** | 100.0 / **97.5** / 0.03 / **4.03** |
| jianma2（二级简码） | 100 / 100 / 0.00 / 3.00 | 不变（零干扰） |
| single（四码字打满 4 码） | 100 / 100 / 0.00 / 4.46 | 不变（零干扰） |
| prefix2 / 词 / 句 | — | 不变 |

## 4. 怎么读这组数字

- **按键收益很小**：`jianma3` 的按键只从 **4.25 → 4.03**（−0.22）。原因是四码字里 **64% 本来就唯一码**
  （4 码直接自动上屏 = 4 键），改成 3 码 + 空格还是 4 键 —— **省不到键**。
  真正省 1 键的只有四码重码的 35.6%。
- **首选率提升是真的**（75.0% → 97.5%）：3 码时不再需要在候选里挑，但代价是——它跟"记住第 4 码（识别码）"
  这件事无关，后者才是三级简码在传统教学里的价值（**少记一个码**），而这一项没有按键指标可量。
- **代价不小**：+4,400 行 / 53 KB；**582 处与既有 3 码全码字撞码**（需要按权重定序，且会改变这些 3 码字的候选顺序）；
  还要一张官方三级简码表（数据来源与许可问题同 D17-bis）。

## 5. 结论与建议

**暂缓三级简码**，理由：

1. ROI 明显低于二级简码（二级：首选 32.5%→100%、键 3.58→3.00；三级：首选 +22.5pp、键 −0.22）；
2. 它的真实价值在"少记识别码"，属于**教学/提示**要解决的问题——用结构事实库给"这个字的识别码为什么是这个"
   比塞 4,400 条简码更对症，而且不动候选排序、不增撞码；
3. 数据侧还要一张官方表（许可与对照成本同 D17-bis）。

**触发条件**（任一满足再立项）：
- 结构事实库 B0 上线后，用户反馈仍集中在"记不住识别码/第 4 码"；
- 或拿到可许可的官方三级简码表，且愿意接受 582 处撞码的顺序调整。
