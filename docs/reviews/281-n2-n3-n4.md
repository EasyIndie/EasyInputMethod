## 2. 数据来源与许可

- **D18**（项目自编，CC-BY-SA-4.0）：
  - `data/learning/wubi86-root-strokes.tsv`：56 个 B0 成字字根 + 5 个基本笔画的书写笔顺；
  - `data/learning/wubi86-complete-decomp.tsv`：8 个 D2 漏拆字的完整拆字。
- **笔数校验**：Unicode Unihan `kTotalStrokes`（Unicode License V3，构建期临时下载、不入库）；
  只校验**笔数**，不把 Unihan 当笔顺顺序来源。
- **明确不采用**：Arphic / Make Me a Hanzi / hanzi-writer-data / KanjiVG 的字形或路径数据
  （前两者许可与 GPL-3 不兼容；KanjiVG 简体覆盖不足）。
- **N3 结构**：不引入新来源。识别码存在时用识别码结构；否则用 D19 `idsStructure`（MIT）；
  两者不一致只记 `structureConflict`，不硬改。

## 3. N2 真实笔顺

- 56 个 B0 成字字根全部有 D18 序列，`strokesKind=writing`、`strokesSource=D18`；
- 笔画用 `一丨丿丶乙` 五类；`count` 与序列长度一致，并已逐条对照 Unihan `kTotalStrokes`（56/56 一致）；
- 示例：`五` = 一丨乙一（4）、`古` = 一丨丨乙一（5）、`母` = 乙乙丶一丶（5）、`雨` = 一丨乙丨丶丶丶丶（8）；
- B0 里不再把全码反推的「取码笔顺」当真实笔顺：`strokesKind=code` 的条目会明确标注。

## 4. N3 五笔结构

- B0 3,000 字中 **2,766 条**有 `structure`：识别码来源 1,525，IDS 来源 1,241；
- 识别码来源的 `structure` 与 `recognition.structure` 完全一致；
- 识别码与 IDS 结构不一致 **146 条**，只记 `structureConflict=true`，按口径差异归档（报告 242）；
- 例：`年` 识别码为杂合（末笔竖+杂合 ⇒ K），IDS 判上下 → 冲突记录，不改识别码；
- 剩余 234 条无结构：主要是 `unknown`（缺码/缺拆字）与少数无 IDS 的字。
