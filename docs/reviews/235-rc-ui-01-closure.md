# 235 — RC-UI-01 结案：换方案落地，不再是待办

- 日期：2026-11-06　｜　决策：用户裁定「按 A 关掉」　｜　关联：ADR-202 / ADR-205 / **ADR-206**、报告 048/055/061/064/067/071/074/217/234

## 1. 这张卡原来要什么

2026-10-17 的 UI 任务卡，五项：

1. 系统输入法菜单里「输入模式：当前模式」这行**右侧状态右对齐**；
2. 在系统菜单里**切换 混输/五笔/拼音**；
3. 关于窗口的标题与按钮布局；
4. 「复制诊断信息」的提示修正；
5. 以上都必须在**正式签名包的 IMK 系统菜单**上留痕（不能只用离屏预览）。

## 2. 为什么长期挂着

| 日期 | 方案 | 结果 |
|---|---|---|
| 10-17 | ADR-202：一级可点击循环 + 二级子菜单 | B 机真实点击二级项**收不到命令**（控制器无 CMD/APPLY） |
| 10-17 | ADR-205：一级仅展开 + 标准二级显式选择 | 换成系统原生展开仍失败；报告 063 的判定后来被报告 064 撤回（热替换污染了菜单） |
| 10-18 | **报告 067 + ADR-206** | 带日志诊断包证明：**IMK 输入菜单只投递顶层项命令，子菜单子项点击不产生任何命令** —— 系统行为，不是实现缺陷 |

## 3. 实际交付形态（ADR-206）

- 菜单恢复**单行**「输入模式：当前模式」，**可点击循环** mixed → wubi → pinyin；
- 行内左标题 + 右状态由自定义 view 绘制（右对齐要求满足）；
- **取消子菜单**与三个二级模式项；模式三选一保留在**设置页**与 `⌥M` 快捷键；
- 中文/半角/简体/标点四项状态、设置、关于仍在同一菜单（正式包实测 7 行）。

## 5. 结论与边界

- **结案**：卡片要求的能力以 ADR-206 的形态交付并被后续两代正式包验证；
  继续按原措辞保留会让人误以为"系统菜单里还有未修的 UI 缺陷"。
- **边界**：放弃"在系统菜单里直接三选一"，这是 ADR-206 明确记录的取舍（换来菜单风格统一与可用性）；
  若将来仍想在系统菜单里三选一，需要新证据 + 新 ADR，不能重开这张卡。
