# 011：核心输入完整性、业界对照与待办收敛

2026-10-14。范围：源码/当前任务/官方资料＋隔离默认配置下的无界面FFI固定样例。未改产品代码、安装包或真实配置/词库；不把竞品功能表当实现清单。

## 1. 结论

核心骨架基本齐全：五笔86、默认混输、轻量拼音、选词/分页/取消/退格、模式/标点/字形切换、本地学习与最小词库纠错已有实现。当前应补的是“目标能容易找到、基本拼写能被正确解析、状态/隐私不出错”的闭环，而不是再做更多输入方案或大型语言模型。

新增值得优先处理：混输跨引擎自动提交歧义、短码拼音可达性、拼音隔音符、冷启动多音字排序质量。特殊按键/受保护字段缺少针对性证据，应作为验收缺口，不能先宣称有故障或泄漏。

建议保持15个既有配置，当前功能阶段不因竞品选项增多而增配；UI学习区两项拟配置仍随NEXT-UI暂缓。本地提交先保留，功能完善后集中推送的安排不变。

## 4. 新增固定样例结果

源码本地修复f90010b，使用现有生成词表；默认Schema配置在全新/private/tmp目录，空本地学习词库，9项/页。FFI会话无IMK、无桌面按键；每个输入新会话，候选去重与翻页后取得总排名。临时配置删除，探针无真实输入记录。

| 模式／输入 | 结果 | 含义 |
|---|---|---|
| 混输wang | 第4键提交佢；纯拼音wang为王等候选、不自动提交 | 五笔域唯一不等于混输域唯一，需保守处理冲突 |
| 混输ni | 你第20，首个拼音第20（第3页） | 兜底存在但不够直接 |
| 混输wo | 我第16（第2页） | 同类可达性问题 |
| 混输yu | 与第74（第9页） | 已有大量五笔补全压前，不是词表缺“与” |
| 混输shi/hao | 首个拼音分别第5/7 | 不应一刀切重排所有情况 |
| 混输nihao | 首项你好 | 长于五笔码长的常用全拼路径已有 |
| 纯拼音xian | 见、省、先等；无西安 | 单音节优先导致歧义词不可直接找到；合法多音字权重需区分常用度 |
| 纯拼音xi'an | apostrophe返回Committed（西‘），后续an继续新组合；无西安 | 默认中文标点处理抢占隔音符，不应按标点中途提交 |
| 纯拼音xa | 西安首项 | 词库已有西安，不是单纯扩词库能解决 |

| 纯拼音jsj/jisuanji | 计算机首项 | 全拼和全简拼已有 |

## 5. 待办重新排序

### 当前必须收敛

1. **IT-24/P0**：新签名包组合导航复验，旧包风险不能因新方案暂缓而关闭。
2. **IT-29/P1**：混输自动提交跨引擎歧义保护。先ADR明确唯一性的作用域；另有不同合法拼音候选时建议保留显式选择，而非仅看五笔域唯一。纯五笔唯一策略不受此建议影响，不新增开关。
3. **IT-25/P1**：本地修复保持，批次新包原生选词学习/误选恢复/读写失败验证。
4. **IT-26/P1**：混输拼音可达性。建议首屏保留少量明确拼音兜底而不抢五笔默认首项；先ADR定义“优先”的层级和数字映射，不直接打破现有规则。先改候选合并，不引入新模型/词典/切换开关。
5. **IT-27/P1**：最小拼音语法（隔音符）及常用读音质量。先支持显式分隔，必要时用已有词表做有限多切分；不换后端、不造整句。常用读音权重先固定集实测，不靠手写几个字排名冒充通用方案。
6. **IT-28/验收**：特殊编辑键、数字/英文/标点混排、受保护字段学习边界；未验标待验，发现数据损害升级P0。并入现有目标应用矩阵，不重复做一套平台框架。
7. **原有IT-18/10/11/12/14/16/17/22/23**：最终包词库/键盘/AX/对比度/多屏/性能/五日闭环。聚合测试，不把每项都拆成新功能。

代码修复可继续本地小步提交；功能完善后集中推送，最终同一签名包复验。没有日期承诺，也不把新增卡全部视为已批准实施行为。

### 下里程碑／证据触发再做

- NEXT-UI整套重构与用户已要求的完整五笔学习区；先准确编码/简要规则、后按实际数据推进逐字明细，不扩成教学课程或百科。
- 全简混拼、第五码顶屏、自动本地造词、手动置顶/忘记快捷操作：记录需求，只有固定集/实际频繁场景收益明确才立ADR。顶屏只评估纯五笔，不在混输四码时抢提交合法拼音。
- 冷启动/功耗/包体优化：违反已有目标再做；不因为竞品用复杂索引就重写现有数据结构。

### 明确不做

云候选/账号/同步/遥测；AI写作、翻译、搜索；剪贴板历史、打字统计；皮肤商店/推荐广告；整句大模型、自动上下文采集、按App画像；emoji/表情收藏、日期计算器、大符号面板；批量词库管理平台；在此阶段增加双拼/五笔98/其他平台等横向范围。已有中英切换/Enter原码可完成英文，不必为常见URL输入加入识别框架。

使用系统已有符号/emoji面板，避免输入法再维护第二套。上述暂缓项不代表永远禁止已在项目长期路线中的合法阶段能力。

## 6. “小而精”的进入门槛

每个新增能力都回答：是否解决经复现的核心输入阻碍？现有操作是否已能低成本完成？能否复用引擎/配置/词库？是否默认零额外后台和上下文收集？能否以固定离线样例证明收益且不破坏五笔肌肉记忆？若答案不清楚，先调研或拒绝，不新增开关掩盖默认体验。

优先使用一套可解释默认策略，失败保留输入并能恢复。学习只保留必要本地偏好，不用全句历史或生产遥测量化收益。现有15项配置不随竞品表膨胀；教学显示两项随下里程碑明确设计，其他项须单独ADR。

## 7. 证据与下一步

本报告是范围评估和任务卡，不是新候选混排/隔音符行为已采纳。后续按IT-29/26/27独立ADR、回归及本地提交推进，UI和公开推送继续暂缓。密码/安全输入只用自有测试客户端的虚拟文本，绝不输入真实密码或绕过系统限制。
