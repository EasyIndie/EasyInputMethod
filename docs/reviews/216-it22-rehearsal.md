## 2. 逐项分诊

### 2.1 连续 8–10 个字母无候选 —— **真问题，但期望值需要先校准**

用户报告：三种模式下 8–10 个字母都不出候选。代理用 ime-cli 接**包内真实数据**（`wubi86-core.tsv` / `pinyin-chars.tsv` / `pinyin-core.tsv`）复核：

| 输入 | 拼音模式结果 |
|---|---|
| `nihao` / `women` / `xiexie` / `xiexieni` / `zhonghuarenmingongheguo` | 有候选（你好 / 我们 / 谢谢 / 谢谢你 / 中华人民共和国） |
| `woaini`、`womende` | **无候选**（词表没有「我爱你」「我们的」） |
| `jintiantianqihenhao` | 无候选（整句，MVP 明确不做整句模型） |

机制：`TablePinyinBackend::convert` 只做「分段后的整串 == 词表条目」匹配；`ime-core` 又按引擎 `max_code_length` 过滤（五笔 4、拼音 32），所以五笔模式下超过 4 码必然无候选。这是设计如此，不是崩溃，也不会丢字。

**真实缺口**在于：`词 + 的/你`、`我爱你` 这类常见组合没有候选，用户感受是「打了半天没有字」。

**处置（已实施）**：按 §3 选项 A 实现多词分段拼接（ADR-299），包内真实数据复核：`woaini→我爱你`、`womende→我们的`、`zhongguoren→中国人`、`jintiantianqihenhao→今天天气很好`、`nihaoma→你好吗`、`asdfghjk→无候选`。整词优先保持不变。

### 2.6 Tab / Shift-Tab —— **清单表述问题，不是缺陷**

原文「焦移动正常，不插入异常字符」没有说清是在**组合中**还是普通编辑。在 TextEdit 里 Tab 缩进、Shift-Tab 无作用是应用自身行为，属预期。已把该行改写为「组合中按 Tab 不插入制表符/不吞键；普通编辑下 Tab 由应用决定」。

### 5.5 设置面板键盘操作无反应 —— **系统设置未开启，非本产品缺陷**

`defaults read -g AppleKeyboardUIMode` = **0**，即 macOS 默认「仅文本框之间用 Tab」，此时 Tab 不会在按钮/开关之间移动，任何 App 都一样。
判据：开启系统设置 → 键盘 → **键盘导航** 后重测。用户已开启并复测：Tab/Space/方向键全部正常 → 判 PASS（未开启时应记 BLOCKED 而非 FAIL）。

### 9.1 VoiceOver 方向键播报 —— **需要一次精确复现**

用户：在 TextEdit 里，候选窗内 `→` 报「文本结尾」、`←` 报「第N项，文字，来源」。
拆解：候选播报（`第N项，文字，来源`）确实发声，说明 ADR-291 的播报在生效；`→` 报「文本结尾」是**焦点落在文档**时 Document 的 AX 回复，不是候选面板的。9.2（VO 浏览候选并选词）是 PASS，说明候选列表本身可被 VO 遍历。
待确认：期望的是「按 ↓/↑ 在候选间移动并播报」还是「VO+→ 进入候选组」。这不是崩溃，但属于可访问性交互细节，需要一次带 VO 的定向复现后再定性质。

### 9.4 VO 开 + 宿主重启后立即打字 —— **已有等价证据，可判 PASS**

报告 215 §1 条件 B 就是这一项：VO 保持开启（PID 31461）→ 停掉宿主 23396 → IMK 拉起 31767/31627 → 用户实测打出「你」且有候选窗。本轮用户不便再操作，直接引用该证据。

### 11.1 长文本时候选框不精确跟随插入点 —— **真问题，待定位**

用户：无卡顿、无闪烁，但输入较长文本时候选框无法准确跟随焦点。
候选窗位置来自光标矩形（`attributes(forCharacterIndex:)` / `firstRect` 两趟，ADR-214）；长文本滚动后取到的矩形可能落在可视区外，或用了组合起始位置而非当前插入点。需要一张「位置明显不对」的截图 + 当时的滚动状态才能定位，暂记 FAIL 待查。

## 3. 2.1 的处理选项（需决策）

| 选项 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A 多词分段拼接** | 拼音后端在「整串不在词表」时，用词表做动态规划分段（最多 N 段），把各段最佳候选拼接输出（`wo|ai|ni` → 我爱你）。仍无整句/语法模型 | 约 1–2 小时实现 + 20 余条回归；需 ADR（新增行为） | 分段错位会产生怪词；需限制段数与总长，并保持「整词优先」 |
| **B 记录为已知限制** | 不改代码：发布说明披露「拼音按词表整词匹配，超出词表的长串不出候选，请分词上屏」 | 0 | 日常体验差，用户会认为「打不出字」 |
| **C 扩词表** | 补常用组合词（如「我们的」「我爱你」） | 数据流水线 + 许可登记 | 治标，覆盖不全 |

代理建议 **A**：这是「拼音兜底」这一 MVP 维度里唯一让人打不出字的缺口，且实现可在拼音后端内部完成（不动 trait、不引数据/网络）。
