## 1. 一个重要更正：报告 237 的"规则推导"结论不成立

报告 237 用「同两码组内全码权重最高的字」推导二级简码，并比较两种频度来源（差异仅 5/624）。
本轮把 rime/rime-wubi（D9，LGPL-3，**仅作验证 oracle**）的 2 码条目取出来逐格对照，结果：

| 对照 | 数量 |
|---|---|
| 规则推导码位 | 624 |
| rime 2 码条目 | 616 |
| **共同码位里选字一致** | **187 / 616** |
| **不一致** | **429 / 616（70%）** |

例：`aa` rime=式（规则给工）、`ad` rime=基（规则给其）、`ah` rime=牙（规则给臣）。

**结论**：二级简码不是"某码位里最高频的字"，而是官方表指定的那一个字。
按规则推导会把 70% 的码位选错——那不叫"手感差异"，那是"和老五笔完全不同"。
所以**不采用规则推导**，改用公开 86 版二级简码表（事实）逐条转写，并做两道机器校验。

## 2. 数据是怎么来的（D17-bis）

1. 转写公开 86 版二级简码表（25×25 矩阵，约 600 格有字）；
2. 与 D9（rime-wubi）的 616 条 2 码条目逐格对照；
3. 每条都要求**「简码 = 该字全码的前两码」**（用 D1 全码表校验）；
4. 排除两类非标准内容：
   - 极爽词库（极点五笔）自行新增的 17 个码位：`ao cm cu em eo fx hb ko la mk mo ns qx vm vr vw wp xs`；
   - rime 中 2 条前缀校验不过的：`hb=齰`（全码 hwwj）、`ya`（占位符 `#°`）。
5. 最终 **598 条**，登记为 D17-bis（项目自编清单，CC-BY-SA-4.0；`data/sources.toml` 含 SHA）。

## 3. 评测口径修正（原 `jianma2` 考卷是错的）

原 `jianma2` 由「高频单字的全码前两码」生成，隐含假设"2 码输入应当首选该字"。
装上官方的 598 条之后，这个假设被证伪：2 码首选的是**官方简码字**，不是"全码以这两码开头的那个高频字"。

| 类别（报告 238 后） | 含义 |
|---|---|
| `jianma2`（40 条） | **官方二级简码**：码位与期望字都来自 D17-bis，等距取样 |
| `prefix2`（30 条） | 原来的考卷，改名为"全码前两码反查"，只反映前缀反查，不代表简码 |

## 4. 结果（同一套 240 条样本，基线 = 1.1.0/build 38 的表）

| 类别 | 基线（无二级简码） | 现在（598 条入表） |
|---|---|---|
| **jianma2**（官方简码 40） | 命中 90.0% / 首选 **32.5%** / 位次 2.08 / 键 **3.58** | 命中 100% / 首选 **100%** / 位次 0.00 / 键 **3.00** |
| prefix2（前缀反查 30） | 首选 93.3% / 键 3.07 | 首选 40.0% / 键 3.60（**预期**：2 码首选让位给官方简码） |
| jianma1（一级 25） | 100 / 100 / 2.00 | 100 / 100 / 2.00（不变） |
| 单字/词/句 | 不变 | 不变（零劣化） |
| ALL（240） | 96.2 / 83.8 / 4.30 | 97.9 / 88.3 / **4.27** |

`prefix2` 的"下降"不是回归：老五笔用户打 2 码时本来就该先出官方简码字。

## 5. 校验与门禁

- `tools/check-level2-codes.py`：598 条、两码唯一、字唯一、**全部满足简码是全码前缀**、生成结果包含全部条目；
- `tools/check-level1-codes.py` 相应更新：核心表 1 码行 = 25、2 码行 = 598；
- `make verify` / 离线回归 60 文件 312 例全绿；核心表体积仍在 800 KB 预算内。

## 6. 版本口径

候选顺序变了 → 按 `MVP后执行计划.md` 的版本规则，进 **1.2.0**，不塞进 1.1.x：
- `Cargo.toml` 1.1.0 → **1.2.0**，`packaging/build-number` 38 → **39**；
- **1.1.0 的 tag 仍打在冻结候选 `393318c`**（那一个提交的 Cargo 版本是 1.1.0），发布流程不受影响；
- `test-docs-sync.py` 相应放宽：只要求"当前 Cargo 版本出现在 ROADMAP 发布列车小节里"，
  已打 tag 的版本才强制要求发布稿。
