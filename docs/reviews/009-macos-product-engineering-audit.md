# 009：设备 B 的 macOS 产品、体验、界面与工程审计

日期：2026-10-11。审计者：Codex。依据当前源码、隔离运行、历史 IMK 验收及 Apple 官方文档。

**结论：已有功能足以支撑面向五笔用户的轻量混输首版，但“功能存在”与“设置可信、操作可恢复、可访问”之间仍有明确缺口。近期应先修设置一致性、快捷键校验和验收脚本的数据保护，再完善候选与面板交互。没有证据支持整体重写宿主或改用 SwiftUI。**

本报告记录建议，不批准新功能、不改变既有 ADR、不修改产品代码。P1/P2 是本报告的修复优先级，不等同 ROADMAP 的阶段编号。

## 3. 优先处理的问题（P1）

### MAC-01：真机验收脚本可能删除真实工作内容（代码确认）

证据：`platforms/macos/tests/run-input-apps.sh:21–35` 的 EXIT cleanup 执行 `close every document saving no`，不区分 TextEdit 测试文档；调用 `field_clear` 清空当时前台输入框；最后清空剪贴板。微信测试直接操作现有会话输入框（109–123 行）。`run-panel-acceptance.sh:14–24,73` 使用固定 Documents 文件名并删除，未排除同名已有文件；还原真实词库采用直接 cp，且本来无词库时没有对应恢复逻辑。主验收脚本按“文档数 + front document”收尾，也不是对象级所有权。

影响：未保存文档、聊天草稿和同名文件有损失风险；复制内容被覆盖；测试词可能继续留在进程内。这是**测试工具的数据保护缺陷**，不是输入法日常输入路径自动删文档。

建议：所有资源用唯一 ID/随机路径创建并记录所有权；只关闭本次创建的文档/窗口；完整保存并恢复剪贴板类型与输入源；微信使用明确的测试会话/空草稿前置；真实词库测试改用专用验收用户或支持隔离目录；即使失败/焦点漂移也应安全退出。验收必须预置一个真实文档、草稿、同名文件和剪贴板，断言前后保持不变。修复前不继续执行这些脚本。

### MAC-02：快捷键保存成功不等于有效，冲突没有提示（隔离复现）

证据：`ime-config/src/config.rs:120` 对 String 无语义校验；`ImeSession.swift:188–228` 手工解析并按固定顺序匹配。`banana` 可保存；将中英与模式都设为 `ctrl+space`，只切中英，模式动作永远不会执行。菜单解析接受 `control/option/command`，运行时解析仅接受 `ctrl/alt/cmd`；隔离测试 `control+space` 在无其它绑定干扰时不匹配。大小写/空白、单独修饰键的支持也应统一。

建议：先 ADR 明确快捷键规范；由 ime-config 校验与标准化，宿主用同一结果展示/执行；拒绝语法错误，说明与其它动作冲突；保留 none 关闭。设置控件可先保留文本输入，但加即时有效性提示、常用示例和恢复默认，后续再评估按键录制。不要允许未修饰普通字母覆盖正常输入。

验收：非法、重复、大小写、别名、禁用、单 Shift、国际键盘、Caps Lock、系统/客户端同名组合键矩阵；失败不写盘，错误定位到具体行。

### MAC-03：全半角配置与实际输出状态不一致（隔离复现）

证据：`ime-core/src/lib.rs:188–206` 的 `width_override` 一旦临时切换就优先于配置；`set_input_options` 不清除覆盖。复现：配置 false → 临时切全角 → 设置 true → 设置 false，配置为 false，实际 `isFullWidth` 仍 true。设置面板显示的是配置值，菜单显示会话值。

建议：明确“默认值”和“当前输入状态”的关系。更直接的方案是用户显式修改全半角设置时清除临时覆盖；如坚持默认值模型，应改中文标题并显示当前临时状态。新上下文保留/重置哪些状态也须写入 ADR。

验收：快捷键/菜单/设置/外部配置四种入口交叉切换，实际字符宽度、菜单和面板语义一致；多应用上下文分别验证。

### MAC-04：配置即时生效没有完整重算当前候选（隔离复现）

证据：`InputController.swift:123–143` 调用 configure + setPageSize + 重绘；`ime-core::configure_engines` 只更新选项、不 recompute。合成词表 `zang→脏(10)` / `zhang→张(9)`：输入 zhang 时开启模糊音，当前候选仍为「张」；重新输入后变「脏、张」。

建议：配置变化应触发受控重算，并规定组合保留、页码与自动上屏行为。**配置通知本身不应意外自动上屏**。影响查询的选项（模糊音、万能键）与仅外观/页大小选项分开处理。

验收：组合中无新按键改 fuzzy/Z 行为，候选及时更新且缓冲保留；模式变化按既有约定取消组合。

### MAC-05：保存失败被吞，用户只看到按键无效（隔离复现）

证据：`ImeSession.swift:127–143` 的标点/简繁保存失败直接 return；`shortcut` 仍返回 true。用临时锁文件模拟失败：Ctrl+. 已被消费，配置不变，没有明确失败结果；模式快捷键失败又采用不同的透传语义。设置行的失败信息统一归因“只读/锁”，不能区分无效值、坏配置、IO 等。

建议：宿主返回成功/失败/未匹配三态；给简短、可恢复的统一反馈，保留原状态，避免失败快捷键误触客户端动作；面板错误指向中文选项与准确原因。成功信息适度、失败信息明确，避免每键弹窗。

### MAC-06：自绘候选缺少辅助技术动作，设置标签关系不完整（源码确认 + 探针）

证据：`CandidateLabel` 只有 mouseDown/onClick，没有 accessibilityPerformPress、候选角色/标签/选中状态；离屏对象探针 AX role 为 AXUnknown、performPress=false。设置 bool 用空标题 NSButton，标题在另一个 NSTextField，未显式绑定；自建词条字段主要依靠 placeholder。

影响：鼠标和数字选字可用，不能据此推断 VoiceOver 或完整键盘访问可用。离屏对象的 AXUnknown **不是完整系统 AX 树结论**，但无辅助动作是确定的。

建议：为候选提供可访问角色、名称（序号/文本/来源）及选择动作；设置控件关联标题、值、帮助与错误；完整键盘访问遍历各面板和对话框；避免抢走输入客户端焦点。以 Apple [可访问性测试指南](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app?changes=_7) 为测试矩阵基础。

验收：VoiceOver 能识别并选择候选；键盘可操作设置/词库/版本；浅暗、增加对比度、减少透明度与大文字场景分别验证。

### MAC-07：缺失/损坏简繁数据可能显示繁体状态却输出简体（源码确认 + 解析探针）

证据：`InputController.swift:88–101` 仅对缺拼音字表设置错误，缺拼音词表/简繁表未同等提示；忽略 setVariantData 返回值。`session.rs:196–204` 加载失败被忽略；`VariantMap::from_tsv` 跳过坏行，不拒绝空映射。只含 garbage 的文件 setVariantData 返回 IME_OK（0）；仅校验 metadata 存在不等于已验证格式/可读。

建议：保留懒加载，但首次使用时返回可识别的加载错误；失败时不宣称繁体功能生效，提供重新安装完整包的恢复路径。发布严格检查之外，运行期也应覆盖资源缺失/损坏，不依赖“正常发行一定完整”。

验收：删除/改坏词表与简繁表，用隔离 bundle 测试；错误可见、状态不误导；正常简体启动仍不解析简繁全表。

### MAC-08：对比度测试可产生“全通过”的假信心（源码确认）

证据：`Preview/main.swift:457–474` 对整张位图取最亮/最暗像素算比值。黑色主文字和白背景就足以通过，来源小字、次级说明、悬停高亮可以完全不合格；透明区域也没有与实际背景合成。审计中 settings 离屏 PNG 未完整形成可评判的面板背景/内容，不当作设置实屏视觉证据。

建议：把现有断言降格为渲染冒烟；按控件/文本角色采样其前景与局部背景，透明图层先合成；单独测来源、状态、禁用、错误、悬停、选中与焦点。保留真实截图和人工检查。不能把现有 ≥4.5 结果写成“整个面板已证明 WCAG 合格”。

### MAC-09：当前签名包、源码与环境记录没有统一（本机核验）

证据：源码 c294b67，已安装 4d9339c；交接仍写 88833aa 与“两机同 main”，设备 B 环境却只安装 arm64 target；发布说明仍写机器 B 待验收。当前已安装包为开发 ad-hoc，不能等价正式签名/公证包。

建议：发布验收单锁定 commit + 包 SHA + 架构 + 签名身份 + 系统/应用版本；用**最终签名包**做一轮真机验收。将“本机/设备 B”与“机器 A”分开写；历史报告保留日期，不把旧结果推到新版本。第三方离线重建与零外联验收仍需外部人员。

### MAC-10：发布 dry_run 未实际核对附件摘要（源码确认）

证据：`.github/workflows/release.yml:48–91` 下载成功工作流产物并检查文件名存在，未执行 SHA-256 核对，也未校验包内 commit/版本/架构与 tag 一致；附件和文案固定 0.1.0。工作流上游已有签名/复现验证，这是正向保证，但 dry_run 文案“校验附件”比该步真实能力更强。

建议：发布前逐项核验摘要、BUILD-INFO/SOURCE-COMMIT、源码与二进制对应关系；从版本单一来源派生名字与文案；dry_run 和正式发布复用同一验证步骤。现有 Release 重跑 --clobber 是否允许应有明确发布约定。

## 4. 输入与界面改进（P2；其中设计建议需先确认 ADR）

| ID | 问题与证据 | 建议 | 验收重点 |
|---|---|---|---|

| MAC-17 | 字根提示未展示；模糊替换仅作用输入开头，无法逐音节组合；精确和模糊候选只按词频排序 | 先字根提示、基础拼音质量，再整句；模糊按音节处理并保守限制扩展；考虑精确优先或模糊降权 | 合成 zhang 查询中，开启 fuzzy 后脏(10)排在精确张(9)前；建立真实词例质量集 |

| MAC-19 | 配置与数据错误 runModal，去重状态保存在各 InputController；同时多个上下文可能重复提示 | 进程级去重、面板内可恢复提示，输入过程尽量不中断；保留首次必要错误可见性 | 两客户端同一错误仅一次；修复后清除；打开设置不污染原组合 |
| MAC-20 | 版本窗无“复制成功”提示；外部链接 completionHandler 丢弃失败 | 简短“已复制”；打不开时告知可复制地址，并明确“将在浏览器打开” | 离线/无默认处理器时无卡顿；不联网探测、不自动提交用户信息 |

## 5. macOS 工程与验证体系建议

**MAC-21 / P2：性能与功耗应覆盖用户会触发的完整路径。** 文件监听200ms常驻轮询（ime-ffi/config.rs:133–136），候选可见时主题也轮询；设置/快捷键同步配置写盘含 fsync；简繁首次加载同步解析且回简体后保留表；CandidateWindow 每控制器实例可能分别持有窗口和字体预热。已有共享弱缓存是正确方向，不建议凭静态代码重构。补测：冷启动第一键、繁体第一键、8–16应用上下文、10次开关设置、满词库选词、空闲60秒唤醒、终端高频输入。用 Instruments Time Profiler/Allocations/Energy 或本地等效采样；分别记录宿主、引擎、峰值和稳态。不要仅以默认简体全新启动证明所有场景≤30MB。

**MAC-22 / P2：构建元数据、环境预检与调试入口。** Info.plist 固定写入 BuildMachineOSBuild/DTSDK/DTXcode 和构建号0.1.0，build.sh直接复制；在 CLT 或不同 SDK 机器构建时可能与实际工具链不符。构建前应检查两种 Rust target、实际SDK/Swift与数据，动态生成真实元数据、校验部署目标和 InfoPlist 本地化；保留 SOURCE-COMMIT，开发脏树标识与正式干净树要求明确。零诊断规则应覆盖脚本中的 cargo 与所有 Swift helper，不只主 app；temporary Ctrl 日志（InputController.swift:385–389）发布构建应移除或限定诊断模式，不记录键值内容。命令行构建本身没有问题，可在需要断点/性能分析时提供轻量 Xcode scheme，且不另起一套发布真值。

**MAC-23 / P2：安装与升级的操作成本。** 目前不同版本要求先卸载，首次需注销并手动添加输入源，文档技术术语多。先补一页正常安装/更新/回滚流程及包内可点击本地说明；未来可评估最小原生安装/更新辅助入口（新功能需ADR）。保留严格签名、公证、权限与影子副本检查；不引入自动联网更新。不要把Xcode27/Icon Composer当成首版必需项，只有图标的实际清晰度/模板反色有问题时再推进。

**MAC-24 / P2：实机 DoD 的通过范围过宽。** run-input-apps主要测五笔短字上屏 + TextEdit撤销，不等价“各应用长文本、光标定位、切窗口、撤销均通过”；微信未运行可SKIP且最终fail=0。已有多屏测试是数学矩形，不是外接屏IMK；caretRect固定请求字符index=0（InputController.swift:492–500），对部分客户端可能错误，尚未实机复现，需比较 markedRange/selectedRange约定并测试文档中段/末尾。给每个场景PASS/FAIL/SKIP/BLOCKED，发布必需场景不能用SKIP算全绿。补 Safari/Chrome地址栏、网页textarea/contenteditable、TextEdit富文本、Terminal、编辑器、聊天草稿；长组合、候选点选、输入源切换、Spaces/全屏、休眠/唤醒与多屏缩放。

现有 Safari 地址栏预编辑残留继续按已接受限制处理。本轮没有证据证明“所有输入法同样如此”或“不留行内预编辑是唯一解”；保留最小复现与按客户端/版本的差异记录，若后续重开再做产品取舍。**已接受限制不能算修复完成，也不应自动升级为发布阻塞。**

## 6. 建议执行顺序

1. **先保护验证环境**：MAC-01，独立小改动修验收资源所有权；在完成前不运行现有多应用脚本。
2. **设置可信性**：MAC-02/03/04/05/07，逐项 ADR（涉及规范/对外行为时）→最小实现→针对性回归。避免将多个设置问题合成大重构。
3. **首版可用性补强**：MAC-06/08，可访问语义与真实对比度测量；MAC-11/12 设置分组与窗口约束。修复后以最终包重验。
4. **发布收尾**：MAC-09/10，统一来源和文档、附件校验、最终签名包验收与P1-M5独立第三方复现，再决定发v0.1.0。
5. **发布后聚焦主定位**：MAC-14/15/17/18 候选、字根、基础拼音、词库纠错；MAC-16/21按实测收益做性能/功耗优化；MAC-22/23/24长期工程改进。

不建议近期优先做 emoji、i18n、整句大引擎、首次激活引导、图标分层重做或更多皮肤；其中首次引导已有不做决定，其他扩展不能代替本报告的可靠性修复。已有 AppKit + Rust +窄ABI、Schema真值、离线数据、共享不可变表、签名/复现流水线应继续保留。
