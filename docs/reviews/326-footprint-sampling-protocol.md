# 326 — footprint 采样协议：为什么要改，改完测到什么

> 触发：报告 325 里同一份 1.3.2 二进制（执行 `46cc4d7b…`）的 footprint 读数横跨 **35.9–57.3 MiB**，
> 其中 44.1（验收脚本内）与 57.3（装后首跑）各误报一次 FAIL。处置见 ADR-385。

## 1. 原来的做法与问题

`perf-session.sh` 键入结束 → 静置 20 s → `vmmap -summary` **取一次** Physical footprint → 与 44 MiB 硬顶比较。

问题有两层，混在一起：

| 层 | 表现 | 原因 |
|---|---|---|
| **同刻噪声** | 同一次运行里，脚本内 44.1 vs 单独复测 35.9 | 首次触页、页回收、`vmmap` 自身读页；单次采样没有重复性 |
| **跨时刻不可比** | 冷启动 35.9 → 用 1.5 h 后 47.0 | 练习题库/学习区按需物化后不回落；绝对值随宿主年龄单调上涨 |

原来的门禁把这两层都算成「产品内存」，于是：

- 刚装完的第一次验收容易报 FAIL（57.3）；
- 跑了几轮之后又可能 PASS（36.5）；
- 一个用了很久的宿主则必然 FAIL（47.0）——即便产品这一版什么都没改。

## 2. 新协议（ADR-385）

```sh
# 静置后连续采样，取中位数；绝对值只在冷启动窗口内判 FAIL
FOOTPRINT_SAMPLES=3        # 采样次数
FOOTPRINT_INTERVAL=5       # 间隔秒
FOOTPRINT_SPREAD_WARN_MB=8 # 离散度超过就标 unstable
FOOTPRINT_COLD_UPTIME_S=900 # 宿主 uptime 超过 15 分钟 → footprint 只作参考
```

输出字段：

| 字段 | 含义 |
|---|---|
| `footprint_samples_mb` | 三连原始读数（可复核，不再只有中位数） |
| `footprint_steady_mb` | 中位数 → 用于打印/趋势 |
| `footprint_spread_mb` | max−min；> 8 时 `footprint_unstable=true` |
| `host_uptime_s` | 宿主已运行秒数（`ps -o etime` 换算，macOS 无 `etimes`） |
| `footprint_cold_baseline` | uptime ≤ 900 s 才为 true |
| `footprint_note` | 超窗/抖动时的自然语言说明 |

判定：

```
PASS = 有稳态样本 & p95 ≤ 16ms & 采到冷首键 & conns == 0 & 无源不匹配
       & (footprint_cold_baseline ? footprint_steady_mb ≤ 44 : true)
```

内存的**硬门禁仍是 `memory-gate.sh` 的 `heap live ≤ 24 MiB`**（ADR-338），footprint 只是粗粒度 tripwire（ADR-379）。

## 3. 改完的实测（1.3.2 已装包，`46cc4d7b…`）

| 时刻 | 宿主 uptime | 三连采样（MiB） | 中位数 | 离散 | 判定 |
|---|---|---|---|---|---|
| 10:44（刚验收完） | 冷 | 35.9（单次，旧协议） | 35.9 | — | 参考 |
| 10:57（旧协议单次） | 冷 | 42.6 / 36.5 / 36.5 | — | — | PASS |
| 11:00（新协议） | 冷 | 45.2 / 45.2 / 45.2 | 45.2 | **0.0** | FAIL（冷窗口内，真超顶） |
| 11:05（新协议） | 5,139 s | 47.0 / 47.0 / 47.0 | 47.0 | **0.0** | PASS（超窗 → 参考值 + 说明） |

读法：

1. **同刻稳定**：改了协议之后三次采样离散度都是 **0.0** —— 说明原来的 20 MiB 抖动不是"同一时刻的随机噪声"，
   而是**时刻之间**的差异（进程已经物化了不同的数据）。
2. **冷窗口内已经真超 44**：45.2 是冷启动后的真实值，不是抖动；这条要如实记账（见 §4）。
3. **超窗后继续涨**：47.0（uptime 5,139 s）。协议把它标成参考值，不让它变成"用得越久越必然 FAIL"。

## 4. 顺带发现：+11 MiB 是练习/学习区物化，不是泄漏

- 冷启动 35.9 → 1.5 h 后 47.0 MiB（+11.1），而 `heap live` 门禁一直是 21.3–21.7 / 24。
- 增量的形态与 P1-M1 描述一致：`Practice.bank` 一次 materialize 5,021 道题 + `LearningHints` 按需解析。
- **P1-M1 的触发条件（"footprint 再涨 > 2 MiB"）已经命中**，下一步应做「练习题库延迟构造」，
  而不是把 44 调高。协议的作用之一就是把这条趋势显式化，让阈值不被悄悄挪动。

## 5. 结论

- 1.3.2 的**性能与内存结论不变**：p95 6.7–7.3 ms（限 16）、`heap live` 21.3–21.7（限 24）、零外联。
- 报告 325 §6 的"44.1 越界"在新协议下可复核：它属于跨时刻差异，不是产品回归。
- 协议不改数值、只改测量条件；所有原始采样落盘（`footprint-samples-mb`、`host-uptime-s`），
  第三方可自行复算中位数。
