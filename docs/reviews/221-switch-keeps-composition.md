# 221 组合态下的状态切换不再丢字（ADR-302）

> 用户报告：编码已出现候选框时，按 **Shift / ⌥M / ⌥F** 会立刻让候选框和编码一起消失；
> 而 ⌥T（简繁）/⌥P（标点）是在候选窗里内联反馈的。要求分析合理性并改善连续输入体验。

## 1. 代码事实

| 快捷键 | 调用链 | 旧行为 |
|---|---|---|
| Shift（中英） | `ime_session_toggle_english` → `Session::toggle_english()` → `self.cancel()` | 缓冲区清空 |
| ⌥M（模式） | `ime_session_set_mode` → `Session::set_mode()` → `self.cancel()` | 缓冲区清空 |
| ⌥F（全角） | `ime_session_toggle_width` → `Session::toggle_width()` → `self.cancel()` | 缓冲区清空 |
| ⌥T / ⌥P | 只写配置 + `prepare()` | 候选窗保留、芯片内联更新 |

## 2. 判断

- **⌥F 全角取消组合不合理**：全角只影响之后提交的标点/数字，与当前编码无关，取消没有收益。
- **⌥M 模式取消组合不合理但可理解**：旧编码的候选确实会变，但"换个思路继续打"是真实场景，保留编码并按新模式重算更贴近意图；无候选时用户按 Esc 即可。
- **Shift 切英文丢字最刺眼**：按 Shift 的动机通常是"这段想打英文"，用户期望字母留下；直接删除与动机相反。

## 3. 改法（ADR-302）

| 快捷键 | 新行为 |
|---|---|
| Shift → 英文（组合中） | 先把编码**原样上屏**（`nihao` → `nihao`），再切英文；宿主侧用已有 `insertText`，无 ABI 变更 |
| ⌥M 模式 | 保留缓冲区，按新模式 `recompute_with_commit(false)` 重算候选，**不自动上屏**；无候选也保留编码 |
| ⌥F 全角 | 保留缓冲区，只影响之后的提交 |
| ⌥T / ⌥P | 不变 |

## 4. 验证

- core 新增 3 个单测（全角保留组合与候选、切模式保留缓冲区并重算、新模式无候选时保留编码且 Esc 仍可取消）。
- `ime-ffi` 的 `candidates_expose_source_codes` 原先依赖"切模式会清空缓冲"，改为先 Esc 再切模式。
- 离线回归 56 文件 / 303 例、`make verify` 全绿；实机复验见 §5。
- 实机复验（build 32，两台设备）：待填。

## 5. 遗留

- 组合中切模式若新模式无候选，候选窗会隐藏、编码以预编辑文本留在输入框里（用户按 Esc 取消或继续补码）；这是刻意的取舍，写进发布说明的已知行为。
