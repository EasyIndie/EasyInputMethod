# 256 — 学习区内存 A/B：开启多约 3 MiB，懒加载没吃掉差额

- 日期：2026-11-06　｜　同一构建 `exec 2dc69977`（learning hints 按需解析）　｜　探针：`memory-gate.sh ROUNDS=3`

## 1. 数据（私有已提交，稳态 = six-words / idle-8s）

| 配置 | 轮 1 | 轮 2 | 轮 3 | 判定（门禁 30 MiB） |
|---|---|---|---|---|
| **学习区关**（默认） | 29.8 / 29.7 | 30.0 / 29.9 | 28.7 / 28.6 | **PASS** |
| **学习区开** | 33.3 / 33.3 | 31.9 / 31.9 | 31.7 / 31.7 | **FAIL** |

footprint 同步差约 2–3 MiB（关 31.7–33.2，开 34.8–36.4）。

## 2. 已排除的原因

- **不是数据解析**：把 3,000 条改成按需解析（只留 120 KB 字节 + 索引，命中时解析单行、缓存 64 条）后，
  差额没有变化 → 不是 `LearningHints` 的常驻。
- **不是视图对象数量**：学习区约 15 个子视图，即使全部常驻也只有几十 KB 量级。

## 3. 最可能的原因

**字形/文本渲染缓存**：学习区会额外绘制大量不同汉字与字根（`禾 口 亻 ⺈ 小 丿 扌 ？` 等），
这些字形在候选窗里本来不会出现；CoreText 会为每个新字形缓存位图/轮廓，量级正好是 MiB 级。
这类开销随"显示过的不同字形数"增长，属**功能本身的成本**，不是泄漏。

## 4. 两个可选处置

| 方案 | 做法 | 影响 |
|---|---|---|
| **A. 分开立阈值（推荐）** | 默认（学习区关）仍守 **≤30 MiB**；学习区开启时放宽到 **≤34 MiB**，并在文档/发布说明写明"+3 MiB，默认关闭不付这个钱" | 无代码改动，口径诚实 |
| B. 继续压 | 每次只显示更少字形（例如字根最多 3 个、去掉识别码字母），或改成"按住某键才显示" | 牺牲可读性/交互，收益有限 |

## 5. 结论

学习区默认关闭时内存**不回归**（28.6–30.0 达标）；开启时的 +3 MiB 是"多画了很多字"的成本。
建议按方案 A 立阈值并写进 ADR，不再为它改交互。
