# 069 — 迭代过程复盘与提速建议

2026-10-18。覆盖从报告 062（Codex 收尾）到正式 0.1.0 签名包（`ba6d796`）的完整一轮。目的不是追责，而是把这一轮暴露的**方法问题**固化成流程改进。

## 一、这一轮的代价

| 项 | 数量 |
|---|---|
| 候选构建（双架构 strict） | ≈ 8 次 |
| 重启 / 重新登录（为恢复输入法注册） | ≈ 6 次 |
| PR CI 轮次 | 4 次（其中 2 次因测试硬编码旧默认值失败） |
| 实机验证轮次 | 5 次（062 锁屏阻断、063 与复测被"未激活"污染、067 带日志判定、068 通过） |
| 无效结论 | 2 条（"候选菜单不呈现"、"热替换本身导致菜单退化"） |

## 二、慢在哪

1. **产品路径没有可观测性**。菜单是否被请求、命令是否被投递、投递的是哪一项，全靠 AX 反推。一个带日志的构建（报告 067）用一轮就定案了前面四轮没定下来的问题。
2. **采集方法缺一个前提**。菜单只有在控制器被客户端激活（一次按键）后才包含产品项；未激活时读到的是系统通用菜单。063/064 的主判断都栽在这里。
3. **热替换会破坏 IMK 注册**。停宿主→换 bundle→手动启动→注册，之后菜单/源会间歇性失效，只能重登恢复。每轮实机验证因此多一次重启，且容易把环境问题记成产品缺陷。
4. **测试硬编码默认值**。改默认快捷键后，CI 仍按 `Ctrl+.`、17 项设置写死，直接失败两次；而 schema 才是唯一来源。
5. **反馈回路太长**。一次"改一行 Swift → 看真实菜单"＝ 构建 2–3 分钟 + 替换 + 激活 + 人工点击 + 恢复，任何一步出错就重来。
6. **ADR 采纳缺少"证据等级"**。ADR-202/205 的依据是本地组件/私有 IMK 回归，实机证据不足，结果两次推翻。

## 三、提速建议（按收益排序）

| 编号 | 措施 | 预期收益 | 成本 |
|---|---|---|---|
| **P1** | `make macos-live-check`：一条命令完成"按键激活→坐标点击→截图→读 config→A/B/A 对照→恢复"的固定流程，人只做审批 | 单轮实机验证 ≤3 分钟，替代本轮 10+ 次手工往返 | 中（把本轮零散脚本固化） |
| **P2** | 宿主内建 trace：`LAMPYRIS_TRACE=1` 时记录 `menu()` 返回项与收到的命令字典（标题/tag/action），默认关闭、不写用户数据 | 菜单/命令类问题一轮定位 | 小（本轮的诊断补丁已现成） |
| **P3** | 实机验证用虚拟机快照（UTM / Apple Virtualization）：装包、登录、测试、回滚快照 | 登录/重启成本≈0，环境可重复，不占开发机 | 中（一次性搭建） |
| **P4** | 测试期望从 schema 派生；新增 golden schema 测试（默认值变更必须显式改一处） | 消除"改默认值 → CI 返工"这类失败 | 小 |
| **P5** | CI：`paths` 过滤文档类改动；签名/公证只在合并 main 后跑；cargo 缓存；verify 与 sign 拆 job | 每轮省 2–5 分钟，省 Apple 公证调用 | 小 |
| **P6** | 探针源码入库 `tools/macos-probe/` + `make probes`（AX 读取、坐标点击、按键、TIS 查询） | 不再因 `/tmp` 清理丢失工具 | 小 |
| **P7** | 变更门槛：涉及输入菜单/命令链路的 ADR，必须附"带 trace 的实机证据"并标注证据等级 | 避免再次基于局部证据采纳方案 | 小（流程） |
| **P8** | 新增 `docs/开发工作流/实机验证.md`：激活前提、热替换禁忌、A/B/A 对照、恢复步骤、平台特殊键（`⌃.` 被系统吞） | 换人/换工具也能一次做对 | 小 |

## 四、关于平台事实的沉淀

- IMK 输入菜单只渲染**纯标题 + 真实快捷键**；自定义 view、`badge`、塞进 key equivalent 列的任意文本都会被剥离（三个构建截图核对）。
- 子菜单子项点击**不会**产生命令（0 条 CMD/APPLY），父项挂子菜单后点击也不再触发循环。
- 单个 `⌃.` 被系统当作取消键吞掉，`⌃⇧.` 正常。
- 源切换/热替换后，菜单需要"按键激活控制器"才会出现产品项；注册失效只能重登。

以上已写入 ADR-206/207/208、报告 067/068 与本报告；P8 的文档会再汇总一次。
