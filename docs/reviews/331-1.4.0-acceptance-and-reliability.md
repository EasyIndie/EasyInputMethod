## 4. 体检抓到的两处问题（都在探针侧，ADR-389）

第一次 30 min 久用报出的读数是「每 6–9 轮就有一轮 p95 400–700 ms」，看起来像产品卡顿。逐层排除：

| 假设 | 实验 | 结果 |
|---|---|---|
| 探针窗口/系统负载（swap 用掉 2.8 GiB，load ≈ 2） | ABC 输入源控制组，65 轮 | **0 次慢键**，最大 17 ms → 不是系统 |
| 某段文本/候选更重（中国/人民/时间） | 六个 chunk 各自重复 8–12 轮，含 soak 的 250 ms 节奏 | **12–31 ms**，全部正常 → 不是内容 |
| 是久用探针自己 | 在宿主旁边每 2 s 跑一次 `vmmap -summary` 再打字 | **10/10 轮**变成 277–605 ms → **就是它** |

原因：`vmmap` 会先 `task_suspend` 目标进程再遍历地址空间（一次 ~1 s），被暂停期间到达的按键自然被
记成"卡顿"。这正是 ADR-385「不许把探针伪影当门禁量」那一类错误，只不过这次伪影伪装成了产品的性能问题。

修法（`ADR-389`，只改探针）：

1. **新增 `tools/macos-probe/footprint`**：`proc_pid_rusage(RUSAGE_INFO_CURRENT)` 读 `ri_phys_footprint`，
   15 ms 完成、**不暂停进程**，读数与 `vmmap` 差 ≤0.5 MiB；久用改用它采样。
2. **footprint 只在冷启动窗口（900 s）内判定**：久用开始前先把宿主重启成冷态，窗口内样本参与判定，
   窗口外标 `footprint_gate: informational`。
3. **久用硬门对齐项目口径**：`FOOTPRINT_HARD_MB` 40 → **44**（ADR-385/379 的值；40 是 ADR-385 之前的旧值，
   在长量下会假 FAIL，本地实测到过 41.8 → 43.5 的假失败）。
4. **延迟进门禁**：久用输出 `latency_p95_median_ms` 并判定 ≤ 40 ms（P2-3 的触发线），另记慢轮数。

修好后同一台机器、同一候选、同样 30 min：

| | 修前 | 修后 |
|---|---|---|
| 每轮 p95 中位数 | 16.18 ms | **9.29 ms** |
| 慢轮（>100 ms） | 24 / 174 | **0 / 178** |
| 单键 >200 ms | 66 / 2,117（最大 694 ms） | **0 / 2,173（最大 30.5 ms）** |

契约测试 `platforms/macos/tests/test-soak-harness.py`（3 条）把这三件事钉住：久用不许出现 `vmmap`、
硬门必须是 44、延迟必须判定。

## 5. footprint 与存活堆的口径（回应"是不是变胖了"）

同一份候选包在三个时点读到三组不同的 footprint：装完第一轮 33.2–35.8、体检中 42.0–42.3、久用稳态 43.4。
存活堆始终是 **21.2–21.5 MiB**。这正是 ADR-385 的结论：footprint 含只读库页与 AppKit/图形缓存，
跨会话可比性差（>8 MiB 漂移就是不稳定的信号），**门禁看 `heap live ≤ 24 MiB`**；44 MiB 只作冷窗口上限。
峰值 44.2 出现在长量末尾，属于窗口外的尖峰，按 ADR-385 不参与判定，但如实记录在这里。
