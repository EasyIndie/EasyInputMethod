# 324 · 受控推断：L1 之外 153 字的根序候选

> 日期：2026-11-19 ｜ 关联：报告 323（方法来源）、ADR-382（不猜）、`docs/tasks/T-ROOT86.md`
> 工具：`tools/wubi86-root-infer.py` ｜ 输出：`build/inference/root-inference.tsv`（**build/ 目录，不入库**）
> 结论：154 个非 `full` 字里，**104 个得到唯一可复核候选**，52 个失败且原因已分类。
> **候选不进产品数据**（`quality` 不变），只作为人工复核的入口 —— 这是 ADR-382「不猜」的落地方式。

## 1. 为什么只做"受控"推断

报告 323 记录了外部资源的许可限制：拆字表不能入库。于是我们只做**能自证**的推断：

```
IDS 部件树 → 每个叶子映射到"已知根序"（full 字的根序 / 标准字根 / 已确认的非字根部件）
          → 按取码规则裁剪（>4 取一三末，<4 补识别码）
          → 必须与码表逐位对齐（键位 = 码位）
          → 唯一才输出 unique，否则记 fail + 原因
```

三条硬约束：

1. **不做自由搜索**：只走 IDS 结构，不做"枚举所有组合再挑一个像的"；
2. **映射表只收已确认项**：`KNOWN_PARTS` 里的 `豖/艮/氐/啇` 全部来自 D25 已判定的条目，不允许"从码反推部件"（那会自我循环）；
3. **唯一才算候选**：多解一律 fail，不猜。

## 3. 失败原因分类（52 条）

| 原因 | 条数 | 典型 | 下一步 |
|---|---|---|---|
| IDS 树太浅（叶子是生僻部件，如 菐/僕/𦥑/鍂） | 34 | 濮 iwoy、噗 kogy、鑫 qqqf | 需要这些部件的拆法证据（不能从码反推） |
| 根数与识别码字母不匹配 | 11 | 夔 uhtt、貂 eevk、辔 xlxk | IDS 结构与码表结构口径冲突，需人工判 |
| IDS 只有 1 段 | 5 | 侃 wkqn 类 | IDS 数据本身不全 |

> 关键纪律：**不为了让推断通过而往 `KNOWN_PARTS` 里塞"从码反推"的部件拆法**。
> 中途我确实塞过 `菐=[业,一,人]`，跑出来"第 4 位 人 不在 y 键" —— 那正是自我循环的症状，已删除。

## 4. 怎么用这批候选

1. 打开 `build/inference/root-inference.tsv`（`make` 后生成），`status=unique*` 的行即有候选；
2. 人工按「码位—字根—键位」逐位复核（和 D25 的判法一致）；
3. 复核通过的，抄进 `data/learning/wubi86-root-order.tsv`（D25）并用 `--root-order` 重跑，
   该字才会从 `partial` 变 `full`；
4. 复核不通过的，把原因写回 `blocked` 行。

**工具命令**：

```sh
python3 tools/wubi86-root-infer.py                    # 全量 154 条
python3 tools/wubi86-root-infer.py --limit 40         # 只看高频前 40
```

## 5. 与"外部资源"的关系

报告 323 结论仍然成立：外部拆字表**不入库**。本推断只用**我们自己的** IDS（D19）、
根序表（D25）、字根清单（D18/ADR-358）与码表（D9），因此产物许可干净、可复现。
