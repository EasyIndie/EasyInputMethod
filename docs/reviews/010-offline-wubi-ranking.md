# 010：五笔固定候选体验与离线排序优化

2026-10-14，用户反馈五笔/混输常用候选靠后、需重复选词。前文为修复前源码审计与建议，末尾记录ADR-159实施；具体用户安装包场景仍待复现。

## 已确认的实现

- ime-table按精确匹配、码表weight等筛候选，重码按weight和文字排序。
- ime-core::personalize按来源（五笔在拼音前）、精确优于前缀、精确拼音优于模糊，再按用户次数、基础weight、文字排序。同组已有本地动态排序，不是完全固定码表。
- ime-ffi选择提交后按scheme/code/text记账；空格首项、数字和显式select都有路径。纯原码Enter与取消等不能一概当作候选学习。自动上屏等不同提交路径是否记账需单独验证，不凭有learn函数声明全覆盖。
- ime-dict本地有界TSV保存scheme/code/text/count，计数饱和增长、原子持久化；没有本报告建议的时间衰减、主动选词权重或置顶字段。
- 学习区分五笔/拼音：混输用拼音选到目标只计该拼音来源，不自动教会对应五笔排序。完整码与输入前缀的分组约束仍保持。
- 主工作区与独立修复78b6762的ime-core及session源码比较一致；不等于已装d429cec的具体输入行为已验证。真实包/词库读写状态需独立核对。

## 可能原因（尚未确定用户根因）

1. 学习链路实际写入失败、加载的安装版本或数据根不符；菜单已有读写错误提示，可核查，不盲目重建/删除词库。
2. 用户目标为前缀补全，前面有精确简码；当前分类规则不让补全靠学习越过精确项。
3. 同组首项长期空格提交积累次数高，主动多次选择后项仍追不上；现有count未区分选择成本。
4. 混输在拼音来源完成选择，该次数不影响五笔来源排序。
5. 候选池上限、刷新/合并/去重和分页表现需覆盖检查；不提前认定存在截断bug。

## 方法与建议优先级

| 方法 | 离线实现与收益 | 风险／边界 | 优先级 |
|---|---|---|---|
| 修复既有学习链路 | 检查选择后次数、下次同码排序、重启保持 | 应优先修bug，不能用新算法掩盖失败 | P1当前功能体验，IT-24后 |
| 同码分组内调频 | 继续局部重排，不打乱不同来源和匹配层级 | 前缀补全限制需明确，不能承诺所有词都能首项 | 第一阶段 |
| 主动选择更强信号 | 非首项数字/鼠标选择给予比默认空格更强学习证据；重复确认再晋升 | 次数来源字段/模型需设计，误选不能一次永久改首项；不在当前按键过程中跳位 | 第一候选方案，先ADR/固定质量集 |
| 频次有界＋近期权重 | 分组内用归一化/饱和频次及近期信号，避免历史次数无限固化 | 当前无时间字段；需迁移、可解释衰减与稳定阈值，不能直接把几次用户count加到数量级悬殊的基础weight | 第二阶段，按证据启用 |
| 显式置顶／恢复默认 | 用户确定偏好可直接固定某码首项，减少重复训练 | 新元数据/管理动作，不能靠伪造巨大频次；更适合后续而非堆入口 | 可选后续 |
| 静态码表权重质量 | 合规离线语料/固定质量集改进新用户默认顺序 | 无个性化，来源许可与SHA登记必需；不可随意改标准一级简码习惯 | 配套改进 |
| 本地上下文模型 | 有可能改善同码消歧 | 增加隐私面、资源和不可预测性，不是解决此问题的最小方案；不收集整句输入历史 | 当前不选 |

建议先恢复和验证已有能力，再评估“分组内、主动选择优先、有限历史影响”的保守学习。是否保护标准一级简码或提供固定排序选项须明确用户群与回归，不临时添加配置，更不擅自锁死所有简码。

不要把常用重排升级为“多候选自动上屏”。四码唯一自动上屏继续基于真实唯一匹配，不因学习偏好忽略重码候选；即使唯一结果相同，选择理由/次数也需可追溯。

混合模式保持五笔优先，拼音次数不默认把拼音顶到全部五笔前。跨来源关联学习可选但需可靠五笔反查和明确语义，作为后续单独议题，不与UI学习区重构混做。

## 隐私与工程约束

完全离线也不等于不存数据：当前已有本地字词/码/次数词库。只保留必要排序证据，不记录整句、宿主文档、应用身份、剪贴板或输入历史，不传网、不遥测。

使用既有本地词库机制，核心只做内存排序，不新增网络/账号/数据库依赖。新排序偏好若需要配置仅经ime-config。重置学习与删除用户自定义词必须明确区分；当前同表保存词条和次数，不能直接删整库当恢复默认。

学习写入错误不得阻碍本次输入；持久化与跨进程合并性能不能显著增加按键延迟。排序在下一次组合/受控重算生效，同次已展示序号不因后台学习随机移动。

## 验证标准

指定码与目标字词的最小场景，不采集用户整句。覆盖：纯五笔/混输、同码精确/前缀、首页/后页、空格/数字/显式选择、重启、读写失败、多个宿主、简繁显示和去重。

确认记录的是实际选择的scheme/code/text，来源分开；取消、原码输入和模拟失败不错误学习。原子保存、失败恢复、导入/删除不丢自定义词。新策略需稳定性与误选恢复测试，首项率/选词键数/翻页成本使用固定合规离线测试集测量，不做生产遥测。

性能与许可/零网络门禁、make verify零诊断保持。实验报告与实际包验证分开，不凭单测认定用户故障已解决。
