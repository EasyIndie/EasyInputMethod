# 323 · 外部资源交叉验证（sdcb/wubi86-viewer + hantang/search-wubi）

> 日期：2026-11-19 ｜ 关联：`docs/参考与致谢.md`、`docs/reviews/306-root-order-pilot.md`、ADR-382
> 结论：**码级可以交叉验证，而且已经验过（99.96% 一致）；拆字数据不能入库（许可不允许）。**

## 1. 两个资源是什么

| 资源 | 性质 | 许可 |
|---|---|---|
| [sdcb.ai/wubi](https://sdcb.ai/wubi/)（[sdcb/wubi86-viewer](https://github.com/sdcb/wubi86-viewer)） | 86 版五笔**学习站**：田字格按字根分色、取码规则自动讲解、编码↔字双向查 | **代码 AGPL-3.0**；`data-src` 混合来源：微软 `ChsWubiNew.lex`、`hantang/search-wubi`、Make Me a Hanzi（Arphic）、字根字体 |
| [hantang/search-wubi](https://github.com/hantang/search-wubi)（sdcb 分叉上游） | 1.3 万字拆字查询，含 `char/code/units` 三列 | **仓库无 LICENSE ⇒ 保留所有权利**；README 自述数据聚合自 王码五笔 / rime / jidian / CNMan，拆解图片来自 wb98、字根拆解来自 ysepan |

**许可判定**：

- `hantang/search-wubi` 无许可 ⇒ 默认**保留所有权利**，其数据表（含 PUA 编码的字根 `units`）**不能**进我们的 GPL-3 产品；
- `wubi86-viewer` 代码 AGPL-3.0：可以**阅读借鉴**，但复制代码会给本项目引入 AGPL 的网络条款；其 `data-src` 里还有**微软专有词库**，更不能进库；
- 结论与 ADR-382 一致：**不把无许可来源写进规范数据**。

## 2. 能做的交叉验证：码级（事实层）

码是"按规则算出来的事实"，交叉比对属于**验证**而不是复制表格。本地一次性比对（不入库）：

| 项 | 值 |
|---|---|
| 对方字表 | 13,928 字 |
| 我们的单字全码表 | 27,823 字 |
| 交集 | **13,368 字** |
| **全码完全一致** | **13,363（99.96%）** |
| 不一致 | **5 字** |

不一致的 5 个都是扩展区生僻字，差一位字母：

| 字 | 我们 | 对方 |
|---|---|---|
| 𫔍 | `qgol` | `qtol` |
| 𫗧 | `qnki` | `qngi` |
| 𬬮 | `qgay` | `qtay` |
| 𡎚 | `fyna` | `frna` |
| 𫄨 | `xqqh` | `xqdh` |

**意义**：我们的码表（D9/Rime 系）与"微软词库系"在 13,363 个字上完全一致，
说明**码表层本身是可信的**；这 5 个差异集中在扩展区生僻字，属"字形变体取码不同"，不影响常用字。

## 3. 交叉验证对我们剩余缺口有帮助吗

我们表内还有 **153 个非 `full`**（全部在 GB2312 一级口径**之外**，一级已 100.0%）。比对结果：

- 这 153 个字**在对方表里码与我们完全相同**（153/153）；
- 也就是说：**缺的不是码，是"字根序列"证据**。对方虽有 `units` 列（PUA 编码的字根拆解），但许可不允许入库。

所以对剩余 153 字，交叉验证**帮不上拆字**，只能帮码。

## 4. 真正可借鉴的是方法（不是数据）

对方 README 描述的补全链路，和我们遇到的问题结构一致，值得作为下一阶段的**方法参考**（不复制代码）：

1. 先取 **~2,500 字**的"笔画 → 字根"人工样本；
2. 从样本**学习每个字根的笔画序列**；
3. 对其余字做**回溯搜索**（允许包围结构拆两段、允许 >4 根时中间不取码）；
4. 失败时依次尝试：字根变形、**书写顺序交错**（如 兆、非）、编辑距离近似；
5. 笔画数与字形库不一致时（繁体 艹 4 画等）用 **kNN** 推断笔画类型。

我们的现状是"规则 + 逐位自证"，对 153 个 L1 外字，可以照这个思路做**受控推断**：
推断结果一律标 `partial` 并注明"推断/待核"，**不进 `full`**——保持 ADR-382 的不猜原则。

## 5. 结论与边界

| 用途 | 可以吗 | 依据 |
|---|---|---|
| 码级交叉验证（统计一致性） | ✅ 已做 | 码是规则产出的**事实**，比对属于验证 |
| 单字引用核验（在 evidence 写"外部资料确认 X"） | ✅ 可以 | 前面处理 薛/鼎/酶 就是这么做的 |
| 把对方 `units`/拆字表**入库** | ❌ 不行 | 无许可（hantang）/ 微软专有词库（viewer）/ Arphic 字体数据 |
| 复制 AGPL 代码进本项目 | ⚠️ 需 ADR | 会引入 AGPL 网络条款，与 GPL-3.0-or-later + 零网络定位冲突 |
| 借鉴"学习字根笔画 + 回溯搜索"方法 | ✅ 可以 | 方法是思想，不复制实现 |
