# 237 — 二级简码「选谁」的频度来源对照（研究文档 §4.2 决策）

- 日期：2026-11-06　｜　关联：`docs/research/wubi-schemes-and-learning-loop.md` §4.2、ADR-304、报告 228/234
- 工具：`tools/eval/compare-level2-sources.py`（研究用，只写 `/tmp`，不产出发布数据）

## 1. 问题

一个 2 字母编码下常有多个字，二级简码只能选一个。用哪套频度选？

- **来源 A**：现有全码权重（WindInput，D3）——与码表同源，最保守；
- **来源 B**：通用字频（jieba 单字频，D10）——不同源，理论上更贴近真实使用。

## 2. 做法

1. 从 `data/generated/wubi86-core.tsv` 取出所有**四码单字**，按前两码分组 → **624 个 2 码码位**；
2. 两种来源各选一个首选字，注入「核心表 + 每对 2 码一行」的临时表；
3. 用同一批 `tools/eval/samples.tsv` 跑 `ime-eval`，对比 `jianma2`（30 条二级规则样本）与 ALL。

## 3. 结果

| 变体 | jianma2 命中% | 首选% | 平均位次 | 按键/条 | ALL 首选% | ALL 按键 |
|---|---|---|---|---|---|---|
| base（当前：无二级简码） | 100.0 | **93.3** | 0.07 | **3.07** | 94.0 | 4.44 |
| A：全码权重选字 | 100.0 | **100.0** | 0.00 | **3.00** | 95.0 | 4.43 |
| B：通用字频选字 | 100.0 | **100.0** | 0.00 | **3.00** | 95.0 | 4.43 |

**两种来源在 624 个码位里只有 5 个选字不同**，且全部是生僻扩展区汉字：

```
bo  㷦 → 䧨      ch  䮓 → 驉      ci  駣 → 騨
hb  䁅 → 䶙      pm  䢆 → 䢇
```

也就是说：这 5 个码位下的候选字**全是生僻字**，选谁都不影响日常输入。

## 4. 另一个发现：624 ≠ 625

`cx` 这个码位在所有四码单字里**没有任何归属**（只有词组 `cxww` = 巴比伦）。
所以"按规则从现有单字表推导"最多得到 **624 条**，第 625 个格子（`cx`）只能来自官方简码表。

## 5. 决策建议

| 项 | 建议 | 理由 |
|---|---|---|
| 简码频度来源 | **采用来源 A（现有全码权重 D3）** | 唯一差异是 5 个生僻字；少一个数据依赖、与码表同源、结果可复现 |
| 表本身 | 先用**规则推导版（624 条）**，并在发布说明注明"按规则推导，非官方表" | 可立即产出、可评测、零新增许可；官方表到位后再替换（D17-bis） |
| 评测口径 | `jianma2` 样本本身也是"全码前两位"推导的，**不能证明与官方表一致** | 必须如实写进报告，避免自证 |

## 6. 对 D17-bis 的直接影响

1. 数据来源登记时可写：`按规则从 D3 单字全码推导`（自建，CC-BY-SA-4.0），不需要新的第三方许可；
2. `cx` 缺口要么留空（624/625，文档写明），要么等官方表补齐；
3. 若将来引入官方 625 表，用同一工具把"规则版 vs 官方版"再比一次，差异码位写进发布说明。

## 7. 复现

```sh
python3 tools/eval/compare-level2-sources.py
# 输出：终端对比 + /tmp/lampyris-level2-sources.json（含差异码位明细）
```
