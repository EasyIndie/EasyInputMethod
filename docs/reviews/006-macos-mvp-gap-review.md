# macOS 首版实现对照与待办（2026-10-09）

## 范围与结论

用户本轮要求先全面梳理、记录待办及交接，之后再实施。本文把“MVP”理解为现有 macOS 首版交付，不另行缩减承诺；权威技术方案§12将 Phase 1 定义为完整五笔输入法，其八项DoD仍是发布门槛。P2整句、其他平台、语音及非目标不纳入首版。

当前引擎、宿主、交互与签名公证链路已实现；输入及多数交互已有用户实测。尚不能称Phase 1验收完成：除后续实机验证外，本轮静态审阅发现候选来源显示、配置即时刷新及错误反馈的要求与实现有差距。数据结构约定与实现也需补决策。检查范围为本地源码、既有测试/CI证据与文档；未新增实机操作，未复核远端套餐/凭据，也未进行逐行全面安全审计。

## 待办队列

优先级：A为首版要求缺口或约定需闭环；B为发布工程与鲁棒性收尾；C为非阻塞优化。条目均为待办，未授权结果不能预先勾选。改变架构、FFI协议或对外行为先追加ADR；配置相关实现先读add-config-option，数据相关先读add-data-source。每次只实施一个可独立验证的改动。

| 编号 / 优先级 | 任务、证据及验收标准 | 下一步条件 |
|---|---|---|
| MVP-01 / A | **闭环数据结构约定**：ADR-015及方案要求cedarwood/二进制词典，而ime-table为排序Vec、默认TSV，ime-dict只实现用户TSV，无.imedict/mmap装载器。比较现有体积、启动/查询成本后追加ADR，明确保留或迁移；同步方案/ROADMAP/T-M1-09状态。不能仅改复选框宣称二进制已交付 | 可先做决策文档；实现按最终决策单独任务 |

## 建议执行顺序

1. 先MVP-01明确当前结构取舍及MVP-12文档闭环。
2. 按MVP-02、03、04逐一完善首版体验与配置承诺，走独立窗口自测及PR。
3. 完成MVP-06/07/08/09/10发布鲁棒性与验证链路；需要新行为时先ADR。
4. 同步MVP-11发布文档；用户有时间时完成MVP-05，不以隔离测试替代正式验收。
5. 全部首版门槛满足后生成对应最终源码的新公证包，才考虑实际交付；此前6d7e8435候选继续用于既定实机测试，未完成事项保留。

C项及P2功能无需阻塞本轮首版收尾。当前所有新缺口均先记录，未在本轮改代码、配置、词库或安装状态。
