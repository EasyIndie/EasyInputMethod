# 066 — 标准子菜单的真实鼠标点击同样不生效；顶层命令正常

2026-10-18 凌晨（重登后的干净会话）。承 065：确认“菜单消失”是未激活假象后，按正确方法（先按键激活、再读菜单）对候选 `df661d3` 做真实鼠标验证。

## 结果

| 对象 | 结构 | 真实鼠标点「五笔」 | 顶层「关于」 |
|---|---|---|---|
| 正式包 a5d456b | 父项自有 action + 自定义 view + 子菜单 + 独立 selector | 不切换（前两轮已证） | 可打开 |
| 候选 df661d3 | 标准子菜单（父项无 action）+ 共享 selector | **不切换** | 可打开（AXPress，窗口标题“关于”） |

两次测试的前置都成立：

- 菜单 23 项齐全（含 `输入模式：混输` 与子菜单），不是通用菜单；
- `mode=mixed`，勾选项也是混输，点五笔应得到 `wubi`；
- 候选运行中 PID 1494、SHA `3099a293…`；测后已恢复正式包 `ed2a2ea…`、strict 签名通过。

因此“子菜单子项不可用”与自定义 view、父项 action、selector 是否共用都无关：**两套完全不同的实现表现一致**。

## 仍存在的两种解释

1. 子菜单子项的点击**没有产生任何命令**（IMK 菜单代理不投递嵌套项）。
2. 系统投递的是**当前勾选的子项**（所以无论点哪一项，模式都“不变”）。

历史证据偏向 (2)：v2/v3 诊断包在 mode=mixed 时收到 `tag=6`（混输，即勾选项）；但本轮候选在同样条件下没有产生可见变化，无法直接区分——两种解释对 `mode` 的观测完全相同。

旁证：Apple 自带输入法与搜狗拼音的输入菜单都是**扁平**的，没有嵌套子菜单；本机 Sogou 菜单 29 项全部平铺。这与“IMK 输入菜单只可靠支持顶层项”一致。

另外排查了 `imklaunchagent: Refusing connection name`：本包 `InputMethodConnectionName = cn.jokerhub.inputmethod.Lampyris_Connection`，符合 `<bundleid>_Connection` 约定；该日志在其它输入法/其它时刻也出现（bundle 名被系统隐去），不能归因于本包，也不是本次现象的原因。

## 设计取舍（需要 ADR）

- **A. 平铺**：`输入模式：混输`（点击循环）+ 三项平铺（混输/五笔/拼音，带勾选）。全部是顶层项，已知可用；代价是菜单多 2~3 行。
- **B. 只留循环**：单个 `输入模式：X` 点击循环；直接三选一留在设置页与快捷键。最小改动，最稳。
- **C. IMK 原生 modes**：把 mixed/wubi/pinyin 声明为 TIS 输入模式（Info.plist + `modes:`/激活时按模式启动），子菜单由系统绘制与投递。最接近原设计的 UX，但是架构级改动（模式状态从 config 迁移到“当前 TIS 源”，需要迁移与验收）。

## 下一步（建议先做一次判定性诊断）

如果希望在 A 与 C 之间做对选择，先花一轮做**带日志的候选**：以 a5d456b 源码为基础，在控制器里记录 `doCommandBySelector:` 收到的 selector、`kIMKCommandMenuItemName` 的 title/tag/state，以及 `menu()` 返回项的 title/tag/state；装好、重登、让用户点一次子项，即可直接看出是“没收到”还是“收到的是勾选项”。

- 若“没收到” → 子菜单路线判死，选 A 或 C。
- 若“收到勾选项” → 去掉子项的 `state = .on`（改用标题勾选符号）可能直接修复，原方案可保留。
