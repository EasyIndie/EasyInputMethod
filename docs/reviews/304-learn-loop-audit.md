## 0. 口径

「学·练·用一体闭环」拆成四条可判定的不变量，逐条对 3,755 条运行时资源核对：

| 不变量 | 含义 |
|---|---|
| **A 字根** | 学习区展示的字根必须来自 241 条标准字根清单，且键位与清单一致（否则键位图与拆解对不上） |
| **B 简码** | 一/二/三级简码必须是官方表、是全码前缀、在引擎里该码的首选就是被教的字 |
| **C 全码** | 学习区展示的全码必须能在随包码表里打出这个字 |
| **D 识别码** | 识别码字母 = 码末位，且能由「末笔 × 结构」网格唯一推出，字根数 = 码长 − 1 |

## 2. 问题清单（统一处理，逐条带证据）

### F1（数据，中）9 条合体字的末位「字根」其实是识别码槽

`矿 dyt`、`扩 ryt`、`旷 jyt`、`杉 set`、`吗 kcg`、`妈 vcg`、`码 dcg`、`蚂 jcg`、`冯 ucg`。

D2 的逐码位编码里，末位私有区存在时是「识别码槽」；这 9 个字的识别码位恰好是可读字形
（`ノ:t`、`一:g`），于是被当成第 3 个字根。后果：

- 学习区教成「矿 = 石:d 广:y ノ:t」，**识别码行是空的**——而真实规则是「石+广 + 识别码 t（末笔撇·左右）」；
- 练习「识别码」题型直接跳过它们（`recognition == nil`），「完整码」题不受影响（码本身对）。

判据（可复跑）：`full` 条目里 `字根数 == 码长` 且 `码长 < 4` → 目前 9 条，全部属于「末位是识别码」而非字根。

### F2（数据，中）`母 xgui` 缺字根，且不符合成字字根规则

`母` 被建成 `radical-char` + `components=['母']` + `keys=[]`，于是学习区没有字根格也没有识别码。
按 86 规则 `母` 是合体（`xgui` = 毌 x + 一 g + 丶丶），不是「报户口 + 笔画」；用 D18 笔顺反推
（`乙乙丶一丶`）应得 `xnny`，与官方 `xgui` 不符 —— 说明它的建模口径错了，不是码错了。

### F3（UI，中）学习区简码只显示一个槽、不标等级、没有三级

`CandidateWindow` 用 `hint?.short1 ?? hint?.short2` 拼「简码 XX」：

- 只有二级简码的字显示 `简码 wb`，看不出是二级；
- 同时有一/二级的字只显示一级，二级信息丢失；
- **运行时资源没有三级简码列**，而练习有「三级简码」题型——学练信息不对齐。

### F4（口径，中）「全码前 3 码」≠ 官方三级简码

评测样本 `jianma3` 用的是「高频字全码前 3 码」，命中 100%、首选 **57.5%**：即 42% 的情况下
敲前 3 码给的是**另一个字**。这不是数据错误（官方三级简码 3,362 条在引擎里 100% 首选），
但学习者如果按「前 3 码」的直觉打字就会选错，教学口径必须写清「只有官方简码表里的字能 3 码上屏」。

### F5（覆盖，中）简码题池 ≪ 简码表

| 表 | 条数 | 学习区 `full` | 可练 | 差异原因 |
|---|---|---|---|---|
| 一级简码 | 25 | 22 | 22 | `不`/`为`/`民` 的拆解是 `partial`，`Practice.bank` 要求 `full` → **这 3 个最常用的一级简码练不到**（用和学都正常） |
| 二级简码 | 598 | 553 | 553 | 35 条 `partial` + 10 条不在 GB2312 一级（`骊骒骠睚睥囝辚嶷糨妯`） |
| 三级简码 | 3,362 | 1,888 | 1,888 | 210 条 `partial` + **1,264 条不在 GB2312 一级**（`苷苣荛芤菰…`） |

即「三级简码」表有 3,362 条，但学习区只覆盖其中 56%。

### F6（数据，低）36 个标准字根从未出现在学习数据

`卄 已 巾 幺 牜 皮 竹 糸 糹 虎 見 貝 車 長 門 韋 頁 風 飛 食 飠 馬 鬥 魚 鳥 鹵 麥 黃 黑 鼓 鼠 鼻 齊 齒 龍 龜`

字根题（`rootBank` 按键位图出题）会考到它们，但学习区的拆解里一次都不会出现（多为繁体/罕见形态），
学习者只能背口诀，没有例字。

### F7（验证缺口，低）末笔无法独立核验；D2 组件 ≠ 字面拆解

- 识别码的「末笔」标签是**由码反推**的（字母 → 末笔×结构网格，双射），因此只能自证，不能对外核验；
  要独立验证需要 3,755 字的真实笔顺，目前只有 59 个字根有 D18 笔顺。
- 用 D18 笔顺去核「末字根的末笔」时有 **86 条不符**（如 `提 rjgh` 的 D2 组件是 `扌日一`，而字面末笔来自 `疋`）：
  说明 D2 给的是**取码用的字根序列**，不等于字面结构拆解。教学文案不能把 D2 组件说成「这个字由这些部分组成」。

### F8（UI，低）26 条无字根 `full` 不进练习池

25 个键名字（`wwww` 人 / `iiii` 水 …）与 `母`/`羽` 没有字根格，`Practice.bank` 要求字根非空 →
「完整码」题永远出不到这 26 个最基础的字（它们的码恰恰是「连打四次」「报户口」规则）。

## 3. 影响面与优先级建议

| 优先级 | 问题 | 理由 |
|---|---|---|
| P1 | F1、F2 | 学习区会**教错拆字**（多一个不存在的字根 / 少整行），属于正确性缺陷 |
| P1 | F3 | 学练信息不对齐（简码等级、三级简码），闭环断点 |
| P2 | F4、F5 | 影响"练得到"的范围与预期管理，需要口径说明与扩量决策 |
| P3 | F6、F7、F8 | 覆盖与验证缺口，不影响当前正确性，但限制"学透" |

## 4. 建议的统一处理口径（不动手，先定方案）

1. **F1/F2 修数据，不改码**：把「末位是识别码槽」的 9 条按识别码建模（`recognition` 补上、末位进 `keys` 不要）；
   `母` 改为合体（`毌:x 一:g` + 识别码），并在 `build_b0.py` 加门禁：`码长 < 4` 的合体字必须满足
   `字根数 = 码长 - 1`，否则构建失败（把这类问题挡在生成期）。
2. **F3** 扩运行时资源为 7 列（+三级简码）或让学习区同时读 `wubi86-level3-codes.tsv`；
   显示改成「简码 一级 g / 二级 gi / 三级 gii」，并复用 ADR-376 的两槽位语义。
3. **F4** 在学习区/使用指南写一句「只有官方简码表内的字能 3 码上屏；其余需 4 码或识别码」，
   并把 `jianma3` 的口径写进评测 README，避免把 57.5% 当缺陷。
4. **F5** 决策二选一：把学习字表扩到「GB2312 一级 ∪ 简码表用字」（+1,274 字，资源 +~55 KB），
   或在题型上标注「该字暂无拆解，仅练简码」。**要先定口径再动数据**。
5. **F6** 给这 36 个字根各配 1 个例字（学习区展示用），或在字根题里标注「仅口诀」。
6. **F7** 若要独立核验末笔，需要新增 3,755 字笔顺数据（第二阶段 N2 扩量），当前不排期；
   先在文档写清「组件 = 取码字根，不是字面拆分」。
7. **F8** 练习加「键名字/成字字根」专项题型（答题=四连键/报户口码），与 F3 一并做。
