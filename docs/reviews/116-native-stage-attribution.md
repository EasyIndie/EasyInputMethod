# 116 — 原生按键长尾分段归因（ADR-242）

## 当前结论

沿用IT-12，先补定位所需的最小生产接线，未改变输入/学习策略。报告115的150暖态样本与非受控手工长尾不足以定位具体跨进程调用；本改动尚未安装或原生采样，不能宣称优化了延迟。

## 代码改动

PerfTrace仅在启用采样时创建每键对象，保留engineUs/totalUs起止点与旧字段，增加可选phaseSchema=1及phases：预编辑、候选数据、状态、内容、光标查询、窗口显示、提交。阶段仅含微秒时长，没有文本/按键/客户端信息；未经过阶段省略，相同阶段累加，各键相互隔离。候选导航等非feed路径不新增总耗时样本。commit阶段包含clearMarked+insertText；engine仍包含FFI学习/写盘，不把commit阶段当作学习耗时。

默认关闭不创建采样对象或阶段字典、不写文件；测试入口仍使用既有私有marker，不增加配置、网络、异步学习或客户端缓存。原有总耗时仍不包含前置事件分类、IMK调度和合成器完成。
