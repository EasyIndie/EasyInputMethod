# 225 设置页「全角/半角」项：不同步 + 控件风格不一致

> 用户反馈（2026-11-04，1.0.0/build 34）：设置 → 输入 tab 的「全角 ASCII」项
> ① 用 ⌥F 切换时**不实时反映**状态变化；② 它是**复选框**，而其它状态项是**下拉菜单**，名称风格也不一致。
> **判定：功能正确，但一致性与可读性不达标**；按用户决定放进 1.0.1 修（不在 1.0.0 前动包，ADR-298/IT-23）。

## 1. 为什么不同步（不是刷新慢，是值不是同一个）

| 事实 | 位置 |
|---|---|
| 面板已监听配置变化：`ConfigWatcher → configChanged(key) → 该行 reload` | `Settings.swift:389/453` |
| ⌥P（标点）/⌥T（字形）**写配置**（`ImeConfig.setString`）→ 面板立刻跟随 | `ImeSession.swift:226/239` |
| ⌥F（全角）只调 `ime_session_configure` + `ime_session_toggle_width`，**只改会话内 `width_override`** | `ImeSession.swift:222` |
| 面板读的是配置里的持久值 `input.full_width` | `Settings.swift` 行渲染 |

所以按 ⌥F 后**重新打开面板也看不到变化**——它显示的是"持久默认值"，与当前有效状态无关。
（这是 `docs/配置架构.md` §253 明确写下的旧语义："全/半角快捷键临时切换不会写入配置"。）

## 2. 为什么风格不一致

| 设置项 | schema 类型 | 控件 | 标题 |
|---|---|---|---|
| 模式 | Enum | 下拉 | 输入模式 |
| 标点风格 | Enum(chinese/english) | 下拉 | 标点风格 |
| 输出字形 | Enum(simplified/traditional) | 下拉 | 输出字形 |
| **全角 ASCII** | **Bool** | **复选框** | **全角 ASCII** |

## 3. 修法（ADR-305，1.0.1）

1. schema：`input.full_width: Bool` → `Enum{half, full}`，标签「半角/全角」，标题「字符宽度」（与"标点风格/输出字形"同为名词短语）。
2. 快捷键：⌥F 改为**写配置**（与 ⌥P/⌥T 完全一致）→ 面板天然实时；删除「临时覆盖」语义。
3. 迁移：旧 `config.toml` 里 `input.full_width = false`（bool）必须能读成 `half`、`true` → `full`，且**不回写**用户文件除非用户改动该项；新增迁移单测。
4. 文档：`配置架构.md` §253/§265、`发布说明.md` 同步。

## 4. 1.0.0 的处置

作为**已知限制**写进发布说明：该项能正确设置默认宽度，但不会跟随 ⌥F 变化，且控件样式与其它三项不同。1.0.1 修。
