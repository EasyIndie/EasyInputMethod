# 255 — 1.2.0 装机反馈修正（⌥L 漏字符、拆字键位、四码自动上屏）

- 日期：2026-11-06　｜　来源：用户装机后实测三条反馈
- 结论：两条是缺陷（已修），一条是预期行为（已解释）。

## 1. ⌥L 在无候选窗时插入 `¬`（缺陷，已修）

**现象**：候选窗不出现时按 ⌥L，文档里多出一个 `¬`（Option+L 的系统字符）。

**根因**：`InputController.handle` 先 `guard … sender as? IMKTextInput`，再处理组合键。
拿不到客户端时直接 `return false`，事件落到系统 → 系统把它当字符插入。

**修法**：组合键（设置/更新/关于/学习区/中英/全半角/标点/简繁/模式）**前移到客户端判定之前**；
只有"更新标记文本、显示候选"这类动作才需要客户端，用可选绑定包住。没有组合态时顺手隐藏候选窗。

## 2. 「我」的拆字把「丶」标成 `T`（缺陷，已修）

**现象**：学习区显示 `丿T 扌R ？N 丶T`，最后格键位明显不对（丶在 Y 键）。

**根因**：D2 的拆字序列尾部不可靠（`positionMismatch` 已经在 B0 里记了这个诊断字段），
而运行时资源 `B0-runtime.tsv` 仍按码位把第 4 个字形标成了 `T`。

**修法**：生成运行时资源时，**从第一个位次不符处截断**，并把该条降级为 `partial`：
宁可不显示，也不教错键位。「我」现在是 `丿T 扌R ？N` + 「拆解待核验」。
副作用：`不` 等条目也会被截断并降级（`丆G` + 参考识别码 `I`）。

## 3. `trnt` 四码不自动上屏（预期行为，不改）

`trnt` 在当前码表里有 **3 个同码候选**：我（328,841）、特性（1,946）、选择性（209）。
自动上屏的门槛是"满码且唯一"，所以 `trnt` 只出候选；`wqiy` 只有「你」，因此直接上屏。

> 这是 ADR-016/旧有规则的既有语义，不是 1.2.0 引入的。若将来要"单字唯一也自动上屏"，
> 需先写 ADR（会改变上屏手感，且与"候选优先"的产品取向冲突）。

## 6. 装复测包时的附带发现：替换 bundle 会让系统把输入源移出启用列表

第二次装（修复包）后，`tissrc select` 反复被系统改回 ABC，`AppleEnabledInputSources` 里没有萤火虫，
但 TIS 仍能查到且标记为 enabled——与 2026-11-06 用户遇到的「菜单里没有萤火虫」是同一现象。

**结论**：**覆盖安装正在启用中的输入法 bundle，macOS 会把该输入源从启用列表里摘掉**。
- 短期：装完需要用户在「系统设置 → 键盘 → 输入法」里重新添加/选中一次（或 ⌃Space 后手动选）。
- 长期（1.2.0 收口项）：安装器在替换后主动 `lsregister -f` 刷新注册并提示"如菜单未出现，请重新添加"；
  或在文档里把这条写进安装步骤，避免用户以为装坏了。

已记录，未在本轮实现。

## 7. ⌥L 漏字符：最终结论（2026-11-06 晚，诊断包 `45bc4d6b`）

给控制器加了"hud-diag 开启时记录每个带 Option 的 keyDown"的诊断后，实测日志：

```
[hud] keydown chars=¬ ignore=l flags=524288 learning=true    ×14
[hud] feedback msg=学习区：开 / 关
[hud] inputText ...                                          ← 0 次
```

- 我们的处理器**收到并匹配**（`learning=true`），HUD 正常切换，`inputText` 一次没被调用 → **事件确实被消费**；
- 日志里 `frontmost=com.mitchellh.ghostty`：**用户是在 Ghostty 里按的**。Ghostty 自己对 Option 组合键做字符映射（⌥L → ¬）并送进 pty，不认输入法的"已消费"。
- 用户复测：**TextEdit 与 Terminal.app 都正常**（只有 HUD 提示，无 `¬`）。

**结论**：修复有效；Ghostty 的行为属其自身 Option 映射，不是输入法缺陷。文档与反馈都按此记录。

**附带发现（低优先）**：19 次按键里有 1 次 `learning=false`（刚激活后的首击，被"组合键时效"守卫挡下）——
首击漏字符是另一个小问题，可单独修（放宽首击的时效判定）。

## 8. 诊断开关

`hud-diag` 文件存在时，控制器会把带 Option 的 keyDown（原始字符、ignoring 字符、flags、热键是否命中）
与 `inputText` 投递写入 `$TMPDIR/lampyris-hud-diag.log`；不需要时删掉该文件即静默。
