## 3. P2 — 在 P1 内处理

| # | 问题 | 建议 |
|---|---|---|
| P2-1 | 配置**跨进程写者**存在覆盖风险：`配置架构.md` §3/§7 允许多进程各自写文件（last-writer-wins），热键与设置面板并发改同一键会互踩 | 明确 **IME 进程是唯一写者**，设置面板经 IPC 请求它写；文件只是持久层 |
| P2-2 | 码表**一对多（重码）**的存储未定义：`yada` 是 key→value，一个码映射多个候选，需 postings 设计（code → (offset,len) 指向候选数组） | 补进 `技术方案.md` §6/§7，M0/M1 先定 |
| P2-3 | Windows **纯 Rust TSF 可能被低估**：最成熟竞品 WindInput 自己的 TSF 用 **C++** 写，不是 Rust | 给 Rust TSF 设 **timebox（1–2 周 spike）**，到期不成就退 C++ 薄壳，不恋战 |
| P2-4 | **许可分层**：GPL-3 适合代码，但**数据/字体/词库用 GPL 并不合适**（数据许可惯例是 CC 系列/OFL） | 明确：代码 GPL-3.0-or-later；自产数据 CC-BY-SA-4.0 或 CC0；第三方数据按各自许可。更新 `数据来源与许可.md` §5 |
| P2-5 | CI 只有 `ubuntu-latest`，macOS Swift 前端（P1-M3 起）与 Windows 前端（P3）无法在 CI 构建 | P1-M3 加 macOS runner；P3 加 Windows runner |
| P2-6 | `deny.toml` 全 workspace 禁用 reqwest/hyper 等，会**挡掉 P6 可选模型下载器**（下载器是合法网络点，只是不能进核心） | 明确下载器放 workspace 外（独立工具），或用 `[[bans]]` exceptions，网络禁令只作用于核心 crate |
