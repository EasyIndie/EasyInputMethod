# 086 — 真机 HUD 不可见：动画与客户端取用修复

2026-10-18。安装 `94fc271` 后真机复验：状态切换能改配置，但 HUD 看不到；`CGWindowList` 只看到一个
`72×36 @ (126,52)` 的窗口，截图里没有内容，AX 也读不到文案。

## 两个原因

1. **后台 IME 宿主里 `NSAnimationContext` 不推进**：HUD 从 `alpha=0` 开始做淡入，动画在 agent 宿主里
   没有真正执行，窗口存在但透明；之后的 `orderOut` 也可能未完成，留下“可见但全透明”的窗口。
   修复：**去掉淡入淡出**，直接 `alpha = 1` + `orderFrontRegardless`，到时 `orderOut`。状态提示优先可靠可见。
2. **菜单快捷键路径下 `activeClient` 可能是旧客户端**：`⌥T` 等由菜单 keyEquivalent 触发时，
   `activeClient` 可能仍指向上一个应用（本次实测像旧 Terminal 的光标位置），HUD 就落到 `(126,52)`。
   修复：HUD 取矩形时优先 `client()`（当前输入上下文），`activeClient` 仅作兜底。

## 验证

- `make verify`、65 场景本地验收、offline 全绿。
- 已装 `94fc271` 含这两个问题；需新包在真机确认：
  - 任意状态切换都应看到 HUD，且位置在**当前输入框**光标附近；
  - 鼠标移开不影响；
  - 空文档/无焦点不出现。

## 备注

这是 HUD 可靠性问题的第三次修正；若新包仍不能稳定贴光标，建议只保留候选框内联芯片 + 菜单/设置里的状态，
把 HUD 降级为可选（需用户确认）。
