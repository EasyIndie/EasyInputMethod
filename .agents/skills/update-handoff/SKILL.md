# 交接标准流程

`HANDOFF.md` 是**当前状态的唯一来源**；`docs/` 是稳定背景（设计、决策、合规）。
交接的目标只有一个：**下一位执行者读完 HANDOFF + 提示词，就能不追问地开始动作。**

## 0. 四种场景（先说清是哪一种）

| 场景 | 什么会丢 | 必须先落到文件 | 主要风险 |
|---|---|---|---|
| **A. 上下文压缩**（同一会话被压缩） | 对话细节、临时推理、工具输出 | 压缩前把「此刻在哪 / 下一步 / 坑」写进 HANDOFF §0/§3/§4 + 一条 §9 日志 | 压缩后凭记忆继续，重复已做过的动作 |
| **B. 开新会话**（同工具同设备） | 全部会话记忆 | 同上 + 一条可直接粘贴的提示词（`--prompt`） | 新会话不知道包/配置/输入源是否被人动过 |
| **C. 跨 agent**（pi ↔ Codex ↔ Claude Code） | 同 B，且工具能力/门禁不同 | 只能依赖仓库文件；Skills 唯一来源 `.agents/skills/` | 依赖上一个 agent 的私有记忆、跳过 `make verify` |
| **D. 跨设备**（A/B、未来 Win/Linux） | 同上 + 环境差异 | 机器可判定的状态（`handoff-status.sh`）+ 包的两份 SHA + 平台差异项 | 新设备上的旧包/旧 config 让"默认行为"不生效；菜单/AX 差异被误判为 bug |

场景 A 是唯一"不需要新会话"的，但它最容易做漏：**压缩前不写文件 = 压缩后从零猜**。

## 1. 五步流程（任何场景都走这五步）

```sh
./scripts/handoff-status.sh --for=compact|session|agent|device [--prompt]
```

1. **采集**：跑上面的命令（只读，不安装、不改配置、不切输入源）。表格里的分支/HEAD、已装包执行 SHA、宿主 PID、config 字节与显式项、词库行数、输入源、最近 CI，直接抄进 HANDOFF，不要凭印象写。
2. **写 HANDOFF**（按下面的契约）。
3. **写提示词**：`--prompt` 会打印骨架；按 `docs/交接提示词模板.md` 填「状态 / 任务 / 步骤 / 边界 / 收尾」五段。
4. **验证**：`make verify` 全绿；确认自己没动真实配置/输入源（表格里 config SHA、输入源与开始时一致）。
5. **提交**：在固定`dev`保存交接提交，同批相关改动经`dev → main` PR收尾；不为每次交接另开分支或PR，不直接推送受保护main（ADR-246/248）。若暂未合入，HANDOFF明确记录待承接提交和下一步。

## 2. HANDOFF 契约

| 节 | 写什么 | 上限/要求 |
|---|---|---|
| §0 元信息 | 更新者（工具+模型）、分支@HEAD、阶段一句话、最近一次验证 | 4 行内 |
| §1 安装与数据 | 每台设备：系统/已装包 SHA/config SHA 与显式项/输入源/词库行数 | 一表一机一行 |
| §2 本轮完成 | 只写"这轮改变了什么"（提交 + 报告编号） | 表格式，不解释设计 |
| §3 未决 | 待验证项、已知差异、阻塞（带报告编号） | 每条一行，可勾掉 |
| §4 下一步 | 可执行步骤：命令 + 判定标准 | 换设备时用 §4.1 单独起一节 |
| §5 边界 | 本次禁止动作、授权范围、还原要求 | 沿用 + 本次新增 |
| §9 日志 | **置顶追加**：做了什么 / 关键决策 / 验证结果 / 遗留 | 一条 ≤5 行，保留最近 6–8 条 |

原则：只回答「此刻在哪 / 下一步 / 有什么坑」；细节指向 `docs/`、`ROADMAP.md`、ADR 编号；过时内容直接删。

## 3. 场景化补充

### A. 上下文压缩
- 压缩**之前**：HANDOFF §0/§3/§4 更新 + §9 追一条（"压缩点：正在做 X，下一条命令是 Y"）。
- 压缩**之后**：第一件事读 HANDOFF（不是回忆），用 `git log -1`/`git status` 对齐现实。
- 长任务在 §4 里写"断点续跑"的最小命令序列，别写"继续验收"。

### B. 新会话
- 提示词必须含：包的两份 SHA、config/输入源当前值、本次任务的判定标准、还原点。
- 新会话开工第一步：`git fetch && git status && git log -1`（防止有人插了改动）。

### C. 跨 agent
- 入口固定：pi → `AGENTS.md`；Claude Code → `CLAUDE.md` → `AGENTS.md`；Skills 都读 `.agents/skills/`（单一来源，不复制）。
- 不假设对方有你的会话记忆或你的工具；把「怎么验证」写进提示词（`make verify` / `make macos-offline-tests` / `make macos-ui-snapshots`）。
- 门禁一致：任何 agent 的产出都走同一 `make verify`；0 诊断（ADR-081）。

### D. 跨设备
- 先跑 `handoff-status.sh --for=device`；表格抄进 §1，包**同时**给 zip SHA 与执行 SHA。
- 记录目标机：已装旧包 SHA、config 是否有**显式** `hotkey.*`（有就必须 `--purge-data` 才能看到默认值）、词库行数、输入源。
- 平台差异单列（例：A/Intel/macOS 13 的菜单索引比 B 小 2；设置面板首次打开分区不同），避免下一位把差异当 bug。
- 需要重启/注销的流程：把「重启前用户手动两步 → 重启后 agent 命令」分开写（见 HANDOFF §4.1）。

## 4. 反例（都踩过）

- ❌ 只写"完成了任务"，没写是哪个任务、怎么验证、下一步。
- ❌ 把设计/ADR 内容抄进 HANDOFF（体积膨胀，还容易和 `docs/` 冲突）。
- ❌ 日志写成日记（超过 5 行、一条覆盖一整天）。
- ❌ 提示词写"接着上次继续"（对方无法核对包、配置、输入源）。
- ❌ 交接前不跑采集：写下的 config SHA/输入源与实际不符，下一位从错误前提出发。
- ❌ 场景 D 只给包名不给 SHA；装完发现是旧包，白跑一轮验收。
