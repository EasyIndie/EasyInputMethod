# 更新交接文档

`HANDOFF.md` 是**"当前状态"的唯一来源**，跨会话、跨工具（pi / Codex / Claude Code）共享。
稳定背景（设计、决策、合规）在 `docs/`，**不要**把设计细节塞进 `HANDOFF.md`。

## 何时更新

- **每次会话结束前**（无论是否写了代码）；
- 开始或完成一个 `ROADMAP.md` 任务时；
- 做出影响后续工作的决定时；
- 用户要求"交接 / 总结 / 记录进度"时。

## 步骤

1. **§0 元信息**：更新时间、更新者（工具名）、当前阶段、分支、最近一次 `make verify` 结果。
2. **§1 摘要**：仅在发生重要变化时改。
3. **§2 已完成**：把新完成的事项加入；不要重复罗列文档已说明的内容。
4. **§3 进行中**：当前未完成的工作；没有就写"无"。
5. **§4 下一步**：按优先级列出**可执行**的下一步（带 ROADMAP 编号）。
6. **§5 待决 / 阻塞**：新增或关闭条目。
7. **§9 会话日志**：在**顶部**追加一条，倒序，**≤5 行**：
   - 做了什么；关键决策/变更；验证结果；遗留问题。
8. **同步 `ROADMAP.md`**：勾选已完成项。
9. 保持简洁：**删掉过时内容**；日志超过 10 条时删除最旧的一条（git 历史仍可查）。

## 原则

- `HANDOFF.md` 只回答：**此刻在哪 / 下一步 / 有什么坑**。
- 一条日志 ≤ 5 行，只写"有信息量"的内容。
- 细节一律指向 `docs/`、`ROADMAP.md`、ADR 编号，而不是复制。
- 与 `ROADMAP.md` 保持一致。

## 反例（不要这样做）

- ❌ 复制整段设计方案或代码解释进 `HANDOFF.md`
- ❌ 写"今天讨论了很多"这类无信息量内容
- ❌ 只写"完成了任务"，不写是哪个任务、如何验证、下一步
- ❌ 让 §3 长期停留在"进行中"却无人维护
